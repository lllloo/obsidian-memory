影片主張：與其追逐每週冒出的新 AI 自動化工具（如 n8n、Zapier 等 no-code 平台），不如掌握底層真正的工程能力。理由是幾乎沒有任何職缺會把某個工具列為條件，列的是工具底下的能力——能建後端、操作資料庫、寫前端、接 AI 層、部署解決方案。作者以此提出一套他用了多年、跨多家公司多種方案都沒找到更好替代的「持久技術棧」，分五層。

## 第一層：後端（引擎）

整套系統的核心引擎，把所有東西綁在一起。語言選 Python，但 Python 只是起點，重點在生態系裡的兩個套件：

- **FastAPI**：建立 API 層，是自動化的進入點。可透過 webhook 或與前端溝通，提供 GET / POST / PUT / DELETE 端點。
- **Celery**：背景 worker。FastAPI 處理進來的請求，把慢工作交給 Celery worker 在背景跑，可用於擴展與提升系統強健度。作者特別看重 Celery 能用 Python 排程與觸發 cron job。

作者自家公司的自動化系統就是這個核心：FastAPI 接所有觸發型 webhook，Celery 管所有排程型的 cron 任務。

## 第二層：資料庫（儲存）

直接用 **Postgres**，不必煩惱其他資料庫，即使要擴展也一樣。理由：

- 多數人不會超過幾百萬筆紀錄，那已是相當大的應用，Postgres 處理綽綽有餘。
- 連 Instagram 都只用 Postgres 擴展到數億用戶。
- 要存向量（給 RAG 用）也能直接存在 Postgres。

作者個人偏好用 **Supabase**，它是 Postgres 的封裝層，簡化了認證等環節，並開箱附帶管理後台 GUI。入門建議直接用 supabase.com 的雲端託管版。

## 第三層：前端（視覺層）

不是所有 AI 自動化都需要前端，但若要做 dashboard 或 admin panel 就需要。推薦三件組合：

- **React**：最知名的 JavaScript UI 函式庫，元件化建構介面，業界標準。
- **Vite**：把 React 程式碼變成可在瀏覽器檢視的實際網站，提供開發伺服器並能打包出貨。
- **shadcn/ui**：作者口中的「secret sauce」元件庫。涵蓋圖表、登入、按鈕、選單，甚至整套 AI 聊天介面。關鍵差異在於它不是放進 `node_modules` 當依賴，而是把元件原始碼直接匯入專案——因此你的 AI / coding agent 也能直接讀寫、調整樣式（顏色、字型、圓角等）。

作者作為後端出身的工程師直言：純粹只當前端開發者「已經沒戲」，因為現在用 AI 建這類前端太容易了。但他區分了「寫出前端」與「設計 / UX」——後者 AI 仍有不足。不過 AI 自動化的場景多半是內部工具、簡單 admin dashboard、簡單聊天應用，這套棧就夠。

## 第四層：AI 模型（智慧層）

到這層之前都還只是軟體工程，這層才讓自動化真正「AI 化」。現今各類模型——語言模型、給 RAG 的 embedding 模型、視覺模型、語音轉文字 / 文字轉語音、圖像生成——都只是一次 API 呼叫的距離，所以 AI 層通常非常簡單。

作者藉此再次強調：不需要為了塞進一個小小的 LLM 呼叫，就換掉用了數十年的成熟技術棧或改用全新工具。

實務做法：

- 可直接呼叫 OpenAI 或 Anthropic。
- 但做更正式的應用、在公司或接案時，通常會透過 AWS、Azure、Google Cloud 的企業級 production 端點——好處是集中計費、更多資料隱私控制、以及不同的擴展方式。
- 注意某些模型只在特定 provider 上有，要拿最新模型得確認去哪個 provider。
- 好消息：會直接呼叫 OpenAI API，就會用這些雲端工具，因為呼叫方式幾乎一模一樣。

作者認為這是整套棧裡最容易學的一層。

## 第五層：部署基礎設施

對軟體開發新手或從 no-code 工具來的人，這是最複雜、最陌生的一層，但搭配 AI coding agent 可以走得相當快。重點是怎麼把後端、前端的程式碼真正部署上線變成可用服務（no-code 工具按存檔就好，custom 設定要多走「ship 出去」這步）。

業界標準做法：

- **Docker**：把各組件（後端、前端）用 Docker Compose 或直接 Docker 分開設定。Supabase 雲端已託管就不必管。剩下要做後端、前端兩個部署。
- **Railway**（入門推薦）：把後端（Python + FastAPI + Celery）包進 Docker Compose 當 repository 部署，可以直接叫 coding agent「幫我部署到 Railway」。Railway 還有 MCP server 協助管理。前端（Vite server + React）同樣做法，設定成兩者互相溝通。
- 更進階 / 真實公司做法：用大型雲端商的 container service，或直接租 **VPS**（虛擬私有機）部署。作者過去三年用 **Hetzner**（德國公司）租裸 VPS 部署方案。

## 五層整體

完整技術棧的五層各司其職：

1. 後端——處理一切的引擎
2. 資料庫——儲存一切
3. 前端——把成果視覺化給使用者（視需要）
4. AI 模型——加入智慧
5. 部署——讓整個系統作為一體對外可用

作者另提到他有一支 4 小時 live build 影片，從零到部署示範用這整套棧建一個「document co-pilot」（公司用自家資料的私有內部 chatbot），是其 agency 最常被要求的專案類型。
