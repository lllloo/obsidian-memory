技術實作之外的職涯/商業判斷框架：AI 開發者下一階段最有價值的位置，不是寫更多 code，而是**能帶企業沿成熟度軸線往右移、把整段工作流端到端用 agent 做掉的人**。

## 企業 AI 成熟度三階段

| 階段 | 角色 | 特徵 |
|---|---|---|
| **AI-enabled** | 員工為主，AI 是個別生產力加成 | 流程沒變，只是員工變快。多數公司在此 |
| **AI-first** | AI agent 成主層，員工透過 agent 管理工作 | 流程以 AI 為核心重新工程化。賣點是「人更少、產出相同或更多」 |
| **AI-native** | 從零以 agent 優先設計每個流程 | 資料源、介接、輸入輸出皆為 agent 服務，headcount 進一步下降 |

趨勢幾乎必然往右移：股東看到 AI-first/native 公司用更少人做同樣產出，老牌公司不跟上會被新創吃掉市佔。

## 該卡的位置：端到端 workflow 自動化

需要兩種能力疊加：

- **Full-stack 工程**：端到端自動化橫跨 database、後端、部署、前端、給 human-in-the-loop 的 dashboard。只懂單一垂直容易變瓶頸、被自動化掉。
- **流程診斷（AI 時代新加的）**：能進企業「畫出流程、找出可被 agent 接管的工作流」，而不是接到規格才開工。傳統工程師很少做，但高度被需要。

## 從 headcount 思維轉成 workflow 思維

老式做法是「出問題 → 開職缺 → 招人」。AI 時代要把粒度拆細：不看「員工 + 一堆任務」，而看 workflow 本身。一個員工通常綁多條 workflow、含大量隱性知識與 edge case。要做的是把 workflow 從人身上抽出、定義清楚，再決定哪些交給 agent。

**切入點是 Type 2 浪費**：

- **Type 1**：流程必要步驟，砍不掉。
- **Type 2**：純粹浪費——重複步驟、手動把資料從 A 系統搬到 B、人工拼報表。「我可以用 30 分鐘寫個 script 把這段自動化」，包成 skill 提供給企業。

## 為何是工程師的機會

非工程背景的人對 AI 仍是黑盒（只認得 ChatGPT，不知能力邊界）；工程師清楚自動化的可行性與成本，能直接指著流程說「這段我能做掉」。**前提是拿到看流程的權限**——一般 dev 角色被隔開、看不到業務全貌。

兩條切入路徑：

- **大企業**：難拿到流程觀察權限，但每家公司為活下去都會多少變成軟體公司。
- **小企業 / 在地公司**：老闆多半不知 AI 怎麼用，以 freelancer / consultant 進場示範蓋 agent，是高槓桿位置。
