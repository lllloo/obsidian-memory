## 逐字稿

### 實驗：讓 3 個 AI 設計同一個電商網站

我最近做了一個實驗，把同一份電商需求分別丟給 Google Stitch、Figma 和 Claude Design。10 分鐘之後，我的螢幕上出現了三個完整的設計稿，每個看起來都很專業，每一個也都讓我有一種奇怪的既視感。你知道那種感覺嗎？打開一個新的產品網站，然後在心裡想：這不是跟那個誰的網站長得一樣嗎？

同一個時間，Figma 的股價從去年八月的高點已經跌去 87%，市場給出的判斷很直接：AI 能直接做設計了，設計師快要沒有用了。但我今天不回答設計師還有沒有未來這個問題，我想問一個更切身的問題：我們有沒有能力看出 AI 給的設計哪裡有問題？

### 今天的核心問題：你能看出 AI 設計哪裡有問題？

### Google Stitch、Figma、Claude Design 各自的優缺點

先說 AI 設計工具的現狀，三個工具各有優劣。Stitch 設計出來的樣子最好看，因為它有很多圖庫可以使用，但改起來最麻煩，它不能單獨編輯組件，必須重新畫一張新的圖。例如這個購物車頁面的按鈕有點錯位，它就必須重新生成一頁新的購物車頁面才能修正。Figma 輸出的 Design system 很完整，貼近原本的工作流，有不滿意的地方都可以直接手動修改，避免 token 的消耗，但它有每日調用 MCP 的上限，無法大量使用。Claude Design 輸出的是可以直接使用的程式碼，也有一個很好溝通的介面，像是點擊右上角 Draw 就可以在畫面上繪製，然後請 Claude Code 去調整，但微調同樣麻煩，沒辦法像 Figma 一樣手動去調整組件位置。

### 問題其實不在 AI，在我們自己

我們進一步仔細看它們的產出，會發現它們全部都有小問題：錯位、對比不夠、字級不一致、CTA 位置有點怪，沒有一個是可以直接上線的版本。而這不是 AI 的問題，這可能是你我的問題。因為設計這件事在本質上沒有標準答案，配色沒有對錯，間距沒有對錯，圓角還是直角也沒有對錯。你給十個設計師看同一份需求，會得到十個不同的版本，每個都說得出理由。

### 為什麼 AI 永遠給你「平均的答案」

這對 AI 來說反而是一個根本性的難題。AI 擅長有標準答案的問題——數學、翻譯、程式邏輯，但在沒有標準答案的領域，AI 只能做一件事情：從大量的訓練資料裡找出一個看起來最不會出錯的版本。換句話說，AI 給的永遠是平均的答案。

然後問題來了，你看著這個平均答案，直覺告訴你好像哪裡怪怪的，但你又說不出是為什麼。能做的只有兩件事：一、憑直覺亂改，通常會越改越糟；二、對 AI 說「再做一次，弄好看一點」，結果 AI 也在猜「好看」到底是什麼。這時候陷入一個死局，因為沒有語言，就沒有能力修正它。那一定得是設計師才有辦法打破這個死局嗎？不用，但要換一個思路。

先停下來想一件事情：設計這個領域已經被研究了整整 70 年。眼動追蹤實驗從 1960 年代就在跑，Flesch-Kincaid 可讀性公式是 1948 年就有的。

### 好設計沒有標準答案，但壞設計有標準訊號

WCAG 無障礙標準累積了 20 幾年的研究，顏色對比、字級比例、注意力熱力圖全部都有學術研究撐腰。好設計沒有標準答案，但壞設計是有標準訊號的。過去 70 年，設計研究累積出了一堆「避開這些你就至少不會太糟」的法則。

這些法則早就被寫成工具了，AI 其實也知道這些規則，但生成的時候不穩定，有時遵守，有時漏掉，你不知道哪裡出問題，跑個工具才知道答案。但這些工具能做的也只是把設計推到及格線，讓明顯的壞偏離消失。及格線之後的事等一下再說，那這 70 年的研究到底量化出哪幾個可以衡量的維度呢？

### 把設計拆成 2 個面向、4 個可量化的問題

我們先把網頁設計拆成兩個面向來看：一、功能——這個設計會不會出問題？二、視覺——這個設計看起來清不清爽？這兩個面向可以再拆成四個具體的問題：一、眼睛看不看得到重點？二、看了之後看不看得懂？三、看懂了會不會採取行動？四、整體的設計是不是一致？每個問題都已經有成熟的工具可以量化，不需要成為設計師，只要知道這些工具的存在，並且把它們串在一起。

### 工具一：眼睛先看哪裡？DeepGaze IIE 眼動預測

設計師最常問的問題之一：使用者打開網站 0.5 秒內，眼睛會先落在哪裡？

有沒有注意過我們在看網頁的時候，眼睛不是從左上角開始一行一行往下掃？眼睛會跳，它會自動被某些東西吸引——大的字、高對比的顏色、人臉、動態，然後它會漏掉大片大片的內容，大腦甚至不知道那些東西的存在。以前要回答「眼睛先看哪裡」，要做眼動追蹤實驗，招募受試者，架設設備，分析資料，整套流程費時又費力。

現在有一個叫 DeepGaze IIE 的眼動預測模型，丟一張截圖進去，幾秒鐘它吐出一個熱力圖，亮的地方表示眼睛會停留，暗的地方表示會被漏掉。因此關鍵不是讓整個畫面越亮越好，而是重要的東西要亮，次要的東西要暗。例如，如果重要的按鈕在暗區，代表大部分的使用者打開網頁的第一秒根本看不到它。這種問題靠直覺幾乎看不出來，但工具 10 秒就能夠抓出來。

### 工具二：看到了，看得懂嗎？Flesch-Kincaid + WCAG

上一階段我們知道使用者看了哪裡，但是看到不等於看懂。例如標題讀完，使用者知道這個網站在做什麼嗎？這裡有兩套成熟的工具。

第一套是可讀性公式。早在 1948 年，一個叫 Flesch-Kincaid 的指標就已經被發明出來，它可以直接告訴你這段文字相當於幾年級的閱讀程度。當文案寫到 14 年級的時候，一般使用者看 3 秒就會關掉。中文則沒有好用的對應公式，但現在可以用 LLM 做質化評估，例如它會具體指出這句話太抽象，使用者不知道你在說什麼。

第二套是無障礙標準。WCAG 是一套累積了 20 年的網頁設計規範，Sa11y 和 axe-core 這類工具把這套規範變成了自動化檢查，一跑就能抓出文字對比不足、連結說明模糊、圖片沒有 alt 文字等。而這些不是有時間再處理的小事，它們是直接影響使用者能不能理解你的內容的硬門檻。

### 工具三：理解了會採取行動嗎？AI Agent 模擬使用者

以前這樣做 task-based testing：招募真人，給他們任務，坐在單面鏡後面觀察他們的操作，時間、金錢、人力缺一不可。

現在 AI agent 可以直接模擬。你給它一句指令：「找到這個網站的價格方案，告訴我 Pro 方案的月費是多少」，它就會自己開瀏覽器、滾頁面、點按鈕，跑完告訴你成功還是失敗，卡在哪一個步驟。它雖然不能代表真實的使用者，但它能抓出所有人都會卡住的結構性問題，例如按鈕點不到、重要的資訊藏在第三層導覽、CTA 被擋在彈窗後面等。而這些問題過去可能都要花費大量資源做 user testing 才會浮現出來。

### 工具四：整體看起來一致嗎？Playwright 讀取 CSS

功能面向看完來看視覺。很多人以為好不好看是最主觀的問題，但好看的網站幾乎都有個共同點：設計風格是一致的。例如主色就是那個綠，不會出現五個相似但不一樣的綠；字級就那六種，不會出現十四種；圓角就兩種，不會出現七種。雜七雜八越多，大腦認知負擔就越重，使用者說不出哪裡不對，但就是覺得這個網站看起來有點亂，然後他就離開了。

肉眼很難看出一致性的問題，十個相似的灰色混在一起，肉眼分不清哪個該刪。但 Playwright 獲取每個元素實際的 CSS，幾秒鐘就能夠統計出來，像是這個網站用了 47 種灰色、13 種字級、15 種按鈕樣式等。跨頁比對更有意思，有時候每頁分開看都很一致，但放在一起才發現首頁用的是深灰色、定價頁用的是淺灰色，差一點點肉眼看不出來，但大腦感覺得到。這是設計系統沒有落地最強的訊號。

### 把四個工具串成閉環，讓 Claude Code 給修正計畫

接下來把以上四個工具串在一起，就可以形成一個閉環，直接針對剛設計完的網站拿去做分析，得到一份結構化的報告，就可以知道哪些元素有問題、問題的類別、嚴重的程度等。然後再把這份報告丟給 Claude Code 說一句「根據這份報告，給我你的修正計畫」，它就會告訴你這顆按鈕的顏色對比不夠，不符合無障礙標準，建議換深一點的顏色；或者它發現註冊按鈕落在了視線的死角，建議往上移動。

針對這些建議改完後再跑一次報告，分數就會往上走。這個循環跑個三到五次，一個完全不懂設計的人也不再只是照單全收 AI 給的結果。

### 「平均臉」實驗：工具給的是清單，不是答案

說到這裡，你可能覺得有工具、有流程、有閉環，問題都解決了。先停一下。

你有沒有聽過心理學家曾經做過一個實驗？他們把幾十張不同人的臉數位疊加在一起，取一個像素平均值，得到一個平均臉。這張臉在客觀指標上非常好看——對稱、比例標準、輪廓完整，沒有任何明顯的瑕疵，受試者給它的吸引力評分甚至高過大多數個別的原始臉。但絕對不會記得它，因為它不是任何一個真實的臉，沒有那顆痣，沒有那個不對稱的笑容，沒有任何想讓你再看一眼的理由。

後來研究者又做了一個更進一步的實驗，他們發現評分最高的臉不是最平均的那一張，而是朝某個方向有選擇地偏離了平均的那張，像是一個有點稜角的下巴，一雙比例上稍微大一點的眼睛。正是那個偏離，讓這張臉變得難忘。

再回頭看剛才這些工具做了什麼：它們的本質是把設計推向平均。對比不夠就拉高，字級太多就收斂，按鈕看不到就移到視線熱區。這些都對，但工具給的是一份清單，不是答案。哪些要修、哪些是故意要留的偏離，那個判斷叫品味。品味是工具教不了的。

### 設計工作的三層：執行、評估、定義——AI 能做到哪裡？

所以回到一開始的問題：我們有沒有能力看出 AI 給的設計哪裡有問題呢？有，剛才看到的工具就是答案。但這只回答了一半，更值得想的問題是：AI 能做設計之後，人的價值在哪裡？

把設計工作拆成三層：最底層是執行——畫出來、寫 CSS、做 mockup，這一層 AI 完勝，而且差距會越來越大。中間層是評估——判斷好壞、給方向、決定取捨，工具可以過濾壞的偏離，但哪個偏離值得保留，人需要自己決定。最上層是定義——決定要做什麼、為誰做、解決什麼問題，這一層只有人能做，需要的不是設計知識，而是對人的理解。

過去學設計是從下往上，現在可以直接從中間開始。執行層交給 AI，你的時間則全部投資在評估和定義。這不是變輕鬆了，而是變難了，因為畫圖有一堆課程可以上，但是品味卻沒有。

### 越多人把設計外包給 AI，有品味的人越值錢

而且有一件事情值得注意：越多人把設計完全外包給 AI，有品味的人就越稀缺，越值錢。
