## 為什麼跨專案需要知識庫

每個 AI 模型都有上下文視窗容量上限（例如 Claude 4.6 為 20 萬或 100 萬 token），看似充足，實際工作時還要扣掉：

- 模型本身的回答
- 中間呼叫工具
- 思考過程

容量接近滿時，AI 的表現明顯下降——忘記前面講過的事、開始亂答。**最重要的能力就是上下文管理**：剛好不多不少塞給它需要的東西。

當 Claude Code 同時管理多個專案時，傳統樹狀資料夾結構會困住 AI——A 專案的一部分跟 B 專案的一部分可能共用同一套資訊，但檔案隔在不同資料夾就看不到關聯。

## 為什麼選 Obsidian

- **Wikilink**：文件之間就算不在同一層級也能互相連線。AI 讀到某個檔案的連線時可跨過去讀相關文件，掌握全貌而不被傳統樹狀架構困住
- **本機 Markdown，資料主權**：所有檔案是 Markdown 存在本機。Obsidian 倒了也帶得走，跟 Evernote、Notion 不同
- **成熟社群與開源外掛**：可變資料庫、待辦管理儀表板、專案管理系統，自由度高

## Step 1：安裝 Obsidian 與 CLI

1. 上網下載 Obsidian 安裝
2. 開 Claude Code 跟它說：「請幫我安裝 Obsidian CLI」
3. CLI = command line interface，命令列介面，讓 Claude Code 能跟 Obsidian 對話（讀／寫／改知識庫）
4. 開啟 Obsidian，建立 vault（例：取名 test，隨意放置）

## Step 2：用計畫模式設計知識庫結構

在 vault 資料夾內開啟 Claude Code，進入計畫模式，下指令的三招：

```
這個資料夾是用來做我的跨專案管理知識庫的。
接下來請你幫我調查我的電腦裡面所有使用 Claude Code 的專案背景，
然後上網找結合用法，並且問我需求的問題，幫我規劃知識庫的計劃。
```

三招拆解：

1. 請他**讀**跟目標相關的資料（既有專案）
2. 請他**上網找**結合用法
3. 請他**問你問題**補漏掉的偏好

計畫模式好處：不會直接動手，先給你計畫，你看懂了再讓他動手。

Claude 會問細節（例：知識庫定位是純測試 / Index Only / 整合到什麼程度），可以選 `check with me` 繼續討論。

## 作者自己的知識庫結構

第一層分區：

- **主軸**：生涯目標、待辦總和、每週例行（週報整理、下週規劃）、每天要做的事
- **個人**：稅務策略、家人 schedule、財務狀況與規劃
- **生涯主線（Pillars）**：GMAT 教學、Claude Code 教學課程、AI 個人顧問生涯
- **日誌**：每天完成任務自動寫入
- **週報**：每週請 Claude 整理日誌，看花了多少時間、各專案進度、下週推進
- **Projects**：實際在推進的專案
- **書籤**：網路上看到的、跟某些專案有關的，先存下來

跨層級透過 wikilink 連線——同一個檔案可關聯到課程計畫、財務狀況、家人 schedule、AI 個人顧問。AI 讀到時自動沿連線跨過去讀相關內容。

## 知識庫不用一次到位

務實做法：**慢慢長出來**，不是一夜變好。

作者一開始只有兩個東西：

- `projects`：每個專案的背景
- `pillars`：把專案連到生涯主線

後續陸續增加：

1. `decisions`：未來要下的決策（背景會階段性變化）
2. `日誌`：每天推進的進度
3. `週報`：日誌零散，每週整理一次
4. **主檔更新機制**：請 AI 根據日誌跟週報回來更新 projects / pillars
5. `personal`：個人生活管理
6. `insight`：每週 AI 看工作模式給指教
7. `書籤`：尚未排進計畫但想存下的東西

## Step 3：安裝 Obsidian 官方 skill

下指令：「請幫我上網找官方的 Obsidian skill 並安裝，先給我接好。」

Obsidian skill 是寫給 AI 看的技能手冊：

- 教 AI 用什麼指令跟 Obsidian 對話
- 多行內容怎麼換行
- 怎麼指定路徑、找檔名
- 怎麼建立標準筆記、放 PDF / 圖片
- 怎麼建立連線

裝好後，用斜線 `/obsidian` 加自然語言，例：

- 「幫我讀知識庫、找這個專案的背景」
- 「幫我看昨天的進度」
- 「幫我寫入今天的日誌」
- 「幫我把剛完成的事寫到日誌裡」
- 「幫我重整 Obsidian」
- 「請幫我在檔案之間按照意思建立合理的關聯」

Claude Code 會根據 skill 教的方式跟 Obsidian 程式溝通，不會寫錯。作者的知識庫從建立到現在沒親自打過字，全部由 AI 建立、記錄、讀取、編輯。

## wikilink 不用自己建

很多人擔心維護成本高，但連線不是你來建：

```
請你按照語義幫我判斷哪些檔案有關係，幫我加上 wikilink 雙向連線。
```

連線加得合理、充足，AI 讀每個檔案時就能清楚知道跟其他檔案的邏輯關聯，自動連過去讀。**恰好的時刻讀到恰好多的上下文**，跟你的互動越來越同步。

## 推薦外掛

Obsidian 設定 → 第三方外掛 → 社群外掛（總共近 3,000 個）：

- **Templater**：模板，新筆記按模板走
- **Dataview**：處理跟資料有關的東西，把 Obsidian 變類資料庫
- **Tasks**：跨文件、跨專案、跨資料夾管理待辦任務

不知道裝哪些可問 Claude Code：「比較熱門的外掛，你判斷我有哪些是需要的？如果你不清楚，可以問我問題、可以上網找、可以讀我目前的文件。」
