## 為什麼不能整包複製 .claude

花幾週、幾個月把 Claude Code 調成最懂自己的工作夥伴（記得專案規矩、自訂角色與指令、整套自動化規則）後，想切到 Codex 時最直覺的做法是把整個 `.claude` 資料夾複製過去。這會踩三個雷：

- **資安事故**：設定裡可能藏金鑰、密碼、憑證，原樣複製等同外洩。
- **觸發機制不同**：Claude Code 的規則與環境設定背後的觸發機制和 Codex 完全不一樣，硬搬過去 Codex 無法解讀，只會壞掉。
- **引用語法不同**：Claude Code 用 `@` 引用其他文件，Codex 不是這樣引用；照搬會導致原本關鍵的引用文本在 Codex 不會自動讀取。

照搬看起來最快，實際最危險，且兩環境之間有許多無法同步適應的地方。

## 正確做法：妥善搬運而非照搬

- 能直接改名對應的地方就改名。
- 不能直接改名、需配合新環境調整的地方，交給模型做翻譯轉換。

## 同步 skill 的兩種模式

作者設計了一個專做 Claude Code 與 Codex 同步的 skill，分兩種模式：

- **setup（首次遷移）**：第一次要把 Claude Code 累積的所有設定搬到 Codex 時用。會盤點 Claude Code 裡所有 harness，產出一份遷移計劃，並依計劃完成完整遷移。
- **maintain（定期維護）**：之後定期啟用，比對兩邊差異，只把安全的部分同步過去。例如 Claude Code 已更新、Codex 還沒，就比對出差異並協助完成遷移。

### 唯一基準原則

maintain 最重要的原則：永遠以平常在用的 Claude Code 設定作為不動的唯一基準，不去動 Claude Code，所有變更只發生在被同步的 Codex 這一邊。

## 三層安全分級

每種模式下的工作再分成三層風險等級：

- **可自動套用**：風險最低，模型自行安全遷移。
- **需確認**：高風險部分，模型會解說、請求使用者確認，並做好事後驗證。
- **使用者親自處理**：資安敏感項（密碼、憑證、金鑰等），模型不會主動做，必須人工手動處理。

## skill 的設計拆解

skill 本質是一本寫給 AI 看的說明書，主要內容：

- **主流程**：告訴模型有 setup／maintain 兩模式，以及三層安全等級的劃分。
- **重要規範（踩過的坑）**：遷移時只動對面（Codex）的檔案、不動原始檔；兩邊一起動可能遺失重要資訊找不回來。記下了 `@` 引用在 Codex 行不通這個 bug，避免未來重犯。
- **協助遷移的範圍**：涵蓋最高等級的記憶檔 CLAUDE.md、memory、hooks、skills、MCP 等需比對的對象。
- **路徑對照規則**：說明 Claude Code 各層級路徑的位置、哪些檔案不應被同步、各層級在 Claude Code 與 Codex 的區別，避免放錯地方。
- **risk policy**：詳列哪些模型可自做、哪些需與人協作、哪些（如金鑰、敏感訊息）千萬不能主動做。
- **產出模板**：規定模型用什麼方式產出、如何向使用者報告執行內容、進度與計劃。
- **判斷模式**：怎麼判斷使用者是首次（setup）還是後續維護（maintain）。
- **自動化指令碼**：為可自動化的低風險遷移準備好指令碼，讓模型安全、準確、快速執行。

## 需人工把關的轉換

部分項目不是單純搬位置，需模型協助人類手動翻譯：

- **Hooks**：兩邊 hooks 邏輯不同，不能單純搬位置，需依翻譯規則轉換形式。
- **記憶檔**：使用者記憶檔有較佳的搬遷原則。
- **AGENTS.md**：即 Codex 裡對應 Claude Code 的 CLAUDE.md，連同 MCP 與各種 harness 都要規範如何轉換，最後再驗證並向使用者報告。

## 安裝第三方 skill 的提醒

把 skill 連結丟給 Claude Code 說「請幫我安裝這個 skill」即可。但裝別人的 skill 前，最好請 Claude Code 先進去看一遍，檢查有沒有危險資訊、提示詞注入、資安風險或惡意程式碼，較安全。

## 實機 maintain 示範重點

- 在 Codex 裡叫出 skill 用金錢符號 `$`（不是 Claude Code 的斜線 `/`）。
- 先用 dry run 純試跑、不直接執行，先盤點。
- 過程會搜尋兩側官方文件確認最新設定，因設定可能隨時更新，每次都重新搜尋而非亂抓。
- 產出 summary：哪些有改動、哪些沒動、哪些尚未驗證。示範中發現某些原樣遷移會有副作用，於是改為加上安全約束後重做檢查。
- 無法自動同步處，可請它手動逐項 review 與搬移；原本選擇不做、但不涉及紅線資料的部分也可請它補做，最後做驗證。

## 並用心法

作者目前約 90% 時間用 Claude Code，當額度滿了或遇到 Claude Code 解不出的問題，就自由切換到 Codex 解決。不盲目捧或踩任何模型，主張所有模型都試看看，找出最適合自己的選擇或組合。
