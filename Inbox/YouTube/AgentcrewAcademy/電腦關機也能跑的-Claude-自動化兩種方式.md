## 自動化前先想兩件事

不是所有人都需要自動化，先釐清兩個前提再決定。

**精度要求**：自動化牽涉對外的訊息或資料時，精度要求極高——必須確保模型產出完全沒問題。做不到就把自動化限制在前面幾個階段，最後一步留人工複核。

- 只給自己看（自動產報表、整理新聞）：可容忍排版瑕疵，目的是快速瀏覽。
- 對外發信、整理未來會複用的資料：精度門檻更高，無法做到零錯誤就別讓它跑完整流程。

**環境要求**：任何程式都需要運作環境，主要分兩種。

- 本機：電腦不能關機、不能休眠，一關就停。
- 雲端：租用 VPS 或用 Anthropic 的伺服器讓 agent 常駐，技術門檻與限制較高。

先想清楚是否真的需要 24 小時待命；沒有的話，小範圍自動化即可，不必追求持久運作。

## 工具一：Loop（短期、即時、本機）

在 Claude Code session 內輸入 `/loop`，空格接時間（如 5 分鐘、1 小時），再空格接指令，Claude Code 就會排程，每隔一段時間回來執行該指令。

特色與限制：

- **週期短**、偏即時監控。
- **只存在於當前 session**：session 中斷或電腦關機，排程即消失。

適用情境：人正在電腦前工作，希望它代為監測臨時任務。

- 修完 bug 後掛著監控錯誤日誌，有新錯誤就即時抓到並修正。
- 寄出信後每隔幾小時定期檢查信件，收到回覆馬上通知。

**快取小技巧**：Max 方案對話快取存取時間約一個小時，若超過一小時才送新訊息，可能讓整包對話重新計費吃額度。因此刻意把下一次 agent 執行縮在一小時內（如設成 50 分鐘），維持快取不失效。防休眠在 Mac 上可用 `caffeinate -dis`（螢幕與本機都不休眠）。

## 工具二：routine / schedule（長週期）

終端機用 `schedule` 設定（可 create / update / list）；App 內在左上角的 routine 設定。特色是時間跨度長、沒那麼即時，適合每天、每週一或每月定期喚醒做任務（如每天整理待辦清單存成 PDF 放桌面）。

routine 分兩種：

**本機 routine（local）**：可設定名稱、註解，重點是 instruction（告訴 Claude Code 到時間要做什麼），並選擇資料夾、權限與執行模型。

- 與 Loop 相同：需電腦開著才能執行。
- 與 Loop 不同：離開 session 後仍持久，唯一條件是不要關機。

**remote（雲端）**：排程跑在 Anthropic 的雲端伺服器上，電腦關機照跑。門檻最低，但有重要限制。

## remote 雲端排程的工具限制

remote routine **只支援官方 MCP / 官方 Connector**，不支援本機在用的任何第三方 Connector 或 MCP，可能導致功能受限。

官方 Connector 能力相對受限的實例：

- Gmail：官方 Connector 最多只能寫草稿，不能寄出信件（第三方 Gmail MCP 可直接寄出）。
- Google Drive：官方 MCP 頂多建立檔案，不能修改原有檔案。

所以要權衡：想電腦關機也能自動執行，門檻最低是內建雲端 routine，但只能用官方且能力受限的工具，是否符合排程需求要自行判斷。

想用平常最熟的第三方工具，就走另外兩條路：自備一臺 24 小時不關機的機器（如家裡的 Mac mini），或租 VPS 讓 Claude Code 跑在上面，取得完整環境。

## 怎麼選

先分清楚自動化的目的，再對應工具。

- **短時間代替眼睛、做重複性監控**（幾分鐘到幾小時、當天結束）：優先用 Loop。
- **時間跨度較長**：考慮 schedule / routine。
  - 工具單純、官方 Connector 就能支援：優先用 remote。
  - 工作流用到非官方工具，或官方環境不支援：自備機器 24 小時不關機，或租 VPS 跑 Claude Code。

最終回到一個問題：這個任務真的重要到需要一個 24 小時不間斷的助手嗎？想清楚再決定。
