## 核心觀點

這支影片把 AI 工具整合裡常混在一起的三個詞拆開：API 是服務之間溝通的端點，MCP 是把 API 能力包成 AI 可理解的工具箱，CLI 則是讓 AI 透過終端機指令操作既有工具。三者不是誰取代誰，而是不同抽象層與不同風險模型。

## API：服務之間的固定介面

API 是應用程式與服務之間的溝通橋樑。傳統開發裡，工程師會讀 API 文件，理解 endpoint、參數、驗證方式與回傳格式，再把呼叫方式寫進程式碼。

對 AI agent 來說，API 的問題是每次都要重新理解文件與格式。如果只是臨時查資料，AI 可以即時讀文件、寫小腳本、測 endpoint，再把結果轉成人能讀的摘要；但這種方式每次都要重做探索與測試，適合一次性任務，不適合高頻工作流。

## MCP：給 AI 用的工具箱

MCP 可以理解成把一組 API 能力包裝成工具箱，讓 AI 不必每次重新研究 API 文件。每個工具都描述自己能做什麼、需要哪些參數、回傳格式如何解讀。

MCP 的優點：

- 工具 schema 明確，AI 比較不容易亂塞參數。
- 權限與 token 可依使用者或服務管理，比較適合企業、多使用者與稽核場景。
- 安裝後 AI 可以直接使用，不必每次重寫程式碼。

MCP 的代價：

- tool schema 會佔用 token。
- 工作流串接不一定像 CLI 那麼自由。
- 第三方 MCP 仍要評估安全性與維護狀態。

## CLI：讓 AI 操作命令列工具

CLI 是命令列介面。對人類來說，CLI 門檻高，因為要懂指令語法；但對 AI 來說，這層門檻下降很多，使用者只要描述需求，AI 可以自己查 help、組指令、執行並解讀輸出。

CLI 的優點：

- token 成本通常較低，不必每次帶完整 tool schema。
- 容易串 pipe、腳本與本機自動化流程。
- 適合個人開發、本機工具、一次性批次處理。

CLI 的風險：

- 權限控制較粗，裝上後常等於能執行整套工具能力。
- 輸出多是純文字，AI 需要自行解析，可能解讀錯欄位或狀態。
- 多人共用、敏感資料、企業環境下要額外設計權限與稽核。

## 怎麼選

| 情境 | 偏向 |
|---|---|
| 臨時查資料、探索 API 可不可用 | API + 臨時腳本 |
| 外部 SaaS、CRM、Slack、Google 類服務 | MCP |
| 個人本機自動化、省 token、串接 shell pipeline | CLI |
| 企業多人使用、需要權限控管與稽核 | MCP |
| 工具輸出穩定且可用 JSON / plain text 控制 | CLI |

影片的結論不是「MCP 不如 CLI」或「CLI 比 MCP 強」，而是看你在意的是 token、pipeline 自由度、權限管控、易用性，還是安全稽核。實務上可以混合使用。

## 安全提醒

無論 MCP 或 CLI，只要是第三方工具，都需要安全評估。官方工具風險較低；第三方工具可能有無意漏洞，也可能包含惡意行為。尤其當工具能讀信件、Slack、CRM 或公司內部資料時，不能只看功能能不能跑。
