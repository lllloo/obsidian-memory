## 待消化重點

- **核心原則**：跨專案只丟 Inbox 原料，Card 消化留給 vault session 產
- **誤判教訓**：Obsidian 1.12.7+ 桌面 app 內建 CLI，`Obsidian.com` 是 terminal redirector 而非 GUI launcher——值得獨立成 Card（見最後一節）
- **CLI 的真實優勢**：路徑相對 active vault（不用寫絕對路徑）、Obsidian 即時感知變更、跨機器可攜
- **CLI 的限制**：Windows `--stdin` 有 silent fail 風險，必須驗 size；Claude Code session 啟動後 PATH snapshot 鎖死，新裝的 CLI 要重開 session 才看得到

## 三階段流程

### 階段 1：A 專案 → Inbox 原料

對話末尾跟 Claude 說「用 obsidian CLI 寫 Inbox 原料」，執行：

```bash
printf '%s\n' "---" "title: <主題>" "created: 2026-05-21" "updated: 2026-05-21" \
  "tags:" "  - <暫定 tag>" "---" "" "## 待消化重點" "" "- ..." \
  | obsidian create path="Inbox/2026-05-21-<主題>.md" --stdin open
```

驗 size：

```bash
FILE_PATH=$(obsidian path file="Inbox/2026-05-21-<主題>.md")
SIZE=$(wc -c < "$FILE_PATH"); [ "$SIZE" -ge 10 ] || echo "silent fail, fallback Write"
```

要點：

- 跨專案 Claude 不知 vault tag 慣例，暫定 tag 即可，留待消化階段對齊
- **不要寫成 Card**——只列待消化重點

### 階段 2：vault session 消化

```
cd C:\code\obsidian-memory
/ob 整理 Inbox
```

`/ob` skill 自動：

1. 偵測 CLI（失敗降級 Write）
2. 走寫入前 Checklist
3. `obsidian tags` 對齊 tag、`obsidian search` 查相似 Card
4. 三條路徑：新 Card / 強化既有 / 直接刪除
5. **三條都以刪除 Inbox 原檔作結**

### 階段 3（選用）：Cards → Topics 升級

vault session 內人工觸發：

```
列出可升 Topic 的候選 Cards
```

Claude 對照 [[topics-review]] 給傾向，**等使用者拍板**才執行：

```bash
git mv "Cards/<標題>.md" "Topics/<主題>/<標題>.md"
```

## CLI vs Write fallback 對比

| 項目 | CLI | Write |
|---|---|---|
| 路徑 | `Inbox/...` 相對 active vault | 絕對 `C:\code\obsidian-memory\...` |
| Obsidian 即時感知 | ✓ | ✗（需 `Ctrl+P → Reload app without saving`） |
| 跨機器可攜 | ✓ | ✗ |
| Windows 穩定性 | `--stdin` 有 silent fail 風險，需驗 size | 穩定 |

## 待消化：應抽出獨立 Card 的子主題

1. **Obsidian 桌面 app 與 CLI 的關係**（1.12.7+ bundled、`Obsidian.com` 真實角色、啟用步驟、Claude Code session PATH snapshot 問題）→ 強烈建議新建 Card 或強化既有 [[Obsidian-CLI-整合指南]]
2. **跨專案 Claude Code 做筆記的反模式**：直接寫 Card 跳過消化 → 違反吸收型卡片盒哲學
3. **`/export` 的正確用途**：不是延續對話，是當原料丟 Inbox
