- 2026-08-05 [[Claude-Code-Hook-能力邊界]]（新）— Query 回存：hook 的限制不在事件多寡，而在**該 type 的輸出契約**——`prompt`／`agent` 是 Claude Code 代管的 LLM 呼叫（免 API key、免依賴），但出口只有 `{ok, reason}` 這一個 allow/block 閥門，內容過不去；`Stop` 上的 `ok: false` 更不是「擋下」而是把 reason 當成模型的下一個指令、回合繼續。另記三條硬限制（`SessionStart`／`Setup` 只支援 `command`／`mcp_tool`、只有 `command` 能 `async`、command hook 裡 shell out `claude -p` 會遞迴觸發全域 hook）。推出的設計原則：**要對資料流做 LLM 加工就放資料落地端而非 harness 端**（非同步是預設、不遞迴、跨工具只需實作一次），純放行判斷才留在 hook。同輪補 [[Claude-Code-記憶系統六層比較]] 回連
- 2026-08-03 [[MCP-無狀態化-2026-07-28]]（新）— Query 回存：MCP `2026-07-28` 版把**無狀態**寫進 base protocol 規範性條款（移除 `initialize` 握手與 `Mcp-Session-Id`，改每請求 `_meta` 自帶 protocol version 與 capabilities，逐請求協商），且條款 **transport-agnostic、明文涵蓋 stdio**——「一個開著的 STDIO process 不是一個對話或 session」，只有 Auth 一節是 HTTP-only。同版 deprecate Roots／Sampling／Logging／HTTP+SSE，至少 12 個月棄用期。兩端採用**直查實測**：Codex CLI 0.146.0 已實作但 flag `mcp_2026_07_28` 標 under development／預設 false（`McpProtocolMode` 預設 `Legacy`），Claude Code 2.1.220 binary 版本常數只到 `2025-11-25`、`Mcp-Session-Id` 仍在、CHANGELOG 無記載。後者為字串缺席的**間接推論**，已標明非官方聲明；1 條勿引用（「這是 Claude Code 的變更」——協議層變更，Anthropic 反而尚未跟上）
- 2026-07-30 [[WSL-剪貼簿貼圖到-Claude-Code]]（新）— 排錯回存：WSL2 按 `Alt+V` 貼圖「閃一下沒反應」的根因**不在按鍵而在解碼層**——WSLg 只把 Windows 剪貼簿圖片曝露成 `image/bmp`，Claude Code 偵測層的 grep pattern 含 `bmp` 故不報「No image found」，但影像管線只吃 png/jpeg/gif/webp，於是靜默失敗；取圖鏈是 `||` 短路串，`wl-paste --type image/bmp` 先成功導致內建 PowerShell fallback 永遠走不到。證據為 binary `strings` 直讀＋把該 BMP 餵 Read tool 得「cannot read binary files」。解法是輪詢 BMP→PowerShell 取 PNG→`wl-copy` 回填，實測不迴圈、不弄丟 Windows 端圖、落地 PNG 逐位元一致；並實測 `wl-paste --watch` 因 Weston 不實作 `wlr-data-control` 而不可用（先前僅二手說法），故只能輪詢。1 條勿引用（「v2.1.157 已修好並新增專屬 Alt+V」查無 CHANGELOG 依據）

## 概念頁

- [[Context-優先與多-agent-的適用邊界]] — 決策判準：能力來自 context 注入、agent 數量只是編排選擇；多 agent 有實證邊界。把 Anthropic（多 agent 高 90.2%）與 Cognition（別建多 agent）的表面對立，經 UC Berkeley MAST 失敗實證（1,642 traces、41–86.7% 失敗率）統一為「可平行/讀重/確定性協調」的適用域之分（2026-07-14 回存）。
- [[LLM-Wiki-知識管理模式]] — Karpathy 的個人知識庫 pattern：LLM 漸進維護互聯 markdown wiki，知識編譯一次後持續維護，與 RAG 每次重檢索形成對比（本 vault 的設計原型）。
- [[OKF-與本-vault-的相容性]] — Open Knowledge Format 與本 vault 的邊界：不遷移內部 Obsidian LLM Wiki，日後有跨工具交換需求再建獨立 OKF 匯出層。
- [[設計品質的可量化檢測]] — 壞設計的標準訊號可量化：眼動熱區、可讀性/無障礙、任務可完成性、CSS 一致性四項檢測串成閉環交 AI 修正；工具只能推到及格線，及格線之後「留哪個偏離」是品味。是實證檢驗頁「驗證用 agent 改不到的判準」在設計領域的落地（2026-07-15 ingest）。
