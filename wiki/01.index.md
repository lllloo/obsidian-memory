- 2026-08-28 測試流程分層改制 + [[測試手段的優先序與成本]]（新頁，5 頁連帶更新，Query 回存）— 一連串追問把 [[專案測試流程]] 從**四層改成三層**：使用者拍板**契約測試不採**，E2E 遞補為第 3 層。不採的理由不是它沒價值，是適用條件不合——契約層真正不可取代的時機是兩端部署節奏分開（型別是編譯期的、擋不到已部署的舊前端），前後端同一批人維護時成本高於它擋掉的 bug；正統 CDC（Pact + broker）解決的是「不知道有誰在用我的 API」，與本情境不符。該層知識與重開條件就地保留在總頁，術語表仍收 Contract Test 詞條（附錄涵蓋刻意比正文廣）。那條縫只由兩者分擔：後端整合測試（全 endpoint 的自身正確性）＋ E2E（少數路徑的串接）；**其餘 endpoint 無自動化保護**，使用者同日拍板連 OpenAPI 那條補丁也先不做（第 2 層都還沒動，先堆工具鏈是本末倒置）。同日上網核實一輪並回存為「重開條件與候選方案」：**mock 可從 spec 產**是原設計沒想到的一步（Orval／Hey API，讓元件測試的假資料不再手寫，直接關掉那條縫且不新增測試層）、Schemathesis 從 spec 自動產 API 測試且與後端語言無關、CDC 在 Radar 雖為 Adopt 但**停更於 2016-11 且語境是微服務**（強化不採）、code-first 與 schema-first 的取捨。整條鏈押在「Scramble 能否推出準確 spec」這個未驗證前提上。同輪把兩個子頁的**第 2 層做法寫完**（前端元件測試：API 一律 mock 是定義不是偷懶、選元素不用 CSS class、fixtures 要集中；後端整合測試：四類只有這層碰得到的東西、每 endpoint 成功 + 422、不重測第一層規則），並釐清三個名字的邊界（元件測試／整合測試／`Feature` 是 Laravel 專有命名）。新頁補上與分層正交的成本軸。**第 2 層做法已寫、尚未實作**，實作要回各自 repo
- 2026-08-28 [[E2E-測試的資料庫隔離]]（新頁，Query 回存）— 使用者問「e2e 測試的時候 DB 建議是獨立的嗎」，查 wiki 發現 [[專案測試流程]] 的第 4 層只有射程定義、環境面全空，故先行補上。核心機制是 **E2E 收尾不能靠交易回滾**：瀏覽器發出的請求由另一個進程另一條連線處理，測試端開的交易包不住它，所以第 2 層那套 `RefreshDatabase` 在這裡失效、資料是真的留下來的。由此推出獨立 database（不必獨立 server）、CI 用即丟容器、平行 worker 各一個 database；另三條：不要用 SQLite 跑 E2E（型別轉換、外鍵、鎖、SQL mode 的差異讓你測到一個不存在的系統，而且它會綠）、重置點放套件開始而非逐條（代價是斷言不能寫「共有 3 筆」這種依賴全域狀態的形式，正好是 AI 產 E2E 最容易寫出來的）、破壞性動作前用 database 名稱守衛擋誤連正式庫。**全篇為通用工程實務綜合，未在本專案實測**，頁內已標
- 2026-08-21 [[MCP-無狀態化-2026-07-28]]（就地更新，Query 回存）— 使用者問「Claude Code MCP 有支援無狀態的嗎」，以頁內既有的 wire 層探針法第三次複驗：**2.1.238 已預設走 modern（`2026-07-28`）路徑**，推翻 2.1.224 那輪「程式碼已就位、未對一般 MCP server 啟用」的結論（該節就地標記已被取代、保留為方法論實例）。探針做成 modern-only server（`initialize` 一律回 `-32022`）仍完整跑通 `server/discover` → `tools/list` → `tools/call`，整輪 3 個 HTTP 請求、無 session、無 SSE 長連線；client 自身 MCP log（`~/.cache/claude-cli-nodejs/<cwd-slug>/mcp-logs-<server>/`）直接寫 `protocolEra: "modern"`，比抽 binary 字串可靠得多。切換落在 2.1.224–2.1.238 之間、**無公告**。附帶實測到 client 端 bug：`tools/list` 把規格上選填的 `ttlMs`／`cacheScope` 當必填，缺了就重試 4 次後呈現為「server 沒有工具」。同日追問「最簡單的 server 長怎樣」時連帶把 stdio 測掉：**同一版本、同一份 server 邏輯，stdio 仍走 legacy**（直接送 `initialize`、不做規格要求的 `server/discover` era 探測，modern-only server 直接連不上），故採用狀態必須綁 transport 講。legacy-only server 的 fallback 仍未測
- 2026-08-19 [[視覺回歸測試的落地與陷阱]]（新頁，研究回存）— 從 cloud-memory 盤點他專案背景時撈出的題目，使用者指定往「怎麼用＋要注意什麼」延伸。核心是把 VR 的所有麻煩收斂成單一取捨——**渲染環境的控制權放在哪**：本地 pixel-diff 把 kernel／字型／hinting／GPU 全納入斷言範圍，雲端 DOM 重繪（Percy 序列化 DOM ＋ asset discovery ＋ 雲端關 JS 重繪）結構上免疫。實用面含 Playwright 穩定化五道閘、`threshold`（YIQ 逐像素色差 0.2）與 `maxDiffPixels`（差異面積）的分工、`-u` 三種語意（無旗標＝missing、有旗標無值＝changed、全量須明寫 all）。八個踩點裡兩個最關鍵：**容差在機制上救不了字形差**（位置不同非顏色不同，中文站尤甚）、**Docker 不是銀彈**（官方文件從未推薦，只說「在產基準圖的同一環境跑」；issue #35143 一手實例同 image 同 kernel 仍 1px 飄、維護者查不出建議繞過後 stale 關閉）。治理層借鏡 Chromatic 的逐分支基準圖與 Flake Filter——**連專做這門生意的廠商都只主張隔離 flake、不主張消除**。同日追問「目標與範圍」後補兩節：oracle 只測變更不測正確（同儕審查定義，故基準圖錯了照樣全綠、核可品質即機制上限），範圍是粒度×狀態×模式相乘且兩種工具的預設方向相反（Chromatic 全截需 opt-out／Playwright 不寫就沒有）；連帶回讀一手論文訂正 LLMShot 對 8.2% 那個數字的誤引。2 條勿引用

## 概念頁

- [[Context-優先與多-agent-的適用邊界]] — 決策判準：能力來自 context 注入、agent 數量只是編排選擇；多 agent 有實證邊界。把 Anthropic（多 agent 高 90.2%）與 Cognition（別建多 agent）的表面對立，經 UC Berkeley MAST 失敗實證（1,642 traces、41–86.7% 失敗率）統一為「可平行/讀重/確定性協調」的適用域之分（2026-07-14 回存）。
- [[LLM-Wiki-知識管理模式]] — Karpathy 的個人知識庫 pattern：LLM 漸進維護互聯 markdown wiki，知識編譯一次後持續維護，與 RAG 每次重檢索形成對比（本 vault 的設計原型）。
- [[OKF-與本-vault-的相容性]] — Open Knowledge Format 與本 vault 的邊界：不遷移內部 Obsidian LLM Wiki，日後有跨工具交換需求再建獨立 OKF 匯出層。
- [[設計品質的可量化檢測]] — 壞設計的標準訊號可量化：眼動熱區、可讀性/無障礙、任務可完成性、CSS 一致性四項檢測串成閉環交 AI 修正；工具只能推到及格線，及格線之後「留哪個偏離」是品味。是實證檢驗頁「驗證用 agent 改不到的判準」在設計領域的落地（2026-07-15 ingest）。

- [[測試手段的優先序與成本]] — 與上三頁正交的另一軸：分層講射程，本頁講**有限資源下先投哪個**。九項手段的優先序與排序用的尺（抓到真 bug 的能力 ÷ 成本）、速度跨五個數量級的分布（只有單元測試與一筆 mutation 實測有依據，其餘標為估計）、建置與維護成本的三個不對稱（VR 跑起來不算最慢但維護成本全表最高；mutation 看似最慢卻不佔人的時間）。含 **gate 與體檢的分界**——判準是紅燈的意義穩不穩定，mutation 與 VR 都不該當 gate，導入既有專案要只擋新的。另完整收錄變異測試的定位：依附測試套件但不跟著跑、是個終點仍是單元測試的迴圈、後端值得深挖而前端不值得（Stryker 的 Vitest runner 三條限制為官方文件一手，含 browser mode 不支援；加上前端可掃面積本來就小）。並記下與業界 Testing Trophy／Pyramid 分工的獨立同向關係。**未在本專案實測**（2026-08-28）。
- [[E2E-測試的資料庫隔離]] — 同組的最外層（2026-08-28 起為第 3 層）環境前提：E2E 會真的寫進資料庫且**收不回來**（跨進程的請求包不進測試端的交易，`RefreshDatabase` 失效），故必須用獨立 database（同一台 server 另開即可）、CI 用即丟容器、開平行則每個 worker 一個 database。含三條判斷：不要用 SQLite（換掉資料庫等於拆掉第 4 層唯一的價值）、重置點放在套件開始而非每條測試之間（代價是斷言不能依賴全域狀態）、破壞性動作前加 database 名稱守衛。**內容為通用實務綜合，尚未在本專案實測**（2026-08-28）。
- [[視覺回歸測試的落地與陷阱]] — [[用測試約束-AI-產碼]] 在**畫面層**的補位：type check 與單元測試結構上斷言不到版面。兩條軸：**目標與範圍**——VR 的 oracle 只測「有沒有變」、不測「對不對」（Fujita et al. ICSME 2023 同儕審查定義；同研究實測 snapshot 測試是加法不是替代，只用 snapshot 的 repo 僅 31／1,627），範圍是**粒度 × 狀態 × 模式相乘**且 Chromatic 每個 mode 各自獨立基準與核可；以及**渲染環境的控制權放在哪**：本地 pixel-diff（Playwright）繼承整條渲染鏈的變因，雲端 DOM 重繪（Percy／Chromatic）把渲染搬離你的機器故結構上免疫。含 Playwright 的穩定化五道閘與 `threshold`（YIQ 逐像素色差）與 `maxDiffPixels`（差異面積）的分工、`-u` 三種語意；八個踩點以**容差救不了字形差**（機制決定、非調參）與 **Docker 不是銀彈**（官方從未推薦，issue #35143 一手：同 image 同 kernel 仍 1px 飄、維護者無解）為首，另含 CJK tofu 前置條件、基準圖逐分支治理與重產前須分辨既有漂移。2 條勿引用（「AI 產碼讓 VR 更重要」與各式假陽性率數字皆只有廠商行銷文）（2026-08-19 研究回存）。
