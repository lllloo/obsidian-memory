2026-08-11 拍板。從 [[不讀碼時該看哪些圖]] 的九張逐張討論（以 165_jiamao 實例驗證：container 實畫、路由檔抽功能地圖、DB 即時查 ER 切片、核決單 enum 狀態機、部署兩環境對照）收斂而成，供日後產專案大綱與架構圖時直接套用。

## 六項、兩層

分層判準由使用者提出：**「每專案一張」vs「每個主題一張」**。

| 層 | 圖 | 維護方式 |
|---|---|---|
| **大綱層**（每專案一張，上手時看） | Context | 人畫，幾乎不動 |
| | Container | 人畫，很少動 |
| | 功能地圖 | 路由檔自動抽 |
| **細節層**（每主題一張，要用才畫） | ER 切片 | 機器產（GUI 直開或 `tbls doc`；一個 use case 一張、distance 1） |
| | 循序圖（典型流程） | 即畫即棄，不維護 |
| | 狀態機 | 宣告式 enum 可 dump；規則慢變可留檔 |

用法：**新人報到給大綱層三張；指派任務時再給該主題的細節層**（如接手核決＝大綱三張＋核決 ER 切片＋送核循序圖＋核決單狀態機）。

## 已移除三項（勿再提議入清單）

- **System landscape**——「管多系統」的需求 GitLab 專案列表已覆蓋，不值得維護一張圖。
- **依賴規則**（Deptrac／dependency-cruiser 類 CI 檢查）——本來就不是圖；刪的是清單席位，使用者主動問約束工具時仍可答（選型拍板：PHP 用 Deptrac、JS/TS 用 dependency-cruiser），但不主動推銷。
- **部署圖**——較少用到；部署知識已在 compose 檔（宣告式、進版控），要看再讀檔或現畫，不佔常備席位。
