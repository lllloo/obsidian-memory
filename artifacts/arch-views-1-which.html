該畫哪些圖

「架構圖有哪些分類」這個問題有兩個答案，因為它其實是兩條互相垂直的軸。搞混的後果很具體：從其中一條軸出發，會結構性地答不到另一條軸上的問題。

最關鍵的是最後兩列。四套體系裡只有 Rozanski & Woods 把資料與維運當成一等視圖。這有實務後果——當處境是「想先看懂資料怎麼在系統裡來回」時，從 C4 出發會結構性地答不到點，因為那個東西根本不在它的清單上。

ISO/IEC/IEEE 42010 只定義 viewpoint／view 這組概念框架本身，不提供具體清單，故不列入比較。

選層：C4 官方自己給了判準

C4 官方 FAQ 逐字列出四層的過期速度，這是其他框架沒給的東西——arc42 是文件模板、4+1 是視角切分，兩者都沒說哪一層會先爛掉。

層內容官方標的變動速度對 AI 產碼的意義

兩個會改變你期待的事實

三大雲廠商都不採用 C4

AWS 與 Google 的官方架構頁完全不提任何記法標準，只給 icon 與 Well-Architected Framework。Microsoft 是唯一具名提到 C4 的，但定位是「可選、非採用」：

Several open specifications exist that you can base diagrams on. Adopting one is a workload team decision; do so only if it adds required shared vocabulary to reduce ambiguity. If your current visual communication approach already works, avoid adding process weight just for formality.

而 Azure 自訂了一套圖種分類（context／container／component／deployment／DFD／sequence／ERD…），用詞跟 C4 撞名但不引用 C4 定義——借用分層直覺，不採規格。

「哪套框架是主流」這題沒有可信答案

沒有任何大樣本、非廠商自辦的調查在 2024–2026 量測過架構圖框架的選擇。流通的採用數字只有兩個來源：IcePanel 的問卷（n=96／n=75，該廠商自己就賣 C4 工具，兩版全文對 arc42／UML／4+1 命中數皆為 0），以及 arc42 官方 FAQ 自承缺乏國際使用統計。

唯一對真實產物做計數的同儕審查研究（ECSA 2024，373 份 GitHub 架構視圖）顯示的是框架本身就不是主流：96% 非正式方框連線、4% 半正式（主要 UML）、0% 正式標記法。

「arc42 與 C4 主導實務」是 2026 年 ICSA workshop 論文的寫法，但引用鏈只到框架作者自家網站與自出版書，零採用率數據。同篇還把廠商行銷調查的「93%」洗進同儕審查論文——引用前務必回溯。
