前後端分離的測試地圖

前端 Vue、後端 Laravel，兩端各自獨立部署、透過 HTTP API 溝通。「還有什麼測試」之所以列不完，是因為測試不是一條清單而是四個互相垂直的維度；把它們排成一列，就會覺得永遠有漏。六張圖：先給四維度的總框架，再展開最常用的那一維（射程），最後是判準來源的光譜與導入順序。

01四個維度 02射程：四層測試各自涵蓋誰 03第一層的關鍵動作：讓判斷脫離框架 04一個測試該歸哪一層 05判準從哪裡來 06導入順序與停止條件

01四個維度

任何一種測試都可以在這四條軸上定位。列不完的感覺來自把不同軸的東西排成同一列。

02射程：四層測試各自涵蓋誰

維度 01 的展開。前兩層在單邊之內，後兩層跨越 HTTP 邊界。中間那條虛線是分離架構所有麻煩的來源。

03第一層的關鍵動作：讓判斷脫離框架

同一條「滿 1000 打九折」，寫在框架內部與抽出來之後，測試要穿過的東西完全不同。虛線框是「必須先啟動才能進去」的殼。

04一個測試該歸哪一層

不必憑感覺分類。三個問題依序問下去，每個測試都有唯一歸屬。

05判準從哪裡來

維度 02 的展開，也是挑手段時最該問的問題。越往左，判準的權威來自程式碼自己；越往右，來自程式碼以外的東西。

06導入順序與停止條件

每一步的前提是上一步已經穩。停止條件比開始更重要——沒有它，這條路會一直加下去。

這裡沒畫什麼。六張圖畫的是測試手段的定位與順序，不是任何一個實際專案的架構——框裡的 PricingService、utils/pricing.js 都是示意。也沒有畫 CI／CD 與部署流程，以及 fuzzing、accessibility、performance 這幾類：它們在維度 02 上各有位置（分別是「不該崩」、WCAG 外部標準、效能預算），但與前後端分離這個主題的關聯度不如上面幾項。

強度標註的來源。圖 05 的證據強度引自本 vault 的 用測試約束-AI-產碼 頁證據總表，該頁每條主張各自標了出處與限制。此處的簡短標籤是壓縮版，要引用請回該頁看完整脈絡與「勿引用」清單。
