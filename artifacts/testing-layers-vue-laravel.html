前後端分離的測試分層

前端 Vue、後端 Laravel，兩端各自獨立部署、透過 HTTP API 溝通。這個架構對測試的影響不是「工作量變兩倍」，而是多出一個誰都不擁有的問題：兩端各自全綠，接起來仍然可能是壞的。三張圖分別畫四層的射程、第一層那個關鍵動作，以及一個測試該歸哪一層的判準。

01四層測試的射程

前兩層在單邊之內，後兩層跨越 HTTP 邊界。中間那條虛線是分離架構所有麻煩的來源。

02第一層的關鍵動作：讓判斷脫離框架

同一條「滿 1000 打九折」，寫在框架內部與抽出來之後，測試要穿過的東西完全不同。虛線框是「必須先啟動才能進去」的殼。

03一個測試該歸哪一層

不必憑感覺分類。三個問題依序問下去，每個測試都有唯一歸屬。

這裡沒畫什麼。三張圖畫的是測試分層的機制，不是任何一個實際專案的架構——框裡的 PricingService、utils/pricing.js 都是示意。也沒有畫 CI／CD、部署流程，以及 mutation testing、property-based testing 這類「驗測試本身可不可信」的手段；後者不是第五層，而是垂直穿過所有層的另一個維度。
