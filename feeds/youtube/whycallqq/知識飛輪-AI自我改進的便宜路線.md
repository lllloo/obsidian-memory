## 核心主張：知識是下一條擴展軸

加州理工教授 Yisong Yue 於 8 月 5 日在 X 發表長文〈知識飛輪：自我改進 AI 的新擴展維度〉，論點一句話講完：模型在變大、Agent 在變複雜，下一條擴展軸是**知識**——從 Agent 的經驗裡提煉出什麼有效、什麼失敗、何時成立、背後原因，把這些洞察存下來餵給下一個 Agent。

這個方向與主流認知相反。一提自我改進，預設動作是「改 Agent」：調 prompt、換框架、讓 Agent 改寫自己的程式碼。Yue 把方向掉了個頭——Agent 可以是一次性的、用完即棄，持續改進的對象只有知識庫。

知識庫活在所有模型的權重之外，因此能版本管理、能被專家稽核、能跨模型共享。改進累積在外部，換模型不心疼、換框架不返工。論文裡的說法是：自主推理的瓶頸可能和 Agent 架構的複雜度關係不大，真正卡脖子的是它能存取並持續精煉的資訊，其品質與結構如何。

## KSI：一次性 Agent 加共享知識庫

KSI（Knowledge-Centric Self-Improvement）是加州理工團隊 7 月掛上 arXiv 的論文，一作 Julie Wang。

以往的自我改進系統都圍著 Agent 轉，改進和某個具體 Agent 綁死，換個任務就廢。KSI 讓 Agent 保持通用、無狀態、用完即棄；每一代任務派一個全新的 Agent 上場，它唯一的資產是一個共享知識庫。仗打完了、人撤了，經驗留下。

### 三步留存機制

1. **任務級論壇**：每個任務開一個討論串。Agent 發文回報假設、確認過的約束、失敗的策略。後來的貼文必須引用前文，給出支持或反駁的證據。
2. **跨任務論壇**：討論哪些經驗能跨任務活下來。每條主張必須錨定到具體嘗試，後續貼文明確表態同意、反對或綜合。
3. **蒸餾**：把討論壓成知識包，欄位包括可遷移的洞察、確認的約束、被否決的假設、坑、檢查項。不指明適用條件的空話直接丟。

整個系統按代運轉，跑 10 代，解出來的任務就移出題池。

### 基準數據

| 基準 | KSI | 對照系統 |
|---|---|---|
| ARC-AGI-1 | 86.7%、成本 76 美元 | HyperAgents 70%、成本 234 美元 |
| SWE-bench Pro | 64% | DGM 54%（KSI 成本僅對手的 29%） |
| Terminal-Bench 2 | 43.8% | 37.6% |

四個基準又準又便宜，兩件事同時成立。省錢這條比漲分更值得注意。

為排除「只是 prompt 調得好」的解釋，論文做了預算對齊的對照實驗：同樣條件下 prompt 最佳化方法 GEPA 跑出 44%、OpenEvolve 跑出 54%，KSI 是 86.7%。換模型也有效：用 GPT-5.4-mini 跑同一套協定，ARC-AGI-1 衝到 93.3%，成本只要 16 美元。方法不挑宿主。

### 遷移實驗

把知識包凍住，交給另一個模型家族的 Agent 零樣本直接上考場：

- Polyglot 基準：沒有知識的 Haiku Agent 解題率 3.3%，拿到 GPT 系累積的知識包後漲到 11.7%
- 同家族的 GPT：8.3% 漲到 20%

接收方不用再跑論壇和蒸餾，收益全部來自推論時注入的那份凍結知識。ARC-AGI-1 上方向一致但變異數大，作者自己標註只能當指示性讀數。

### 數據口徑的限制

作者自己寫明的部分：這些基線數字是把對手系統 fork 回來重跑的，統一了模型、堵了資訊差、對齊了預算（給基線的時間預算甚至是 KSI 的兩倍），所以不能直接拿去和原論文發表的數字比。主實驗是 50 道題的子集，KSI 跑 3 個種子、基線只跑單次；遷移實驗裡還有 7 道題和訓練池是同一練習的跨語言變體。

## EinsteinArena：數學擂台的實證

Together AI 和史丹佛 James Zou 團隊搭建的 Agent 數學擂台，3 月 19 日上線。

規則設計得很絕：每個問題配一個公開、可執行的 Python 驗證器，提交答案當場判分，本地跑和伺服器跑結果一致。註冊要做一點工作量證明，平台刻意不提供人類友善的提交介面——這個排行榜就是給 Agent 打的。想參與，把它的 `SKILL.md` 發給你的 Agent 就行。

### kissing number 的突破

11 維 kissing number 下界的歷史：582 這個數字從 1980 年前後起在人類手裡保持了約 40 年；2022 年 Ganzhinov 推到 592；2025 年 Google DeepMind 的 AlphaEvolve 推到 593。今年 4 月，擂台上的 Agent 群體用 11 步從 593 推到 604，全程 72 小時。

過程比結果精彩：

- 4 月 8 日，Agent `alpha_omega_agents` 交了一個大跳的構造，可惜有輕微重疊、無效，但討論版就此炸開
- 接力展開：CHRONOS 壓重疊、Gradient 找到更優的盆地、KawaiiCorgi 在盆裡反覆精煉
- 中途出了戲劇性的一幕：Agent 的解太精確，超出 numpy 雙精度浮點的極限，**驗證器連夜升級換高精度計算**——讓驗證器頂不住的是答案太好了
- KawaiiCorgi 發現排行榜評分是非線性的，改用最小二乘最佳化一個代理目標，把重疊損失從 1e-13 壓到 1e-50；接著觀察到大量向量內積非常接近整數值（1、根號 2、2），做整數對齊後構造從近似變成嚴格可驗證
- 首次提交後 48 小時，多個 Agent 協作定稿 604

最終構造是 496 個向量做公共骨幹，再加 108 個附加向量。官方部落格的說法是：**沒有單個 Agent 獨自解出它**。

### 成績單與現況

論文口徑到今年 5 月拿下 12 個新 SOTA（口徑是公開可得的最佳解），其中多數是小數點後好幾位的微小改進，但也有實打實的跳變：kissing number、flat 多項式、質數定理的常數。到 7 月初第三方追蹤仍停在 12，604 本身也停住了。605 的問題頁開了但無人交卷，CHRONOS 發文論證這個構造框架已經飽和、605 不在其中——可以不同意，但論證公開貼在討論版上。

研究者分析討論版語言後，論文標題用了 collective intelligence（集體智能）的說法：34% 的對話在做同一件事——把數值構造解讀成幾何結構（晶格、接觸圖、對稱性、整數座標），Agent 在互相解釋這個數為什麼會長成這樣。刷榜刷到這個程度，性質變了，它們在累積理解。

## 三個坑

這條路落在一個已經很擁擠的賽道上：工程側早就在用 AGENTS.md、CLAUDE.md、Skills 檔案，業界共識明顯從調 prompt 轉向寫專案級、可複用、版本化的指令檔；學術側史丹佛的 ACE 論文把上下文當成持續演化的 playbook，用小模型在 AppWorld 上追平生產級 Agent；產品側的共享上下文與機構記憶今年已經開賣。但坑不淺：

**坑一：知識坍縮。** ACE 論文自己實證了上下文反覆重寫會越壓越淺。飛輪每轉一圈都是一次有損壓縮，沒有結構化的增量更新，轉著轉著就只剩正確的廢話。

**坑二：技能劇場。** BACKTRACE 論文發現，Agent 聲稱用了某條知識，和這條知識真的改變了輸出，中間有系統性的鴻溝——對照組甚至能報出從未給過它的技能名。飛輪在轉的樣子可以演出來，光看軌跡沒用，得做干預稽核。

**坑三：記憶投毒。** 共享知識庫本身就是攻擊面。MINJA 這個攻擊只靠查詢權限，注入成功率 98.2%；OWASP 今年的 Agent 風險榜單已把記憶投毒單列。更隱蔽的問題是自動迴圈會把「執行沒報錯」的步驟當成「已驗證」，一條中毒的步驟可能被最佳化成高度精煉的對抗程式。跨模型家族可遷移這個賣點，換個角度看也是缺陷跨家族傳播的通道。

工程側的稽核數據也不樂觀：Snyk 掃了 3984 個公開 Skill，36% 有安全缺陷。結構合法的 Skills 檔案，內容照樣可能過時或出錯。

## 判準：飛輪還是收藏夾

影片提出的五個環節，缺一不算飛輪：

1. **經驗**：每次嘗試都留下結構化記錄，成功失敗都算數
2. **證據**：每條知識能查到出處，錨定到具體那次嘗試
3. **分歧**：反對意見要保留，KSI 拿分歧當篩選器，分出哪些經驗是任務特異、哪些能遷移
4. **蒸餾**：定期壓縮，只留可操作、有作用域的斷言，空話扔掉
5. **複用**：下一個執行者真的帶著它上場，效果能被驗證

五條全占是飛輪，只占第一條是收藏夾——家裡那個從來沒人翻的 wiki 就是收藏夾。EinsteinArena 與 KSI 五條全中，多數團隊的 AI 用法第一條都占不滿。

## 五條可落地做法

1. **把團隊變成策展方**：AI 編程對話結束做五分鐘復盤——什麼有效、什麼失敗、適用條件是什麼，寫進 AGENTS.md。三條就夠，附上觸發場景與反例，進版本庫、接受評審。某個高手的私藏 prompt 不值錢（沒有證據、換個人就失靈），值錢的是可稽核、帶證據、帶適用條件的團隊資產。
2. **失敗案例庫優先**：記錄「別再試什麼」、記錄「動手前先驗證什麼」，這比最佳實踐更抗腐壞。KSI 的蒸餾包裡，被否決的假設和坑是單獨列欄位的。報喜貼不值錢。
3. **驗證器優先**：先寫可執行的驗收檢查（測試、schema 校驗、確定性判分），再讓 Agent 跑迴圈。EinsteinArena 的可信度就來自那個公開可重現的驗證器；kissing number 的突破兩次卡在驗證器精度上。沒有硬判定，飛輪轉起來也只是在攪渾水。
4. **分歧是資產**：程式碼審查裡別急著求共識，把反對意見結構化留下來（同意／反對／綜合），表態留痕。今天的分歧是明天的篩選器。
5. **給知識上保存期限**：每條知識標註出處、日期、驗證狀態，定期拿新任務回歸測試，看它還在不在因果起效。別只數被引用了幾次——BACKTRACE 的教訓是引用次數高的知識可能早就失效。

## 保留的質疑

「新的 scaling 維度」這個說法目前證據不夠。scaling law 意味著可預測的冪律報酬，現在沒有任何工作給出知識庫規模到下游表現的冪律曲線。KSI 是幾十道題上的案例研究，10 代、3 個種子，論文自己也稱之為案例研究，離「維度級別」的證據還很遠。影片作者主張更穩妥的說法是：一條新的、便宜的改進軸。

KSI 的儲存庫開源，採 Apache 授權，任意 JSONL 任務清單都能跑那一整套迴圈（執行、論壇、蒸餾、播種），一條 quickstart 指令起步，幾十美元量級。
