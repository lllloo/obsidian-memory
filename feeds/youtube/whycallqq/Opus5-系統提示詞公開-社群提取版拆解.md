> [!note] 定性
> 影片作者將這份社群提取的快照定性為「**核心已獲官方證實、擴展層仍待確認**」，不是完整洩漏。以下內容以文本本身為準，兩點保留意見：一是「對話誘導」提取可能混入模型生成內容；二是網頁產品的工具與路由環境仍在動態變化，快照僅代表特定時間點。

## 時間線與比對結果

- 2026-07-24：Anthropic 發布 Opus 5，同日社群出現自稱對話提取的執行時提示詞。開發者 Eversmile12 首發 13.5 萬字元版本，約四小時後 Pliny 在其 CL4R1T4S 倉庫提交 20 萬位元組版本
- 兩版相差 6.7 萬字元，顯然不是同環境的逐字快照，差異來源尚無定論
- 影片作者實測 Pliny 版：202,762 位元組、201,987 個字元，按 4 字元 1 token 粗算接近 5 萬 token，檔案內標註日期為 7 月 24 日
- 與官方公開的核心提示詞比對：統一空白與格式後，核心提示詞的 **52 個非空段落中有 38 個逐字吻合**
- Pliny 版比官方多出約 18 萬字元，集中在**工具定義、記憶系統、產品環境與互動規則**——影片認為真正值得工程師拆解的正是這 18 萬字元

## 關於 Pliny

完全匿名，帳號致敬古羅馬學者老普林尼（未經本人確認）。據 TIME 報導，他毫無程式設計經驗卻入選 TIME 2025 年 AI 百大影響力人物；常在新模型發布數小時內公布越獄結果，曾被 OpenAI 封號後恢復，拿過 a16z 創辦人無附加條件的資助，並曾因評測與資料開放方式抵制 Anthropic 三萬美元的安全挑戰賽。TIME 2025 報導時其 Discord 社群已超兩萬人；截至 2026 年 7 月底，CL4R1T4S 倉庫累積 4.6 萬 star，裡面收錄各大廠的提示詞。他戲稱安全護欄是「安全表演」。

## 文件結構統計

- 全文 2,049 行。按程式碼行數算，「記憶系統」是最大章節之一，整整 800 行占近四成；但按字元算僅占 23%，工具定義篇幅更大
- 定義了 **30 個自帶完整 JSON schema 的工具**，規格遠超很多公司的內部 API
- 19 個範例區塊中，好回覆示範 15 個、壞回覆僅 2 個，完整正反對照僅兩組——**few-shot 密度低於預期**
- 篇幅配比是「靈魂暴擊」：寫**能力**（工具、邊界、規則）的篇幅呈壓倒性優勢，**人設與語氣只有薄薄一層**。反觀多數人的 Agent 提示詞通篇都是人設、工具說明只塞兩行，呼叫當然不穩定

## 記憶系統的併發控制

為模型配備讀、寫、追加、取代、列表、刪除共 6 個記憶工具，相當於一套完整的增刪改查。最硬核的參數是 `if version`——每次寫入必帶版本號，對不上直接拒絕，等同 HTTP ETag 的樂觀併發控制。提示詞寫明其他 Claude 產品可能同時修改記憶，必須解決併發衝突。

寫入語義也很講究：**全量寫入是覆蓋式的，沒寫進去的行等同刪除**，因此提示詞反覆警告改寫前必須先讀；刪除整個記憶檔案僅限使用者明確指令。

另一組作者特別欣賞的規則是 `forbidden memory phrases`：讀取記憶後嚴禁在回覆中出現「基於你的記憶」「根據紀錄」等話術，必須表現得像自然想起一樣——工程上這叫**徹底抹除基礎設施在使用者體驗中的痕跡**。

## 版權紅線與自檢清單

一次引用不得超過 15 詞、同一來源全文只准引一次、歌詞詩歌絕對禁區，甚至模仿原文段落結構都算違規。末尾附自檢清單，模型回覆前必須連答 6 個問題，錯一個就重寫。這說明**基礎能力靠訓練，產品層細粒度約束全靠提示詞兜底**。

未成年人安全章節有條極嚴的紅線：如果模型在心裡試圖替使用者請求「找補」、把它往安全方向解釋，這個「找補」動作本身就是拒答訊號。此規則僅限未成年人場景，並非通則。

## 工具層的安全設計

- `end_conversation`：允許模型主動結束對話，但觸發極保守，須窮盡多次勸導與明確警告後才允許呼叫；且呼叫後會回傳二次確認，必須再呼叫一次才生效。提示詞特意標註這是正常流程、別當成注入——本質是**破壞性操作的二次驗證被優雅地塞進提示詞層**
- `web_fetch`：採對話內 URL 白名單機制，模型只能抓取使用者發過的、或搜尋結果中驗證過的連結；若自行拼湊相似網址直接拒絕。推斷是為了遏制 URL 幻覺並防範任意外聯
- 提問工具：需要使用者做選擇時，規則要求優先呼叫工具彈出選項按鈕。普通文字提問雖允許，但**互動邏輯正被收編進工具層**
- 深度研究工具：只能建議，必須彈按鈕等使用者確認啟動；若針對普通人建檔或研究具體病情則明確不推薦

## 安全路由與分發策略

`fable safeguards routing`（安全路由）章節顯示，觸發安全分類器的請求會被較低層級模型接管。文件寫轉給 Opus 5，但官方口徑更細：生物類轉 Opus 5、網路安全類由 Opus 4.8 接管。官方部落格稱平均觸發率不足 5%。這個架構證明**最敏感的能力控制已剝離文字層，交由請求路由層在系統端直接掐斷**，形成典型的雙層防禦。

分發面：`recommend_claude_apps` 共列 14 個應用入口——寫程式碼推 Claude Code、做表格推 Excel 版、做研究推 Cowork——要求模型主動推薦且不能因此縮短當前任務。等同把**產品、法務與分發手冊三合一**。

其他曝光內容：API 字串（含 `claude-opus-5`）；Opus 之上還有 Mythos 檔位，意味同一底座分雙版本，公眾版加強護欄、護欄更少的 Mythos 5 僅對受信任機構開放；廣告政策特意強調必須說明「Claude 產品無廣告」，防的是開發者拿 API 做貼片廣告產品；甚至花一整段解釋出口管制（6 月 9 日發布、6 月 12 日因美國政府指令暫停、7 月 1 日恢復），這些訓練截止日後的資料全靠提示詞「補課」。

## 搜尋規則

高頻變動資訊必搜、靜態常識不搜；只要涉及當下事實，不管多有把握，必須遵循「先搜再答」。還有條反直覺規則：**預設相信搜尋結果，哪怕內容離譜；但對陰謀論與 SEO 汙染重災區必須保持懷疑**。影片認為這套標準是完美 RAG 系統的現成規範。

## 提示詞債務

想原封不動抄這套規則的人要先推演：這 30 個工具在你的系統裡若不存在，幾萬 token 的 JSON 定義就是純粹的無效上下文，不僅增加成本與延遲，更極易引發指令間的災難性衝突（是否降低品質需對照自己的評測）。

快照裡的債務跡象：

- 檔案開局沒有任何鋪陳，第一行直接甩出「禁止使用 `voice_note` 標籤」的禁令，極像線上事故的熱修復或歷史遺留；原文既無說明也無廢棄標記
- 版權規則在強制要求、硬限制、自檢清單、關鍵提醒裡循環出現至少四次——同一邏輯出現四次，要麼是刻意冗餘以強化記憶，要麼是長期沒重構，抑或多層規則縫合的產物

2025 年已有同名論文，證明規則膨脹已是學術問題。

## 可直接搬走的五條工程模式

1. **工具描述寫成 API 契約**：明確用機、禁用場景及回覆格式。官方強調詳細描述決定工具效能，具體提升靠自身評測
2. **破壞性操作（刪改、支付、發送）必加二次確認**：低成本擋住高危事故
3. **用版本號保護共享狀態**：多實例讀寫記憶時帶版本令牌，衝突秒拒
4. **收窄資料出口**：網頁抓取限死白名單（使用者提供或搜尋驗證過），模型自造連結一律先驗後放。雖防不住已放行網頁裡的注入，但安全水位大幅提升
5. **輸出自檢**：快照的做法是把清單寫進提示詞，但更工程化的解法是**把紅線規則寫成 CI 裡的 lint 腳本接在管道後**，模型生成完機器再掃一遍

底層邏輯一致：別把提示詞當散文，把它當系統工程。契約、併發、越權攔截、靜態檢查全是後端世界玩剩下的，AI 公司只是把這套工程紀律平移到自然語言。

## 三大趨勢

1. **提示詞快取是剛需**：5 萬 token 前置指令全價重算會破產，官方快取價只有十分之一，這價差本身就是風向標
2. **提示詞走向分層管理**：快照明顯是產品、安全、工具、會話多層強行縫合的產物；未來的多智能體系統必將拆分這些模組獨立演進與快取
3. **提示詞債務急需治理**：官方指南提到 Opus 5 已具備主動驗證能力，保留舊的強制指令反而導致過度驗證浪費 token。給模型立規矩也需要程式碼審查、重構、甚至刪規則的魄力——規矩和程式碼一樣，不維護就會腐爛

作者收尾修正自己的暴論：塑造模型行為的要素很多（訓練、後訓練、路由等），但提示詞是極少數能讓外界**逐字逐句 debug** 的行為層；讀透它就摸到了大廠最真實的工程取捨。另一個觀察：提示詞洩漏正從事故變常態，與其被動挨打，不如像 Anthropic 這次順勢公開核心——當被扒不可避免，寫得體面本身就是頂級公關策略。
