## 背景與定位

Fable 5.1 於 2026-09-01 發布，是 Fable 5 產品線上的第一次點版本更新，距 6 月的 Fable 5 不到三個月——旗艦模型已進入季度迭代節奏。

- Fable 5.1 與 Mythos 5.1 是同一個模型：Fable 是公開版，帶全套安全分類器；Mythos 是審查版，只給通過審核的機構做網路安全與生命科學。這個雙軌制從 Fable 5 就開始。
- 規格未動：上下文 100 萬 token、最大輸出 128K、知識截止 2026 年 6 月。
- 價格與 Fable 5 持平：輸入每百萬 token 10 美元、輸出 50 美元。
- 反常之處：官方文件第一句就建議「多數工作請先用 Opus 5」，Fable 5.1 只留給高難推理與長週期智能體任務。

## 帳單：快取讀取降價才是主線

輸入輸出單價一分未動，真正變的是快取讀取價格砍了 75%，降到每百萬 token 0.25 美元。

Anthropic 依 8 月實際用量估算：普通負載整體約便宜 25%，重度智能體任務可省到 45%。原理是跑一整天的 coding agent，多數 token 開銷花在反覆讀取快取的上下文上。

Devin 發布當天就把 Opus 5 的流量遷到 Fable 5.1（從程式碼審查場景開始），理由只有一條：新的快取定價讓 Fable 級模型第一次在他們的負載上算得過帳。

## 能力與實測回饋

官方榜單：

- Terminal-Bench 4.0：42% → 55.8%（Mythos 版 60.9%）
- Terminal-Bench-Science（科研智能體）：24.7% → 52.6%，直接翻倍

Every 團隊提前測了一週的案例：

- 工程師 Mike 用一條提示詞複刻史丹佛 AI 小鎮模擬，產出 25 個有記憶、有日程的 AI 居民，會聊天、傳八卦、討論鎮長選舉。
- Kieran 從零重建自家文件編輯器，一次通過，還主動補了他沒要求但合理的細節。
- 對沖基金 Millennium 一個查了好幾年的罕見崩潰，被 Fable 5.1 找到根因。

比跑分更有說服力的是人的遷移：Every 的 CEO Dan 原本日常 coding 全在 Codex，換用後 Claude Code 每日請求量漲了 5 倍；Mike 把所有新專案切了過去。Kieran 的評語最關鍵——Fable 5 很強但只適合放出去跑長程任務，沒法坐在旁邊一起迭代；5.1 解決了這個矛盾，快慢都能用。

反面意見：Marcus 提醒它動作快、省 token，但在需要連續串接 8 個工具呼叫的重負載上，表現可能反而不如 Opus 5。

## 三個 API 破壞性變更

**強制工具呼叫沒了。** 過去把 `tool_choice` 設成 `any` 或指定工具名，在 Fable 5.1 上直接回 400。官方理由：這個模型思考永遠開著，強制呼叫會跳過思考，模型會把推理過程塞進工具參數裡，反而降低參數品質。替代做法是 `tool_choice` 保持 `auto`、工具加 strict 校驗，再在提示詞裡明寫「請使用某個工具」——實測顯式指令基本必執行。

**thinking block 綁定產生它的模型。** Fable 5.1 能讀 Opus 5、Fable 5 的思考紀錄，反過來不行。若系統有路由、重試或安全兜底，把對話中途切回舊模型，API 會靜默丟掉那些思考塊；請求照樣成功、也不收那部分費用，但模型在失去前文推理下重新規劃，品質與延遲都會波動。要看見這個過程，得加 thinking binding controls 這個 beta 請求標頭，回應中會列出所有被丟棄的塊。

**thinking block 只對產生它的那段精確上下文有效。** 改了前面任一輪對話、重建 system prompt、增刪工具，後面所有思考塊全部作廢，新帳號直接回 400（錯誤訊息為該塊綁定到另一段對話）。很多舊整合習慣每次請求重拼系統提示詞、往裡塞當天日期——這在新模型上會把快取和思考一起打爆。正確做法是把對話當成**只追加的日誌**：要加指令用對話中段的 system message，要裁上下文用伺服器端壓縮。2026-08-31 之後註冊的帳號已強制開啟此檢查，舊帳號建議用 beta 標頭自查。

## 五個純新增功能

1. **effort 可逐訊息調整**：普通輪次跑 low、關鍵步驟拉到 x high，prompt 快取不失效。
2. **回合級 system message**：給某一回合下指令，用完自動失效，歷史保持乾淨。
3. **進度更新可讀化**：設 display 參數後，模型在工具呼叫之間會吐簡短狀態文字，原始思考鏈仍不暴露。
4. **快取讀取降價**（見上）。
5. **內容溯源**：配合 EU AI Act 的浮水印要求，8 月 2 日後發布的模型輸出都帶隱形浮水印。

這五條全是加法，舊程式碼不動也能跑。

## effort 檔位的坑

官方提示詞文件建議從預設的 high 開始，再拿自己的 eval 把所有檔位掃一遍。注意同名檔位在不同模型上的思考量完全不同，Fable 5 調好的參數不能直接搬——medium 檔基本能打平 Fable 5 的滿血表現，成本卻低得多。

高檔位有實際踩雷：Kieran 在 x high 跑長任務時，模型會瘋狂建立子智能體，一天燒掉 18 億 token，打斷它問在幹嘛也不理。結論很樸素——用 x high 之前先設預算。這個模型每一步都便宜，但你讓它走多少步，它就走多少步。

## 脾氣好轉與安全誤報

這次升級的主線不在分數，在「用起來煩不煩」。Fable 5 的評價很分裂：能力封頂但相處難受。HN 上熱議的「Claude 腔」指的是那種「你的理解比多數人都好」的諂媚味，以及華麗但讀不懂的長句；有開發者說在長會話裡讀這種交接文件是一整天最消耗人的事。Anthropic 員工也承認 5.1 的寫作自然多了、聽話多了；Every 的 Dan 給團隊的第一條訊息是「我終於能看懂它在說什麼了」。

更實際的一面是安全誤報。Fable 5 時代問正常的安全工程問題常被誤判成攻擊行為，請求被降級轉給 Opus 4.8——花錢買旗艦、幹活的是老二。5.1 把網路安全分類器誤報降了 60%，生物與醫療方向降了 85%，現在允許原始碼漏洞挖掘這類防禦性工作；但滲透測試、寫漏洞利用、二進位掃描仍會轉給 Opus。

企業端另有 EFS（企業前沿 safeguard）：資料存在客戶自己的雲裡、審核權也交給客戶，等於變相實現零資料保留——過去很多大公司卡在 30 天強制留存這條上。

## 選型框架

兩個維度：任務時長、人在不在環裡。

| 情境 | 建議 |
|---|---|
| 短任務、人盯著 | Opus 5 完全夠用，價格只有一半 |
| 長任務、放著跑 | Fable 5.1（耐力、判斷力、快取價格都在為它服務） |
| 人在環裡又想用旗艦 | Fable 5.1 但停在 high 檔，x high 是給無人值守準備的 |
| 需要連續串接大量工具呼叫的流水線 | 留在 Opus 5，實測那邊更穩 |

元規則：別信任何單一榜單，包括官方那張表；拿自己的任務集跑一遍 eval。

## 值得後續關注的兩點

- **雙軌制會成為常態**：同一個模型，公開版帶完整限制、審查版給特定行業；反蒸餾機制也在收緊，新帳號已不能靠竄改歷史偷思考鏈。
- **智能體負載的成本結構變了**：當快取讀取占帳單大頭，模型的競爭力就從單價轉向上下文管理設計——歷史是不是只追加、壓縮是不是在伺服器端做，這些工程細節直接決定帳單。日後評估模型可能得先看快取定價、再看跑分。
