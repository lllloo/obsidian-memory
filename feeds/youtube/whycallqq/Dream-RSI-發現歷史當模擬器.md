## 背景：從 RSI 路線圖到可跑的系統

- Dream-RSI 是 Google 與 Google DeepMind（合作方含馬里蘭大學、維吉尼亞大學）於 9 月 14 日掛出的論文；RSI 即遞迴自我改進（Recursive Self-Improvement）。
- 上一期介紹的 RSI 路線圖論文《人類建造的最後一個 AI》把自我改進分五級：
  - L1：AI 執行人定好的改進
  - L2：AI 自選改進策略
  - L3：AI 自行獲取學習經驗
  - L4：在真實部署環境中適應
  - L5：改進「改進機制」本身
  - 並用 HCI 指標量化大模型剩餘提升空間，結論是靠人堆實驗的時代快到頭。
- 兩篇相隔四天（9 月 10 日與 9 月 14 日）：前者給座標系，Dream-RSI 給出第一個可復現的資料點，並公開程式碼、提示詞與發現出的完整程式。

## 定位：改的是搜尋策略這一層

- 不動模型權重、不動底層 coding agent，改的是更上層的**探索／搜尋策略**，約落在 L2～L5 之間（「改進怎麼改進」）。
- 要解的問題：AlphaEvolve 這類發現系統是「提候選 → 跑評估 → 看回饋 → 再繼續」的迴圈，一跑幾千輪；每輪往哪搜、搜幾個方向、何時放棄，主流由工程師手寫固定策略。
  - 固定策略學不會教訓，失敗方向會反覆燒錢。
  - 線上優化策略也不行：評估一個策略得看它跑完一整輪發現，回饋又慢又貴。

## 核心洞察：發現歷史就是精確模擬器

- 發現系統跑完一輪留下的是一棵**結構化發現樹**：每個節點是一次嘗試，帶完整執行結果、分數、程式碼快照。
- 新策略想知道「當時走另一條路會怎樣」不用真跑，沿樹換路徑回放即可，結果早在磁碟上。
- 三步循環：
  1. **線上探索**：當前策略指揮 coding agent 產生新發現樹。
  2. **建構回放模擬器**：這棵樹變成可反覆回放的模擬器，放進模擬器池。
  3. **做夢式策略改進**：策略開發 agent 寫出多個候選策略，在模擬器池離線回放打分，勝者重新上線，跑出新樹、池子再擴大。
- 「做夢」致敬強化學習的 World Models 與 Dreamer 系列；差別在 Dreamer 的世界模型是學出來的近似，這裡是真實執行紀錄——零誤差、零執行成本。

## 工程設計：策略即程式碼

- 探索策略本身是一段可執行程式碼：決定從哪些葉子繼續搜、並行發幾個請求、何時停。可 diff、可 code review、可進 git。
- 改進策略交給 LLM agent 改寫程式碼；每個版本都在全部歷史樹上回放打分。
- 當前線上版本永遠在候選集中，新策略分數只會更高、單調不降——即後端熟悉的 champion-challenger 模式，只是擂台換成歷史回放，試錯賭注近乎零。

## 實驗結果

- **演算法工程（Lasso 回歸求解器）**：
  - 基線 SimpleTES 用 GPT-OSS-120B 跑 51200 次生成；Dream-RSI 用 Gemini-3.1-Pro 只呼叫 317 次，六個留出資料集平均執行時間更低（差 162 倍）。
  - 換 Gemini-3.7-Flash：1879 次對固定策略 3200 次，結果更好。
  - 發現的求解器在六個資料集上全面勝過 sklearn 與 glmnet；做法是強規則篩選加 Cauchy-Schwarz 不等式驅動的 KKT 剪枝，只在界無法排除某特徵時才重算精確梯度。
- **數學優化（三任務）**：
  - 和差問題 1.145427，超過 SimpleTES。
  - 圓填充 2.635983，追平含 AlphaEvolve 一系在內的最佳成績。
  - 自相關不等式 SimpleTES 分數較高，但它燒了 51200 次生成，Dream-RSI 不到 1000 次（省 50 倍以上預算）。
- **GPU kernel（KernelBench 四任務）**：
  - VGG16、LayerNorm：同等效能少花 2.43 倍與 1.79 倍生成次數。
  - ConvDiv、ConvMax：同等預算效能高出 2.09 倍與 1.44 倍。
- 三領域結論一致：同等預算搜得更好，同等品質花得更少。

## 反直覺實驗：經驗總結反而拖後腿

- 論文第五章：把歷史經驗總結成幾句洞見寫進提示詞指導下一段搜尋。
- 結果：不論固定策略或 Dream-RSI，加了語意引導的版本在同等預算下**全部輸給不加引導的版本**。
- 原因：長程發現是多線程並行探索，提示詞裡的方向性建議會提前鎖死搜尋空間、殺掉多樣性——經驗總結可能是枷鎖而非財富。

## 策略自己學會的「節奏」

- ConvDiv 任務上效能從 0.427 漲到 1.898。
- 同時每輪評估嘗試次數從 110 降到 50，進入效能平台期後又回升到 92。
- 策略沒變得更貪心或更保守，而是學到「順時省著花、卡住就加大投入」——沒人寫進去，是在回放中試出來的。

## 最獨到之處：歷史從唯讀文本變成可執行資產

- 以往系統用歷史的方式：塞進上下文當背景，或拿去微調權重——兩者只拿走內容、丟掉結構。
- Dream-RSI 保留決策點、分支、結果，組成可做反事實查詢的世界，換來**離策略評估（off-policy evaluation）**能力。
- 訓練模型有離策略評估，調 agent 策略幾乎沒有，因為環境太貴；但你的環境其實早被自己記錄下來，只是沒人當模擬器用。

## 可直接搬用的三個思路（窮人版 Dream-RSI）

1. **先記錄、後優化**：把 agent 系統每次決策與結果結構化存下（樹狀、帶完整快照）；沒有這份資料，一切自我改進免談。
2. **策略與 agent 分離**：策略是一層薄、可替換的程式碼，幹活的 agent 不動，才能安全做策略實驗。
3. **能離線評估就離線**：能用歷史回放回答的問題，別花真錢線上試。

只要系統裡有搜尋、排程、試錯迴圈，這套思路就成立。

## 限制與展望

- 回放模擬器只能回放歷史真正走過的地方；全新搜尋方向樹裡沒有，模擬不出來——做夢無法取代上線，只是讓上線更聰明。
- 自相關任務仍是 SimpleTES 最好（代價是 50 多倍預算）。
- 前提是任務要有便宜可靠的自動評估器。
- 方向：探索策略將成為 agent 系統新的優化對象（類比從手調特徵 → 手調架構 → 自動搜架構）；模擬器池可擴展到多任務共享歷史、跨專案復用。
- 講者判斷：agent 系統的競爭正從「誰的 prompt 寫得好」轉向「誰的歷史資料結構設計得好」；日誌不再是排障才想起的廢料，而是自我改進的燃料。遞迴自我改進不會以一夜奇點的方式到來，而是某天有人把搜尋策略的改進也自動化、效率悄悄翻倍、再變成標配——你今天設計的日誌格式，決定系統明天能否自我改進。
