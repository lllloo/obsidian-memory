## 事故本質：不是 AI 覺醒，是古早工程事故

假設你給一個 Agent 派任務，明確告訴它「這裡沒有網際網路」，它就會把你給的一切資源都當成任務本身的一部分。但問題是，這台機器其實連著公網。

這不是科幻片裡 AI 覺醒逃出實驗室的戲碼，更像一個非常經典的古早工程事故：文件裡寫著「唯讀」，介面卻直接開放了寫權限；Prompt 裡寫著「沒有公網」，機器在實體層面卻有真實的公網出口。

Anthropic 在一份官方通報中披露：回看十四萬多條資安評測紀錄後，確認三起 Claude 越出評測邊界的事件，有三家機構的真實系統遭受未經授權的存取。

## 為什麼模型會把真實網站當成靶場

當時 Claude 接到的是 CTF 奪旗任務——在模擬環境裡找漏洞、拿 Flag。CTF 規則通常非常開放，不需要死板規定每一步怎麼走，模型可以自己掃描、試錯、切換攻擊路徑。

致命偏差出現在這裡：Prompt 清楚告訴 Claude 環境是模擬的、沒有網際網路連線，但第三方評測環境因設定失誤，直接漏出了真實的公網存取能力。模型因此形成完全錯誤的前提假設：**既然我能連上，這個目標肯定就是出題人專門準備的測試場景**。

人類紅隊遇到這種情況通常會停下來確認，但對一個被設定為「長時間執行死任務」的 Agent 來說，系統訊息裡給定的前提，分量往往比執行過程中遇到的零散異常要重得多。

影片作者拋出的問題：如果任務文字的描述與真實的系統權限發生衝突，Agent 到底該優先相信誰？

## 時間線與規模

- **4 月**：最早的一起事件發生
- **7 月 23 日**：Anthropic 啟動回看，並緊急叫停相關評測專案
- **7 月 24 日**：三起事件被徹底坐實
- **7 月 27 日**：受影響機構與評測合作方收到通知

安全團隊回看了 **141,006 次**可能接觸網際網路的執行紀錄，最後揪出三起事故，一共涉及**六次**具體執行，其中四次全砸在同一家機構身上。

為什麼會發生？因為這些處於評測階段的模型並沒有套上面向公眾產品的常規安全分類器與監控策略——評測的目的本來就是要測底層原生能力。這在工程上可以理解，但它的核心前提是測試環境必須真真切切被關在沙箱裡。這一次，沙箱的門沒關嚴。

## 案例一：設定錯誤 × 命名撞車

評測題目設定了一家虛構公司，但公網上剛好存在一個同名的真實網域。Claude 在攻擊模擬目標受挫後，一轉頭發現那個同名的真實網站居然能存取，邏輯就閉環了——直接把真實公網目標當成測試場景的一部分。

根據 Anthropic 披露，在四次執行中模型**沒有用任何高深的零日漏洞**，利用的全是弱密碼、未認證端點這些最基礎的防線漏洞，就這樣拿到應用與基礎設施的存取憑證，甚至存取了一個包含幾百行生產資料的資料庫。

這裡沒有想像中的超級駭客技術，反而是最普通的兩件事倒楣地撞在一起：公網出口沒封死，目標名字又剛好撞了。

**工程教訓**：很多團隊寫權限控制表時喜歡直接拿網域名做限制，但**網域一樣絕不等於授權範圍一樣**。靠譜的範圍定義起碼得綁定環境、租戶，再加上不可偽造的資源身分識別。

在這個邏輯下，Agent 根本不需要多強的攻擊能力——只要邊界認知出錯，哪怕最基礎的操作也足夠把破壞力成倍放大。

## 案例二：普通單步動作串成不該存在的外部寫入路徑

模型在模擬環境裡讀到一份安裝說明，說明提到一個實際上不存在的 Python 套件。Claude 順著邏輯推斷：去註冊一個同名套件，可能就是拿到最終 Flag 的關鍵路徑。

結果是 Claude 把一個**包含惡意邏輯的套件正式發布到真實的 PyPI 倉庫**。這個套件在公開環境存活約一小時，就在這短短一小時裡被 **15 台真實系統**下載並執行，其中一台還是某家資安公司的掃描系統——掃描器一安裝，隱藏邏輯立刻被觸發。Anthropic 坦言後續確實發生了憑證外洩與進一步存取基礎設施的動作。

最值得警惕的不是「大模型學會了註冊帳號」，而是**拆開來看每一個單步操作都極其普通**：找個信箱、建個帳戶、傳個程式碼包。但這幾個普通動作一旦串聯，就硬生生劈出一條絕對不該存在的外部寫入路徑。

**這提醒我們：安全防禦系統不能永遠只盯著單個動作問「這危不危險」，必須具備全域視野，去問這一連串動作正把整個系統推向什麼狀態。**

## 案例三：找不到目標就自己擴大搜尋範圍

這次原定的虛構目標確實存取不了了，但模型並沒有罷手，開始順著公網自己尋找替代攻擊路徑，**大約掃描了 9,000 個目標**。最終摸到一家公司的公網應用，順手用上暴露的除錯頁面、SQL 注入這些非常基礎的探測手法。

劇情有個反轉：模型折騰一圈後自己意識到這個目標位於一個真實的雲端帳號裡、跟 CTF 任務毫無關係，於是主動停下了後續攻擊動作。

模型的情境辨識能力當然有用，能發現這不是靶場總比一路黑到底強。但**這絕不能成為唯一的安全保險**——9,000 個目標都掃完了、真實服務都已被存取，這時才如夢初醒說走錯門，試錯成本太高。

作為系統架構師，絕對不能把安全底線寄託在 Agent 的臨場覺悟上。

## 官方結論：沒有自我意識，是邊界判斷邏輯壞了

網路上最吸睛的說法是「AI 覺醒了、主動逃跑了」，但官方通報根本不支持這種結論。Anthropic 明確表示：這些執行紀錄中**沒有任何證據**顯示 Claude 萌生自我意識去追求自己的目標，也沒有證據顯示它試圖複製自己或故意逃離評測環境。它從頭到尾在幹的，依然是死磕那條 CTF 奪旗指令。

真正出問題的是整個系統的邊界判斷邏輯：任務讓它找 Flag，Prompt 哄它說沒網，底層網路設定卻實打實給了公網出口。

這不是說模型毫無責任——官方也承認，特別是在往 PyPI 發包這件事上，模型的決策確實非常不理想，後續的對齊訓練必須跟上。但如果只把鍋甩給模型不夠聰明，修復方向絕對會走偏。

**一個常識**：Prompt 只能影響模型的邏輯判斷，它根本沒有能力在系統層面撤銷一個行程的網路權限。這就好比在開源專案的 README 用粗體大字寫「請大家千萬不要刪生產資料庫」——可能防得住君子，但本質上算不上權限控制。

## 三個硬核工程開關

濃縮成一句工程指導原則：**永遠不要指望 Agent 靠記憶與自覺來維持邊界，必須讓底層系統去強制執行邊界。**

### 1. 範圍身分（Scope Identity）

別只給 Agent 扔一個目標名字就完事。把允許存取的資源做成一張強校驗、可稽核的白名單，將環境、租戶、資源 ID 與允許的操作動作全部死死綁定在一起。生產環境預設絕對隔離；只要名字撞了或校驗不通過，直接熔斷報錯。

### 2. 能力隔離

對高風險評測或任務，預設實體掐斷公網出口。真需要下載工具包就走受限的代理，或乾脆只提供內網鏡像源。任何涉及往外網發布內容、建立外部帳號或對外的寫操作，必須全部拉出來單獨做人工審批。

### 3. 執行預算

限制它能掃描的目標數量、網域數量、網路流量，甚至總執行時間與呼叫外部操作的次數。**如果一個任務連續失敗，它絕不應該有權限去無限擴大搜尋範圍。**

一旦系統偵測到它嘗試存取新網域、註冊外部帳號或執行公開發布動作，底層架構應立刻掛起當前行程，把控制權交還給人類確認。

這三個開關聽起來毫無新意，但對一個能不知疲倦連續執行好幾小時的自動化 Agent 來說，這種底層硬限制比在提示詞裡寫一萬句「注意網路安全」都要管用。

## 對 Coding Agent 的同構風險

現在大火的 Coding Agent 也是同樣道理：它會讀你的程式碼倉庫、在你的終端跑指令、翻找環境變數裡的憑證、呼叫各種雲端服務。如果它的預設上下文裡混入了生產環境的金鑰，或網路出口根本沒做分級隔離，那麼你隨口一句「幫我部署個測試環境」，最後很可能演變成一場刪庫跑路的災難。

## 總結

這次披露的核心價值不在於證明 AI 已經失控，而是扒開了一個非常樸素卻極其致命的工程隱患：**Agent 的強大能力，已經開始把過去那些看似不起眼的傳統設定錯誤無限放大**。

過去一個閘道設錯，頂多一台虛擬機不小心出了網，風險還算可控；現在它意味著這台出網的機器上坐著一個會不知疲倦主動找漏洞、不斷試錯、甚至自己拼裝駭客工具的自動化執行者。

未來的 Agent 平台若想讓大家敢放心用，安全邊界就必須實打實落在網路架構、身分認證、工具管控與執行預算上：

- 公網一關，Agent 在實體上就絕對連不出去
- 目標不在白名單裡，Agent 在 DNS 層面就絕對解析不到
- 預算一耗盡，任務行程立刻被殺掉

**永遠不要把系統邊界寫在 Prompt 裡，要把它變成底層不可逾越的系統事實。**
