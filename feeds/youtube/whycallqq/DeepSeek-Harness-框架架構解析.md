8 月 13 日凌晨 DeepSeek 先發了 V4 Pro 正式版，半天之後又悄悄在 GitHub 開源了一個儲存庫：一天內 star 衝到 6.9 萬、fork 超過 5,800。這個儲存庫裡沒有模型權重、沒有推論引擎，它叫 **DeepSeek Harness**，一個 agent 框架，MIT 授權可自由商用。很多人掃一眼就走，覺得又是一個 agent 工具。

## Harness 是什麼

DeepSeek 在徵才啟事裡給過一個公式：**Model + Harness = Agent**。官方對 Harness 的通俗定義是「把模型變成 agent 的那一層」——模型只負責想，Harness 負責把想法落地：調度上下文、呼叫工具、管理任務狀態、處理回饋、守住權限邊界。沒有這一層，模型再強也只能聊天。

## 基本事實

- 儲存庫 8 月 13 日公開，TypeScript 寫的 monorepo，裡面有 `cli` 和 `web` 兩個應用，底下數十個套件。
- 命令列叫 `dsh`。裝好 Node.js 後敲一行 `npx` 命令，瀏覽器開 `127.0.0.1:3080` 就能用。
- 想從原始碼跑也行：clone 下來 `pnpm install` 加 build，前後端都在同一個儲存庫裡。
- 自帶 Web 介面，長得跟 DeepSeek 網頁版幾乎一樣，填上 API key 就能幹活；模型適配器本身可換，要跑別的模型也行。
- 官方把醜話說在前面：這是**開發者預覽版**，正在快速迭代，會有破壞相容性的改動。翻譯一下就是能玩、能研究，別上正式環境。

## 一切皆外掛

README 第一屏寫著「一切皆外掛」，這是字面意思。官方列的清單是：模型、工具、技能、工作階段、沙箱、儲存、循環、調度、UI——所有 agent 能力都是外掛組合出來的。模型適配器是外掛、工作階段日誌是外掛，連 agent 循環本身都是外掛。

整個系統**沒有特權核心**：想改任何地方不用動原始碼，在自己的設定裡掛個新外掛上去就行。外掛卸載時它註冊的所有東西自動撤掉，不留垃圾。底層的外掛框架叫 **Cordis**，還配了一篇講「時空可組合性」程式設計範式的論文。

組裝方式是分層的，像蓋樓：

| 層 | 作用 |
|---|---|
| bundle | 官方打包好的能力層。`base` 管模型／工具／沙箱／權限／憑證，`web` 管瀏覽器介面，`headless` 管無伺服器的單次執行 |
| profile | 自己命名的組合方案 |
| patch | 針對任何一行設定做整體替換 |

啟動時敲一句 `dsh dump config`，機器上實際跑的那棵外掛樹會完整印出來，每一行都能換。好處很實際：官方升級了，你的改動不會被沖掉。

## 關鍵差異：agent 循環也是外掛

大多數框架的外掛只到工具層——你能加工具，改不動主流程。Harness 把 agent 循環本身也做成了外掛。

它把「一次模型請求加上它呼叫的工具」叫做一個 **step**，一個 **turn** 由零個或多個 step 組成。循環怎麼跑、每一步給模型看什麼、工具執行前後插什麼邏輯，全是事件 hook：

- `agent pre-step`：能在模型請求發出前改寫、甚至拒絕訊息。
- 工具呼叫前後各有 pre 與 post 兩個 hook，校驗、日誌、限流都能插在這裡。

想做一個完全不同的 agent 行為，不用等官方發版，寫個外掛掛上去就是你的 agent。

社群對這種全外掛化設計有兩派聲音：一派覺得是工程藝術品，每一層都能換；一派覺得是過度設計，普通使用者用不到這層彈性，學習曲線還陡。具體場景舉例：要給團隊所有工作階段統一加一個程式碼規範檢查，在寫死的框架裡可能得 fork 原始碼去改；在這裡寫一個外掛掛進 profile，全團隊生效。

## 工作階段日誌：事件溯源

每次執行，模型看到的一切都會寫進一條**只追加的事件日誌**。思路是事件溯源（event sourcing），跟資料庫的 WAL、跟 git 的提交歷史是同一類東西。恢復、分叉、檢索、回放共享同一份事件流。

它還有一條硬規則：**模型能看到的東西，必須能從日誌裡重建出來**。

Web 介面有個 Trajectory 視圖，可按來源看每一次工具呼叫、每一個子 agent 的調度。除錯 agent 最難的就是搞清楚它當時看到了什麼，這個日誌直接把答案給你。另外還帶一個 Python SDK，能把同樣的 agent 組合從自己的程式裡叫起來，方便接進自動化流程。

### 崩潰復原：只修復、不竄改

日誌設計裡最能體現工程品味的是行程崩掉的場景。一般做法是截斷，把沒寫完的部分扔掉；Harness 不這麼幹——它給沒寫完的 turn 補一個**合成的結束標記**，reason 寫上 `interrupted`，前面寫過的事件一個不動。

這就是 WAL 重放的思路：只做修復，不做竄改。文件把這個決策的理由寫得很清楚：長任務的一次 turn 可能有數十步，裡面有大量已經持久化的有效步驟，丟不起。這種克制在 agent 框架裡很少見。

## 四種執行模式

| 模式 | 內容 |
|---|---|
| 標準 | 完整工具集，日常用 |
| PTC（程式化工具呼叫） | 模型寫一段程式碼來組合多個工具呼叫，少跑很多來回，也省 token。與 Anthropic 先前提的「程式碼化工具呼叫」是同一個方向 |
| 極簡 | 只留 shell 與檔案編輯兩個工具，官方拿它跑基準測試，測模型的裸能力 |
| 創造 | 檢查當前的執行期，在記憶體裡組合出新的模式 |

四種模式本質上就是四套預設的外掛組合，理論上自己也能配出第五種、第六種——這才是這套架構的用意。

## Agent 預設（preset）

開工作階段之前要先選一個 agent 預設：一個預設就是一個目錄，裡面一份 YAML，定義這個 agent 掛哪些工具、用哪段提示詞。

- 預設掛載一次，所有選它的工作階段共享同一份註冊，狀態按工作階段隔離。
- 子 agent 自動繼承父 agent 的預設。
- 官方自帶四類預設，從日常到極簡都有現成起點；也可以複製一份官方預設改成自己的版本。
- 有個很細的產品規則：**只有還沒產出的空工作階段才能換預設**——因為換了工具集，舊歷史裡的工具呼叫新組合接不上。

## 創造模式背後：自我進化

創造模式更激進的思路是：模型可以在不打斷任務的情況下，自己寫一個外掛、自己裝上、立刻生效。Agent 幹著活，發現自己缺個能力，現場給自己造一個。

再往前想一步——如果模型能自己寫外掛，那從海量 agent 實例裡篩出改得好的外掛、再融回主線，這條路就通了。這正是 Anthropic 那篇自我改進部落格之後大家都在聊的「自進化」，而 DeepSeek 這套做法是目前把這條路講得最具體的一個。

社群目前的共識是：對普通使用者這功能暫時用處不大，它吃生態，得等大量高品質外掛沉澱下來才有差異；但對極客來說，這是給後人種樹的機會。

## 開發過程本身也開源

很多報導沒提的細節：儲存庫裡有個 `.agents/notes` 目錄，按日期歸檔了開發筆記——架構決策、bug 修復、功能實作全攤在那，最早一篇是 6 月 11 日。`docs` 目錄下還公開了四篇事故復盤。

從中能看出這個專案有多少是 agent 參與開發的、每次決策的理由是什麼。筆記裡的決策非常具體，例如工作階段落盤為什麼做成批次刷盤、為什麼給寫盤視窗設上限，完整推理過程都在。對想學 agent 工程實踐的人，這比程式碼還稀缺。順帶一提，從筆記日期看這個專案至少悶頭開發了兩個月。

## 實測表現

媒體拿到內測後做了兩個測試：用 V4 Flash 配 Harness，一次提示、沒有人工介入，三十多分鐘做出一個第一人稱殭屍射擊遊戲，不算完美但能玩；另一個是讓 Harness 把一段經典影片橋段重現成 3D 動畫，也是一次提示出片。

這類展示看看就好，別當成權威基準，但能一次跑出可執行的遊戲原型，說明工具鏈與循環的穩定性是過關的。真正拉開差距的還是長任務裡的上下文管理。

## 定位：要的是模型之上那一層生態

很多人覺得 DeepSeek 發這個是要做「中國的 Claude Code」，搶終端使用者的程式設計入口。Harness 對標的確實是 Codex 與 Claude 這類產品，但這個判斷可能小了——DeepSeek 真正想要的是**模型之上的那一層生態**。

模型的差距在縮小是行業共識。當模型能力趨同，開發者沉澱在誰的框架裡，誰就有護城河，而外掛生態就是護城河的載體：誰的標準被更多人接受，誰就能把整個社群的生產力變成自己的資產。

時間點也很講究：V4 正式版凌晨發，Harness 開發者預覽版同天跟上，團隊此前一直在社群網路預熱和招人，絕非臨時起意。另有媒體報導 8 月 17 日 DeepSeek 的 API 要漲價、快取漲得尤其多。組合起來看：框架免費開源、MIT 可自由商用，但跑起來要燒模型的 token——Harness 帶量，API 收錢。這個商業模式跟雲廠商當年開源 Kubernetes 是同一個邏輯：控制面送給你，在資源上賺回來。

官網還專門掛了資料處理政策與使用政策兩個頁面，明顯預判了社群會問什麼。

## 冷水：目前的限制

1. **是預覽版**，官方明說會有破壞性變更，想上正式環境的先死心。
2. **Web UI 沒有認證**（社群的容器封裝專案專門提醒過），別暴露到區域網路或公網。
3. **貢獻指南寫明暫不接受外部 PR**，想參與只能走外掛生態與 Discussions。
4. **創造模式讓模型自己裝外掛，安全邊界社群還在吵**——模型自己寫的程式碼直接進執行期，權限策略怎麼配值得認真對待。

這些不算勸退，是讓你帶著正確的預期去用。使用前建議先讀一遍官方的資料處理政策與使用政策頁面。

## 評估任何 agent 框架的三問

1. **可替換性**：每一層能不能換？換的時候要不要改原始碼？
2. **可觀測性**：出事的時候，能不能精確回放它看到了什麼、做了什麼？
3. **可組合性**：能力能不能像積木一樣拆下來重組，沉澱成你自己的資產？

拿這三問去套 Claude Code、套 Codex、套任何新出的框架，比追每一個新發布的工具省力得多。

## 走向

外掛生態會先熱鬧起來——發布才一天，社群已經有 Docker 封裝、桌面端、終端 UI，甚至有人做了桌寵外掛；官方給外掛儲存庫留好了檢索入口，加個 `dsh-plugin` topic 就能被發現。接下來是模型廠商的跟進，Harness 這一層會成為新的兵家必爭之地，越來越像基礎設施——就像當年的編輯器之爭、容器編排之爭，贏的未必是功能最多的，而是生態最厚的。

一句話總結：模型是引擎，Harness 是整輛車。以前大家比引擎參數，往後要比整輛車的工程。
