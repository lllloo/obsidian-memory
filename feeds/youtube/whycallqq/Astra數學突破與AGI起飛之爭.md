## 爭論的兩造

8 月 1 日，OpenAI 公布內部模型 Astra 的十項數學與理論計算機科學成果，其中一部分解決了長期開放問題，另一部分是實質性進展，包括三個 Erdős 問題，還有高維漸近球堆積上界的新結果。每項結果都附了 Lean 4 的機器可檢驗證明，直接掛在 GitHub 上。找到這些結果消耗的 token 按 API 價格折算約兩千美元。數學圈老牌部落客 Thomas Bloom 只評價了三個字：大新聞。

當天，AI 評論者 Andrew Curran 發文說懷疑論者該認清現實了、「我們正在起飛」，論據是三連擊：推論效率提升帶動降價、模型發布節奏加快、AI 又公布十項數學成果。

第二天，一篇六萬瀏覽的長文頂了回去，標題是〈我們還沒有獲准起飛，暫時還沒有〉。作者 Ian Butler 是 XBOW 的 AI 研究員（XBOW 去年第二季登上過 HackerOne 全球排行榜第一，創始團隊裡有 GitHub Copilot 的建立者）。

兩邊都是圈內人，兩邊都拿數據說話。影片的結論是：**兩個人都在說實話，因為他們回答的是兩道不同的題。**

- **Curran 回答的是**：前沿能力還在不在漲？在漲，而且漲得猛，價格還在跳水。
- **Butler 回答的是**：這套學習範式能不能泛化到所有地方？目前不能，而且堵點很清楚——差信用分配、差長期強化學習的穩定性、差災難性遺忘。他還搬出 Karpathy 的判斷：AGI 大約還有十年。

## 數學突破的分量是真的

去年 OpenAI 鬧過風波：有研究員把 GPT-5 找到既有文獻說成了破解 Erdős 開放問題，結果被資料庫維護者 Thomas Bloom 當場糾正——那只是文獻檢索，翻出已有成果而已。

但這次不一樣，每項結果都附了 Lean 4 證書，機器可以逐行檢驗形式化推導。（形式化命題是否準確對應原來的猜想，還得靠數學家獨立審閱。）成果清單裡有硬貨，比如首個非 sofic 群的顯式構造；今年五月他們還用內部模型推翻了 Erdős 單位距離猜想，八十年的懸案，Gowers 的評價是「如果投到數學年刊，我會建議接收」。

關鍵在於 Butler 並沒有否認這些。他承認積木已經造出來了，現有工具可能是通向遞迴自我改進的零件；他爭的是另一件事：**這些零件自己拼不成那架飛機。**AGI 裡那個 G（通用性）還缺貨。他的邏輯鏈是：數學和程式碼的突破，證明的是可驗證領域裡的能力，而智慧的真考驗在可驗證領域之外——那裡沒有裁判、沒有編譯器、沒有證明器。

## Butler 的三發彈藥

### 一、倖存者偏差

數學和程式碼是最容易自動驗證的兩個領域，答案對錯有裁判（編譯器、單元測試、形式化證明器），突破自然堆在這裡；其他領域沒有判卷老師，進步了也沒人敲鑼，自然上不了頭條。你盯著頭條看，就覺得全世界都在起飛。

這套說法有文獻撐著，但學界還沒吵完：

- NeurIPS 2025 有篇 Yue 等人的研究，發現當時的 RLVR 主要提升取樣效率——pass@1 漲了，可讓模型多試幾次，大 k 的 pass@k 反而低於基礎模型，分布的尖被削得更尖、底盤反而變窄
- 同屆的 ProRL 得出相反結論：延長訓練能找到基礎模型取樣不到的新策略

兩篇論文打架，說明這警惕有據，但還不是定論。

### 二、驗證器太脆與信用分配

規則驗證器只在數學和程式碼裡造得出來，自由文本領域造不出規則，只能讓 LLM 當裁判，而 AI 裁判會引入獎勵雜訊；真實世界和人際互動壓根沒有好的驗證器。

更關鍵的是主流方案的獎勵發得特別粗。以 GRPO 為例，整條 rollout 跑完只拿一個二值的終局獎勵，平均攤到每一個 token 上——一個算術小錯和完全胡說八道，拿的是同一個零分。過程獎勵和模型獎勵的路線也有，只是都不成熟。這就是**信用分配問題**：模型分不清功勞和鍋該記在哪一步。

再加上災難性遺忘、長期強化學習又穩不住，三件事疊在一起，Butler 的判斷是：不解決這些，能力就泛化不到數學、大部分科學和程式碼之外。

### 三、SCBench：14.8% 的嚴格通過率

前兩點偏理論，第三點直接見血。威斯康辛大學麥迪遜分校的基準 SlopCodeBench（簡稱 SCBench）：36 道題、196 個 checkpoint，模擬真實的長期專案——Agent 要在自己之前寫的程式碼上，跟著不斷演進的需求一輪輪迭代。嚴格通過的標準是新功能測試要過、歷史上所有回歸測試也都要過。

GPT-5.5 時代的成績：

- 嚴格口徑通過率只有 **14.8%**
- 寬鬆的 isolated 口徑也只有 28.1%

換成大白話：一百個檢查點，不到十五個能乾淨通過，而這已經是當時最強的編程模型。

更瘆人的是**腐化模式**：

- 77% 的軌跡裡，程式碼結構在持續變差
- Agent 寫的程式碼冗餘度是 473 個開源 Python 儲存庫平均水準的 2.3 倍
- 劣化速度是人類專案的五到七倍
- 典型案例：Opus 4.7 做某道題，main 函式從 38 行一路膨脹到 240 行

這不是能力不夠，這是**退化**。基準觀察到的是結構侵蝕和冗餘不斷累積；具體的退化機制論文本身還沒有證明。Butler 的推斷是：模型沒法把過去的決策和當前的決策穩定關聯，每改一次都在背叛上一次的自己。人類專案也會腐化，但腐化速度快好幾倍，性質就變了。

有人會說那是舊模型。HumanLayer 創始人、《12-Factor Agents》作者 Dex Horthy 拿基準的一個小切片複測了新一輪模型（GPT-5.6、Fable 5、K3），checkpoint 通過率大概翻倍，**但沒有任何一次執行能完整乾淨地解出哪怕一道題**。他的完整測試報告還沒發布，Butler 也提醒這些只是個別樣本，但趨勢看得很清楚：分數在漲，乾淨完賽的能力還沒跟上。

## 框架：畫你自己的參差邊界地圖

Karpathy 在播客裡有個說法：RL 像在用吸管吸監督信號。大實驗室的後訓練主力都是 RLVR，它的上限在哪，學界還在打架。Butler 自己的判斷是：替代的學習範式出現突破之前，模型在特定領域之外可能已經蹲在局部最優裡。（這是他的判斷，不全是論文的結論。）

「鋸齒狀智慧」是 Karpathy 2024 年造的詞，Mollick 管它叫「參差邊界」。BCG 做過一個 758 名顧問的實驗：邊界之內的任務，用 AI 的人快 25%、品質更高；邊界之外一個特意挑選的複雜任務上，AI 組的正確率反而低了 19 個百分點。麻煩的是輸出看起來照樣完整流暢，你很難意識到已經越界了。

**框架一句話：別問 AGI 哪天來，去畫你自己的參差邊界地圖。**模型能力是一條參差不齊的邊界線，邊界內它強得嚇人，邊界外它錯得自信。你的工程水準和職業安全，都取決於手裡那張地圖畫得準不準。占卜起飛日期是媒體的工作，校準邊界地圖是工程師的工作。

## 八條可落地做法

### 前四條管流程：把信任拆成可驗證的小塊

1. **長任務別用一個對話硬扛。**Anthropic 公開過雙 Agent 方案：一個 initializer Agent 先把需求展開成 feature list 的 JSON 檔案和初始化腳本；編碼 Agent 每次對話只做增量——開工先跑測試，一次只做一兩個特性，更新進度檔案，git 提交，收工。配套的護欄叫**測試棘輪**：提示詞裡寫死「刪除或修改測試來讓它通過是不可接受的行為」。
2. **開工前把完成條件寫成外部可測的檔案。**這是防 Agent 中途偷偷重新定義「完成」。上下文不夠用時做全量重置，用結構化交接檔案重建狀態，像給新工程師做 onboarding。
3. **生成和評估必須分開。**模型給自己的作業打分永遠偏寬鬆，Anthropic 的工程部落格和 Addy Osmani 的總結都實測過這點。評估器要和生成器隔離，高風險的地方加一道人工 review gate。
4. **eval 做成二值的 pass 或 fail**，每個 eval 只查一種失敗模式，能用確定性檢查就別用 LLM judge，而且要在真實生產流量上持續跑。線上出的每個 failure 回灌成回歸測試。

### 後四條管分寸

5. **人在迴圈按風險分級。**不可逆的動作強制人工批准，策略寫成 policy as code，在 LLM 之外強制執行——別讓模型自己判斷自己能不能動手。
6. **學會用 METR 的任務時程思路切任務。**時程衡量的不是 AI 能連續跑多久，它是用人類專家完成任務的時間來標定任務難度，再看模型在這個難度上的成功率。METR 目前只報告 50% 和 80% 兩檔，99% 那檔資料不夠估不出來。實用含義是：任務越大越難，成功率掉得越快；把大任務切到目標可靠度對應的顆粒度，成功率立刻不一樣。
7. **專門對付腐化。**SCBench 論文的數據很扎心：提示詞干預只能改善初始品質，擋不住後續退化。所以要定期人工審查和重構，尤其是**第一個 checkpoint 的架構評審投入產出比最高**——第一塊磚歪了，後面全是斜的。
8. **在你自己的真實任務上系統地試。**記錄模型在哪靠譜、在哪翻車，畫出自己的參差邊界地圖，每換一次模型就更新一次。

這八條都在回答同一個問題：怎麼和一個很強但不穩的隊友長期共事。

## 三個往後看的判斷

**一、起飛派手裡最強的牌是 METR 的任務時程曲線。**按新版 TH1.1 的口徑，前沿模型的 50% 任務時程在 2019 到 2025 年間大約每 196 天翻倍，2023 年以後的估計加速到 131 天左右。但這個指標衡量的是模型在一組軟體、機器學習和網路安全任務上的成功機率，不等於 AI 能連續自主工作多少小時；METR 自己也說 99% 可靠度估不準，超過十六小時的點估計也要謹慎。所以這條曲線說明能力在猛漲，但還推不出「無人監督的長期工作」已經被解決。

**二、記憶和持續學習會是下一個主戰場。**現在主流做法是繞開參數更新，用提示檔案、檢索和外部記憶保存經驗——`CLAUDE.md` 和 `SKILL.md` 就屬於這類外部記憶，是上下文工程，不算真正的持續學習。真正的持續參數學習還是研究問題，災難性遺忘只是障礙之一，安全驗證、回滾、隱私也都是麻煩。這也印證了 Butler 說的遞迴自我改進受限：誰能解決穩定的長期學習，誰才真正拿到起飛許可。

**三、工程範式會繼續往 Harness 方向走。**雙 Agent、測試棘輪、policy as code 會在一兩年內從小眾技巧變成標配。Karpathy 說的是 decade of agents——工程師的活不會消失，會變成設計 Harness 的活。

## 結語

數學成果是真的震撼：十項結果、機器可檢驗的證明、折算兩千美元的 token 成本。Butler 的冷水也真的有依據：14.8% 的嚴格通過率、五到七倍的腐化速度、信用分配的死結，每一條都指著同一句話——通用性還沒到貨。

兩邊都對，因為他們回答的是兩個問題。而對工程師來說，真正要緊的從來是第三個問題：在參差智慧的時代，怎麼造出可靠的系統、怎麼安排自己的手藝。影片的建議濃縮成一句：**少看占卜，多畫地圖。**模型每換一代，你的邊界地圖就該更新一次；可靠的任務放大，不可靠的上 Harness。
