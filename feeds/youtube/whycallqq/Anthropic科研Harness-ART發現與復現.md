## 事件與講者切入點

- 9 月 23 日 Anthropic 宣布成立生命科學團隊與自有分子生物學實驗室，同時發布第一個成果：Claude Agent 在大型 DNA 資料庫中翻找逆轉錄酶（RT），注意到一個長相奇怪的基因旁有一串規則重複的 DNA，布局有點像 CRISPR，命名為 **ART**
- 官方口徑：約 950 個 Agent、21 小時、2.1 億 token
- 講者重點不在發現本身，而是技術報告裡另一組數字：同樣流程、同樣 Harness 完整重跑 10 次，**全部錯過**這個關鍵發現
- 補充對照：把關鍵 DNA 直接放進上下文，最強幾個 Claude 九成以上能看出重複序列；改成給檔案、工具、資料庫讓它自己找，發現率最低掉到 32%。模型會，Agent 卻做不到——這個落差比酶本身值錢

## 精確數字與限制

- 技術報告精確版：949 個 Agent session、119 個任務、2.156 億 token、21.5 小時掛鐘時間
- 76.9 個 Agent 小時，最多 58 個並發
- 所有濕實驗由人類完成
- 論文目前是預印本，未經同儕審查
- 這個系統實際功能未知

## 950 個 Agent 怎麼協作

- 不是 950 個模型開群聊，更像分散式任務系統：
  - 人類只寫一份研究簡報（「找新的逆轉錄酶系統」），拆成任務派給 Worker
  - **Worker** 自己定計畫、寫程式、查資料庫、分析序列、寫結論
  - 每個 Worker 配一個 **Supervisor**，審查計畫與結果，不合格就打回（49 個任務被返工過）
  - Supervisor 發現線索可直接開新任務：119 個任務中有 98 個是這樣長出來的
  - 中間結果寫入共享知識庫，**Editor** 彙總成 19 份報告交給人類
- 任務佇列、Worker、審核、共享儲存——做後端的應該眼熟
- 「949 個 Agent」的真相：21.5 小時內排程了 949 次帶工具、帶程式碼、帶獨立上下文的科研會話
- Anthropic 多智能體文章的數據：BrowseComp 評測中，token 用量一個指標就解釋 80% 的效能差異。多 Agent 的核心價值之一是把 token 預算換成平行的搜尋寬度——不同上下文、不同路徑同時探索更多搜尋空間

## 搜尋漏斗

- 19.4 億個蛋白質簇 → 19.8 萬個逆轉錄酶簇 → 3,564 個候選搭檔家族 → 17 個方向深挖 → 19 份報告（其中一份是 ART）
- 中間還有 339 萬候選序列、1.1 萬個抽樣基因座等步驟
- 17 個深挖方向只有 3 個被確認為新關聯，其餘 14 個全被否決
- 整條漏斗沒有一步靠模型硬背：HMM 搜尋、聚類、資料庫比對全由傳統生物資訊工具執行。**Agent 負責調度與判斷，計算交給程式碼**——寫自己的 Agent 可直接照抄這個分工

## ART 是怎麼被找到的：一條旁支

人類任務書只要求找搭檔基因，一字未提重複序列。過程四步：

1. 普查階段：一個候選 RT 因旁邊躺著噬菌體基因被提名
2. 一個 Worker 深挖後否決這個關聯，但順手記一筆：這個 RT 本身很像 retron，值得再看
3. Supervisor 據此開 follow-up，讓下一個 Worker 檢查這類 RT 的上游區域
4. 新 Worker 發現上游拖著很長的非編碼區（中位數 940 個鹼基），並**主動把這段 DNA 讀進自己的上下文**——沒有任何人要求過

- 報告中 Worker 的日誌大意：「這段序列太壯觀了，肉眼就能看到串聯重複陣列，片段重複多次、間隔 100–180 個鹼基，該不會是類 CRISPR 結構吧」
- 接著做了人類科學家的全套動作：數重複次數（14 個拷貝）、量間距、寫腳本掃一遍、對比所有已知 RT 系統、查文獻確認無人報導；過程中自我懷疑（會不會是去年的 DRT9、會不會是 retron 已知變體），逐一排除才提交
- 沒用 AlphaFold、沒用專門訓練的 DNA 模型：一個通用語言模型盯著 ATCG 看出了異常

## 十次重跑全部錯過

- 同 Harness、同任務書重跑 10 次：幾乎每次都採樣到 ART 相關基因座，兩次甚至追到正確家族，但**沒有任何一次有 Agent 去讀 RT 上游那段 DNA**
- 十次都正常跑完、各有產出，只是沒再走通那條支線
- 官方歸因：搜尋空間太大、Harness 行為不確定，第一次成功是高度路徑依賴的結果——少開一個 follow-up、少讀一個檔案，整條路徑就不存在

## 對照實驗：模型會，但沒看到

- 7 個 Claude 模型 × 5 種資訊條件 × 各 100 次，共 3,500 次嘗試
- 前兩檔：序列直接塞進上下文、不給工具 → 最強的四個模型九成以上能指出重複陣列
- 後三檔：序列放進檔案系統，配 HMMER、BLAST、Python 等工具讓它自己找 → 識別率一路下降，最低組合僅 32%
- 原因：39% 的嘗試從頭到尾沒有連續讀過 200 個鹼基，連一個完整重複單元都沒看全；凡連續讀過 200 個鹼基以上的嘗試，識別率高出 16–32 個百分點。模型沒變笨，只是沒看到
- 呼應 Anthropic 6 月另一篇文章：讓 Agent 去 NCBI 拉病毒序列，同一問題問三遍，Sonnet 4 給出 106、15、5 條，正確答案是 266 條；加上確定性檢索層後所有模型正確率都在 90% 以上、最高 99.7%，差距也被抹平
- 兩個實驗指向同一結論：**瓶頸出現在推理開始之前**，能否穩定拿到正確上下文才是分水嶺。模型決定潛在能力，Harness 決定能兌現多少

## 標題 vs 論文實際主張

- 2021 年已有論文描述過這個區域：噬菌體 MarsHill 的 gp206 基因當時就被認定為類 retron 逆轉錄酶，上游 1,241 個鹼基的非編碼區也有記錄，論文還猜測有非編碼 RNA
- 「Claude 發現新酶」是新聞標題；「Claude 發現一個此前未被系統描述的分子系統」更接近論文主張。Anthropic 也承認底層 RT 早被發現，新東西是三件套組合：重複陣列 + RT + 搭檔蛋白
- 目前唯一確認的：重複序列會被表達成短 RNA，感染 15 分鐘時最高占噬菌體 RNA 的 8%
- 能否編輯基因沒有任何證據，稱它為下一個 CRISPR 是標題黨

## 對 Coding Agent 的對照

| ART 實驗中的失誤 | Coding Agent 對應 |
|---|---|
| 沒讀上游 DNA | 沒打開真正相關的原始碼 |
| 搜尋方向跑偏 | grep／語意搜尋找錯檔案 |
| follow-up 沒生成 | 沒繼續追呼叫鏈 |
| 資料庫存取不穩 | MCP 與 API 回傳不完整 |
| 重跑結果不同 | 同一 issue 多跑幾次結果就變 |
| 確定性檢索層把成功率拉到九成 | 用 AST、LSP、測試 runner 取代模型純猜 |

- Anthropic 說過：Agent 系統進入生產環境後，最後一哩路往往變成旅程的大頭
- 他們之所以能複盤十次重跑，是因為每個任務的工具呼叫、上下文、決策點都有記錄；只存最終答案的團隊出了問題無從查起

## 三句收尾

- 模型會，不代表 Agent 會
- 模型決定潛在能力，Harness 決定能力能兌現多少
- 很多 Agent 的推理失敗其實發生在推理開始之前——我們可能不缺會思考的模型，缺的是別讓它連檔案都沒打開
