## 一個快捷鍵叫出 Agent

不用開編輯器、不用先啟動終端、不用在 Dock 找圖示：`Super + Shift + Ctrl + A`，一個乾淨的終端視窗彈出來，Agent 已經在裡面等著。這是 DHH（Ruby on Rails 作者、37signals 創辦人）剛發布的 Omarchy 4，一個 Linux 桌面系統。

它把九個 AI 編程 Agent 預先接進系統層，從 Claude Code 到 Codex 到 Grok，隨你挑一個當預設。

發行版預裝幾個 CLI 本不稀奇，但這次的待遇不同：Agent 在 Omarchy 裡有**預設位**、有**專屬快捷鍵**、有**頂欄用量面板**，還能接管系統崩潰的診斷——這些待遇以前只有瀏覽器和輸入法才有。

## 4.0 Quattro 的地基工程

Omarchy 是 DHH 基於 Arch Linux 與 Hyprland 做的桌面系統，去年開始走紅。4.0 代號 Quattro（致敬奧迪那台四驅拉力車），是專案史上最大更新：

- 整個桌面外殼用 Quickshell 重寫：狀態列、啟動器、選單、通知、鎖屏原本由七八個獨立程式拼起來，現在收進一個常駐行程，還帶外掛架構；Waybar、Walker、Mako 等老牌元件全部退場
- 內部檔案從 git 倉庫改成標準 Arch 系統包，更新走 pacman，系統檔案從 `/etc` 下發——自己的修改與官方更新可以安全分離，升級不再是賭博
- ISO 瘦身一 GB 多，壓到 6GB 以內，安裝提速三成，最快一分鐘內裝完
- Hyprland 設定全部轉成 Lua；雙系統安裝、出廠重置也跟上（機器要轉手，一鍵回到初始狀態）

地基打完，樓上的 Agent 設計才站得住。

## Agent 的懶載入與預設 Agent

官方手冊列了九個 Agent 的命令表，這些命令其實是藏在 `~/.local/bin` 下的小腳本，由 mise 統一管理。第一次敲 `claude` 它才現場下載安裝；不裝就不佔空間，裝了也能跟著 `omarchy update` 一起升級。想加新的，一條 `omarchy-mise-install` 就能按同樣方式接入。

懶載入這個選擇很聰明：系統不替你預設立場，只把路修到每家 Agent 的門口。

挑好預設 Agent 後，`Super + Shift + Ctrl + A` 一鍵喚起；嫌快捷鍵長，終端敲一個字母 `a` 也行。更直接的是 `omarchy agent prompt` 後面跟一句話，Agent 領任務直接開工、全程自動批准不停下來問——官方手冊甚至專門提醒：做好它真幹活的準備。另有細節：從家目錄啟動時，Agent 會自動進入 `~/Work` 目錄，這樣信任設定才留得住。

這個設計裡真正新的東西是**預設 Agent**這個概念：作業系統以前只有預設瀏覽器、預設終端、預設輸入法，現在多了一個預設 Agent。

## 頂欄用量監控

系統偵測到你在用 AI 編程時，頂欄會長出一個 agents 圖示（不用就隱藏）。點開是一個面板：訂閱檔位、五小時 session 額度用了多少、每週限額剩多少、token 按天按模型列成表。Claude Code、Codex、Fireworks 開箱支援，資料每十五分鐘刷新一次，多台機器的記錄還能透過同步資料夾合併。

把 Agent 用量放在頂欄、和電量網速並排，這個安排很說明問題：多 Agent 時代的第一個工程問題是**可觀測性**，DHH 直接把它做進系統頂欄，Agent 的消耗開始被當成一種系統資源來管理。

影片作者的體感：五小時額度說沒就沒、週限額一到直接停擺；以前這些資料藏得很深，要自己翻後台或等限流了才發現。現在常駐頂欄，開工前看一眼再決定任務交給哪個 Agent。當成本變成即時可見的儀表板，使用方式會變——什麼任務值得燒 token、什麼任務手寫就行，判斷會下意識發生。**監控本身就是一種約束。**

## 崩潰診斷流水線

Omarchy 會盯著 `systemd-coredump`：程式一旦出錯，系統彈出通知，點一下就把崩潰現場連同一份診斷手冊塞給預設 Agent。Agent 負責還原事實、符號化呼叫堆疊，再判斷這個 bug 值不值得回報給上游；確認是 Omarchy 的問題，它會在你同意後幫你報上去，報之前還會先查重避免洗版。也可以手動對任意行程跑一遍，一條命令的事；嫌通知煩可以按程式個別遮蔽——崩潰照崩，提醒閉嘴。

過去崩潰診斷是體力活（翻日誌、查符號表、搜重複 issue），現在系統把整條流水線搭好，Agent 只需要進場幹活。

## 能力、監控、回滾三件事一起給

Agent 在 Omarchy 裡能看病，也能動刀：系統自帶一份 skill，掛進各家 Agent 的技能目錄，教它們調 Hyprland 設定、改狀態列，甚至從零做一個主題。官方建議很誠實：這份 skill 還是實驗性的，先開 plan mode 看清楚它想做什麼，隨時準備回滾；改砸了跑一條 `omarchy reinstall configs`。

把 Agent 請進門、給它鑰匙，又提前寫好驅逐條款——能力、監控、回滾三件事一起給，這才是完整的系統設計。

## 這是一盤入口的棋

過去一年 AI 編程工具都在搶編輯器裡的位置：外掛、側邊欄、行內補全，本質是 Agent 求著宿主給一點空間，而**外掛的入口是租來的，宿主隨時可以收回**。Omarchy 反過來：宿主直接給 Agent 留了座位，九個候選競爭上崗，誰拿到那個快捷鍵，誰就是使用者每天第一個打交道的 Agent。

（有人會覺得這只是 Linux 玩家的玩具，但 Chrome 當年也是從小眾選擇變成所有人的預設。）

## 可帶走的判斷框架

不用 Omarchy 也適用——以後任何號稱 AI 原生的產品，看三個地方：

1. **啟動**：Agent 藏在幾層選單後面，還是一個快捷鍵直達
2. **上下文**：它能看到你的專案目錄和崩潰日誌，還是只能看到你複製貼上的那一段
3. **約束**：誰在盯它的帳單，誰能一鍵讓它停下來

啟動決定你用不用，上下文決定它好不好用，約束決定你敢不敢用。拿這個框架回頭看編輯器外掛：啟動還行、上下文只有你打開的檔案、約束基本沒有，分數不高。三件事都做到，才算把 Agent 接進工作流的骨架。

## 接下來的走向

- 編輯器廠商會跟進預設 Agent 位，VS Code 與 JetBrains 不會坐視系統層搶走入口
- 用量監控會變成標配
- 當 Agent 能改系統、能診斷崩潰，工程師的工作會多出一項新內容：**給 Agent 劃邊界**——哪些目錄能碰、哪些操作要審批、哪些任務可以放手。這門手藝現在幾乎沒人教，但遲早是基本功，說不定過兩年面試會多問一句「你怎麼管理 Agent 的權限」
- 本地模型：Omarchy 裡一鍵就能裝 Ollama 和 LM Studio，不想燒訂閱的場景總會有人跑回本地

作者收尾一句：**Agent 不缺能力，缺的是預設入口**——能力大家都有，入口只有一個快捷鍵。
