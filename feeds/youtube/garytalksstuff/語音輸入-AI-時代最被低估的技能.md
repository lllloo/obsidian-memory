## 為什麼語音輸入是核心技能

作者主張語音輸入不是配角，而是跟 AI 協作時最核心的技能之一，理由有兩個。

**效率**：史丹佛研究指出說話比打字快 3 倍。同樣時間內可以指派給 agent 的任務數量就是打字者的三倍——打字要花 9 小時的工作量，語音輸入 3 小時就做完。

**Context 的豐富度與精準度**（作者認為這點更重要）：打字是有成本的，你會下意識想省力，能少打一個字就少打一個字，結果丟給 AI 的永遠是被大腦壓縮、精簡過的版本。用講的幾乎沒有摩擦力，可以很自然地把背景、脈絡，還有那些打字時偷懶想略過的小細節全都倒出來。而對 AI 來說，**正是這些你以為不重要的細節定義了你的品味**，以及它交出來的成果符不符合你的預期。

## 工具選擇

Apple 內建語音輸入免費、是不錯的起點，但作者用一陣子後發現辨識效果不夠好，尤其在中英文切換上——專有名詞常需要用英文講出來，這方面體驗有待加強。

作者過去半年改用 Typeless，評價是辨識準確度高、使用體驗絲滑，像「一個按鍵就能召喚 AI 語音助手」。同一段語音用 Apple Dictation 轉錄的結果對中英文很不準、常漏字，通常還要修正幾輪才能發出去；Typeless 則會把冗言贅字與不通順的地方修掉，並自動排版。

## 實戰流程：口述打造個人網站

**第一步：brain dump**。開發前作者習慣把所有想法用講的全部倒出來，這時候的想法最雜、最沒條理。如果用打字，就會不自覺邊打邊修、邊打邊篩，很多腦子裡很粗略的想法會在「想把句子打通順」的過程中被遺忘——而這些粗略想法往往最能代表個人品味。說話時你不會陷入審查自己說出來的內容是否合邏輯、是否通順，只需專注把想法講出來。

轉錄工具會直接把混亂的語言轉成清楚、有邏輯、排版好的文字，跳過精修文字與排版這個繁瑣過程。

**第二步：用 Ask 功能反問自己**。Brain dump 完不會馬上把 prompt 送出去，而是選取剛轉錄的文字、按 `Control + Space` 觸發 Ask 功能，然後說：「這是要給 coding agent 的提示詞，希望補充更多我沒思考到的細節，請審視我的提示詞，在你覺得需要我補充資訊的地方用括號標起來。」

它會用括號標示哪些地方可以增加哪些資訊。這個功能引導你做更深入的思考，也訓練你把意圖表達清楚——作者強調這正是跟 AI 協作最重要的能力：告訴 AI 你到底想要什麼。作者習慣這樣來回調整提示詞。

同一個 Ask 功能也用在回客戶 email：口述完之後請它遵照自己的語氣與本意，轉成一封專業的郵件。

**第三步：不切換視窗地問問題**。開發過程中遇到看不懂的名詞，以前要切出去開 GPT 打字搜尋，看完再切回來，心流就斷了。現在直接 `Control + Space` 問「這是什麼意思？可以用白話文解釋嗎？」。作者引用研究指出，人工作被打斷後恢復專注需要 23 分鐘。

**第四步：把 review 的口述變成修改指令**。Review AI 產出時（自己看螢幕 brain dump，或跟同事、老闆討論），這個過程產生的其實是最珍貴的 context，但大部分人討論完就忘了，頂多記兩句重點，還要花時間重新回想再轉成提示詞。

作者的做法是先把想法錄下來，例如「右邊圖片臉的部分太暗了，漸層蒙版不要調那麼深但要保持高質感；主標不夠直覺，要讓使用者從那一句話就理解我們能帶給他什麼；右邊句號的綠色 animation 不知道用意是什麼，希望每個設計都有考量要帶給觀眾什麼感受與目的」，接著按 `Control + Space` 啟動 Ask 說「我想要你把這一段變成一個給 coding agent 的清楚指令」，直接轉好，不用再花時間思考怎麼把想法寫成 prompt。

同樣方法可套用在很多情境：把一場跟客戶的會議變成給 Codex 的提示詞，或把一堆混亂想法變成完整提案。

## 手機版：走路抓靈感

作者提到做產品這麼多年，最好的想法幾乎沒有一個是坐在電腦前想出來的，都是在走路、洗澡時冒出來的，而這種靈感保鮮期超短——想說回電腦前再弄，一分鐘後就跟那個 idea 天人永隔。

現在 Codex 手機版或 Claude Code 的 remote control 結合語音輸入手機版可以解決：邊遛狗散步邊對著手機講話，想到什麼就講什麼。作者說自己現在有一半工作時間都在走路，並在影片中示範邊走邊口述網站調整需求（把左邊文字往上拉、底部預留空間放 YouTube 訂閱數、Patreon 訂閱數與輔導企業數的跳動動畫）。

## 效益估算與適用性

粗算：每天平均打一萬字要花兩小時，用講的只需三十分鐘，一天省一個半小時，一週省下將近一個工作天。

作者也承認有些人就是喜歡安靜打字幫助思考，這只是個人使用習慣的分享，每個人都有自己的工作方式。

## 資安疑慮的回應

社群上對 Typeless 的爭議主要是有人發現它會參考當下螢幕上的資訊來輔助轉錄跟回答，看起來超出語音輸入軟體應有的權限。作者的理解是它讀取螢幕上下文是為了搞懂你現在在做什麼，才能把字修得更貼近意圖，這也是它跟其他語音輸入拉開差距的原因之一。官網有完整的資安說明與已申請到的資安認證，工作對資安要求嚴格的人可以先確認是否符合需求。

## 更高一層的視角：context 轉換遊戲

作者認為知識工作者做的事，說穿了就是 **context 的搬運者與轉化者**。產品經理把一場 meeting 變成一個軟體上線，你把腦袋裡一團模糊的想法變成一份遞給老闆的簡報——本質上都是同一件事：把一種形式的 context 轉換成另一種形式。一段跟朋友的閒聊可以變成一份旅行計畫，一個洗澡時冒出的念頭可以變成下一個創業的起點。

他強調影片真正的重點不是語音輸入、不是 AI coding、也不是特定工具，而是這個視角本身。AI 讓 context 之間的轉換變得前所未有地容易，而留給人的是一路累積的失敗與成功、獨一無二的價值觀與信念，以及選擇做什麼、不做什麼的判斷力。
