## 懸停式導航搭配 Fork

在很長的 Codex 對話中，把滑鼠移到對話區左側空白處的橫線上，會浮出小視窗預覽附近幾輪對話內容（你說了什麼、Codex 怎麼回應），點一下即可跳回該段，不必往上滑動或憑記憶尋找。

真正的價值在於搭配 Fork。每則回覆下方都有分叉按鈕，可從該時間點複製出一條保留前面全部上下文的對話，之後兩條 session 各走各的方向。

典型情境：專案來回二十幾輪後畫面跑掉，想找出是哪一輪改壞卻不想重看整段歷史。做法是先用懸停式導航定位 context 髒掉的節點，從那裡 Fork 出新 session，等於保有原版與一個可重試的平行宇宙。

## 側邊對話與引導：兩種插手方式

兩者都是在主任務執行中介入，但性質完全不同。

**側邊對話（side chat）**：點右上角的切換側邊面板按鈕，在旁邊另開一條對話問補充問題，不打斷主線。等同 CLI 介面的 `/side` 與 `/by the way` 兩個 slash command，本質相同，只是介面與觸發方式不同。

注意事項：若主任務跑很久、有重新連線，或曾關掉 App，側邊對話可能消失。因此適合拿來問問題，但若真的做出重要結論或決定改方向，仍要貼回主線。

**引導（steering）**：主線還在跑時，直接在對話框補一則 follow-up message。桌機介面下按 Enter 比較像排隊，等這一輪結束才成為下一輪；用 `Command + Enter` 送出才算真正以引導方式介入正在跑的任務，在它浪費更多時間與 token 之前糾正方向。

**分流原則**：只是想理解、不想污染主線上下文的小問題 → 側邊對話；真的要改方向 → 引導。新手最常犯的錯是把所有想法都丟回主線，想到一件加一句，最後 Codex 收到一堆互相打架的要求，任務開始變形。

## Record & Replay：把操作錄成 Skill

解決的痛點是「我想讓 Codex 學會我的日常工作流程，但我不會寫乾淨的 prompt，也不會自己做 Skill」。

邏輯很直覺：錄製你的螢幕操作 → Codex 分析 → 整理成專屬 Skill。日後觸發關鍵詞，它就照這份流程模仿你的步驟完成一系列工作。官方定位的適用場景是重複性高、依賴個人習慣，而且「直接示範比文字描述更容易」的流程。

**安裝與觸發**：左上角外掛程式 → 搜尋 Record & Replay → 點選 Plugin。三種觸發方式：slash 指令、`@` 提及，或直接在聊天框說「錄製我的操作並學習記錄變成可復用的 Skill」。最長可錄 30 分鐘，期間游標位置與鍵盤動作都會被記錄。結束時按停止鍵或在聊天框輸入「完成錄製」。

**錄完不要急著相信它學會了**，兩個驗收動作：

1. 打開 Skill 看流程順序抓對沒有。
2. 讓它真的跑一次，確認能不能完成；跑偏就用自然語言調整。

它有機會把流程整理得比你原本更清楚，甚至在重跑時修掉一些不穩定的步驟。

**跨 AI 工具聯動**是另一個有意思的場景。示範前先講清楚整條流程的目的，而不是只讓它看你點了什麼——這樣它在理解螢幕錄製內容與製作 Skill 時比較不會跑偏。影片舉的例子是把 Gemini（多模態分析爆款短片的分鏡、節奏、鏡頭邏輯）、Claude（依分析結果重新發想主題腳本並輸出表格）與雲端 Excel 串成一條 agent 接力流程，錄一次之後下回只要說「用某某 Skill 跑一次」即可。

**限制要講清楚**：Record & Replay 本質依賴 Codex 的 Computer Use，也就是靠螢幕視覺辨識模擬游標與鍵盤。作者實測每一步都需要十幾秒的思考時間，因此不適合即時性任務（打槍戰遊戲、搶演唱會門票），只適合固定、重複、有明確步驟的流程，例如每週固定的整理、固定格式的報告產出、把某工具的輸出轉成固定格式。

作者也補充，跨模型串接其實可以用 CLI、Plugin 等更好的方式做；Record & Replay 的價值在於讓非技術人員也能用最直接的方式教 AI 學流程。

## 手機遠端控制

不是最新功能，但作者最近常用。背景是 2026 年 5 月 Business Insider 報導的現象：許多 AI 開發者出門時把筆電留一條縫不蓋起來，讓 AI agent 繼續在背景執行。

**做法**：透過手機裡的 ChatGPT 直接連線到你的 Codex，可以遠端派任務、看進度、補指令、批准操作、看結果，並支援 File Previews、側邊對話與 Inline Review Comments。

**連線設定**：設定 → 連線 → 開啟「可控制此電腦的裝置」並允許連線 → 右上角新增 → 出現 QR Code → 手機掃描完成連線。

**應用例**：早上出門前讓 Codex 產出一份市場研究報告，通勤路上用手機看檔案預覽，發現第三段太繞就留一則 Inline Review Comment 要它改短、直接講結論，到公司時已經調整好了。

**兩個限制**：

- 真正跑 code、讀檔案、改 repo、執行 terminal 仍發生在你的電腦或 cloud environment 裡，手機只是把指令送過去，不是取代工作環境。
- 手機端打不開電腦上的 `localhost:3000`。`localhost` 指的是「這台設備自己」，手機上的 `localhost` 指向手機自己，而手機並沒有跑那個預覽頁。合理做法是讓 Codex 在 host（你的電腦）上用 in-app browser 或 Browser Use 打開頁面、檢查畫面、截圖回報，你在手機上看結果再給下一步 feedback。

**大前提**：電腦主機要開著、連網，且 Codex 能連上去，否則一切免談。

## 作者觀察

隨著 AI agent 成熟，工作型態會更碎片化。以前是坐在電腦前自己一路把事情做完，現在比較像掌舵：很多 agent 在不同地方跑任務，跑到一半回來問「這裡要選哪個方案」「這個操作可不可以批准」「測試失敗了要不要換做法」。你不一定每一秒都在打字，但會一直需要做判斷——真正花時間的不是親手做事，而是等對方做到一個節點再由你決定下一步。

整輪更新合起來看：懸停式導航讓你精準找到上下文、搭配 Fork 回到過去改寫未來；側邊對話與引導解決任務中途怎麼插手；Record & Replay 解決怎麼把操作習慣教給它；手機遠端把人從電腦前解放。
