## 省 token 省的不只是錢

模型越強，每次對話吃掉的 token 也越多。常見的抱怨是「月費 20 美金的方案完全不夠用，但 200 美金又用不完」。

作者自承其實不太在意 AI 花多少錢，但認真去省 token 之後發現：真正省下來的不只是錢，而是**幫 AI 清出一個更乾淨的工作環境**——少了沒用的雜訊，AI 的注意力更集中，產出品質也明顯更好。

## 每次按下送出，模型收到什麼

很多人以為自己每次只傳了眼前這行短短的字，實際上系統會把大量 context 一起打包塞給 AI，主要有四層：

1. **系統與專案規則**：Claude Code 內建的系統提示詞、你在專案目錄下寫的 `CLAUDE.md` 或 `AGENTS.md`，甚至當前的 Git 狀態與作業系統資訊。
2. **工具的使用說明**：在 Claude Code 或 Cursor 這類環境裡，所有掛載工具的名稱與參數描述——內建的終端機、檔案讀寫、搜尋功能，加上外接的所有 MCP Server。**光是這份工具清單，每次請求就可能先吃掉幾千個 token。**
3. **對話歷史紀錄**：這個視窗裡聊過的每一輪對話、AI 給過的長篇分析、它寫出來的每一段程式碼。
4. **外部檔案與工具執行紀錄**：叫它讀過的幾百行原始碼、PDF、終端機跑指令噴出的一大串 log。

關鍵在於 **AI 的底層 API 本身沒有記憶**，所以每次按下 Enter，系統都必須把這四層完整重新注入。第一輪歷史紀錄是空的、消耗很少，但 AI 每次產生的長篇分析、讀過的檔案、報錯日誌，下一輪都會變成歷史紀錄再塞回輸入。到第十輪、第二十輪，就算你只回一句「幫我改第二行」，模型依然要把前面累積的全部重讀一遍——你打的那句指令可能連整包資料的 1% 都不到，剩下 99% 全是越滾越大的舊 context。這也是為什麼聊到後面不只覺得 AI 變笨、專注度下降，token 也越燒越誇張。

## 兩個沒用的直覺解法

- **把 prompt 寫短一點**：當視窗早就累積幾萬個 token，把眼前的 prompt 從五十字縮成五字，省下的比例微乎其微。
- **換成便宜的小模型**：理解力不足的小模型一旦寫錯程式碼或答非所問，逼你來回重試好幾次，整趟任務累積下來反而燒掉更多額度。

真正該做的是**精準控制這包 context**：只留 AI 執行任務時不可或缺的關鍵資訊，並在對的時間點果斷丟掉已失效的廢棄資訊。

## 第一招：丟掉用不到的

效果最立竿見影。核心概念很簡單——只要是下一次請求根本用不到的內容，就讓它徹底離開對話視窗。

**換任務就開新對話。** 很多人習慣在同一個視窗一路聊到底：剛跟 AI 來回討論改好登入功能，接著順手丟一句「幫我看另一份完全不相干的報表」。這時模型還背著上一段任務的所有程式碼、報錯紀錄與工具輸出，等於每問一句新問題都在為早就結束的舊進度白白燒額度。手頭任務告一段落就果斷開新視窗。

**善用編輯或分支回溯。** 送出後才發現打錯字或指令不夠清楚、模型吐了一大堆沒用的內容時，**千萬不要在底下接著回「不對，我剛剛打錯了，重新來一次」**——那整段錯誤的長篇大論會永遠卡在歷史紀錄裡，之後每一次對話都得跟著送出。更好的做法是直接回頭編輯那句打錯的指令，或用類似 rewind 的功能回到送出錯誤 prompt 之前，把失敗產出徹底抹掉。

**精簡掛載的工具與 MCP Server。** 不管用 Codex 還是 Claude Code，很多新手覺得這個也好用那個也好用，一口氣裝了一大堆 MCP 與 plugin。但每個 MCP 工具背後的說明文件與參數定義，每次送出都會被完整塞進 context。如果當下只是要寫個小功能或改文章，就把用不到的網頁搜尋、資料庫或其他 MCP Server 果斷關掉。

## 第二招：縮減留下來的

有些背景資料接下來一定會用到、不能直接丟，這時要思考的是能不能只萃取真正關鍵的部分，把體積縮到最小。

**先搜尋，再餵給模型。** 很多人處理大專案或長文件時，習慣把上百頁的 PDF 或幾千行程式碼全丟進對話框讓模型自己撈。如果問題本身有明確的關鍵字、函式名稱或錯誤代碼，更好的做法是先用搜尋工具找出最相關的那幾行或那幾段，只把相關內容餵給 AI——光是多做這個動作，每次請求的消耗就能從好幾萬直接降到幾百。

**給結論，把中間的討論過程清掉。** 多輪對話裡可能推翻了兩三個方案才敲定架構，但進入下一步時模型只需要知道最後確認的規格與要遵守的限制，根本不需要知道被淘汰的廢案是怎麼來的。把冗長的討論清掉，只把最終有效的結論整理成一份 Markdown 檔案，在全新對話裡餵給 AI。

關於自動壓縮／摘要／compact 這類功能：有幫助，但**不要當成萬靈丹**。摘要本質上是一種有損壓縮，會保留大方向但也可能漏掉細節。真正重要的規格、限制、決策，最好還是自己主動整理成一份乾淨的 Markdown。

**縮小輸入格式與輸出範圍。** 輸入時能用純文字或程式碼傳遞的資訊，就盡量不要丟一張幾 MB 的肥大截圖。下指令時如果只是要改某個函式或某個小段落，一定要明確要求「只輸出修改後的段落」，不要讓模型太熱心把整篇幾百行從頭重寫。因為**輸出的 token 往往比輸入更貴、更吃額度**——白話說就是「AI 聽你說話比較便宜，你聽 AI 說話比較貴」。

## 第三招：用 prompt caching 打折

不管是 Claude 還是 OpenAI，主流模型背後都有 Prompt Caching 機制：把對話中重複用到的提示詞暫存在伺服器上，讓後續請求更快、成本更低。

影片舉的數字：以 Claude Opus 5 來說，一般輸入一百萬 token 要 5 美金，命中快取後的讀取價格直接打一折，降到 0.5 美金——便宜十倍。做大型專案或寫程式長期累積下來，省下的費用相當可觀。（實際價格請以官方定價頁為準。）

怎麼吃到這個優惠：

- **注意快取壽命。** 影片指出 prompt caching 通常是 1 小時：一小時內持續對話，快取就保持有效；同一個 session 放著超過一小時沒講話就過期。要省 token 的話，盡量不要讓同一個 session 空著超過一小時。
- **避免破壞快取的動作。** 最常見的是在同一個任務裡**中途換模型**——每個模型有自己的快取，一換等於整段對話從頭重算。同理，中途調整模型的思考強度、或中途打開加速模式，前面累積的快取也會全部失效，得重新付全額把資料再寫進去一次。

## 送出前問自己兩個問題

順序是：先把用不到的丟乾淨，留下來的縮到最小，非留不可的再交給快取打折。細節記不住的話，打好字準備按 Enter 前只要問兩個問題：

1. **AI 要回答我現在這句指令，真的非得看前面的上下文跟舊資料不可嗎？** 如果不需要（例如只是要問個不相干的新問題），就果斷開新對話，或善用類似 command by the way 這類功能。
2. **中間這段討論過程，AI 真的需要「全部知道」才能做出好判斷嗎？** 如果不需要，就不要在同一個視窗硬聊，把剛確認好的結論整理成 Markdown，開全新對話丟給它繼續下一步。

## 收尾觀點

Token 燒得多本身不是壞事，真正浪費的是讓早就沒用的 context 在每一輪請求裡白白吃掉額度。把雜訊清乾淨，才能把最珍貴的額度留給真正需要 AI 深度思考的地方。

作者把省 token 視為在清理**AI 時代下的技術債**——也就是那一行又一行寫給 agent 的文字，有些時候一整份文件用一句話就可以解決。省下來的不只是真金白銀，而是 agent 乾淨的 context、更集中的注意力，以及後續更好的產出。

影片另附一個 prompt（放在該集 Patreon 文章）：貼進聊到一半的對話，它會把還有效的決定與還沒解掉的問題整理成一份交接文件，供下一個 session 直接使用。
