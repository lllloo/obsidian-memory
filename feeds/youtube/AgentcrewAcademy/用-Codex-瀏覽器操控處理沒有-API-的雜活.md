## 為什麼從 Claude Code 換成談 Codex

Dustin 原本想拍的是 Claude Code 的 Computer Use，但一直延後，原因是 Claude Code 的 Computer Use 表現不穩定：讓它操控電腦時常兜圈子、點錯地方，或因自身的倫理條款拒絕存取。後來大量使用 Codex 後發現它的 Computer Use 與瀏覽器操作都相當穩定，才決定拍這個主題。

他也提醒這個比較只反映當下：模型廠商競爭激烈，優勢隨時可能反轉。

## Codex 相對 Claude Code 的兩個優勢

**一、生圖能力**
GPT 這一家的生圖模型明顯領先其他家。只下很簡單的指令就能產出有設計感的海報，且圖中的中文字不會變成亂碼（過去的模型常見問題）。Claude 本身不具備生圖功能。

**二、瀏覽器操作與電腦控制**
這是 Dustin 認為最大的優勢。操作瀏覽器對模型而言非常耗 token——模型必須靠頁面結構或截圖來定位要點擊的位置，圖形介面對人類很直覺，對模型卻很複雜；一旦點錯、重來、繞圈，token 消耗會大幅上升。Claude 同樣做得到這些事，但錯誤率高很多；Codex 的操作順暢且更省額度。

## 沒有 API 的雜活：實際 use case

- **Messenger 訊息**：讓它開瀏覽器查看某些人的最新訊息，甚至代為回覆（Messenger 個人版目前沒有 API）。
- **社群平台資料**：查 Reddit 單篇貼文、查 Twitter 與 Threads 內容；也可以不限定單篇，而是針對某個主題做社群監控——對行銷、公關、廣告工作者實用。
- **銀行帳單下載**：為了記帳（bookkeeping），每個月逐一登入銀行、在繁複介面裡找下載位置很煩人。使用者先登入好，再讓它自動操作、找到下載入口、抓回檔案並整理。
- **雲端後台操作**：Dustin 曾不小心讓某個 API 憑證外洩，需要輪換憑證。Google Cloud Console 這類後台很複雜、入口常常改動，非技術人士只能照著 AI 給的步驟一步步點；改成直接下指令請它代為操作。
- **里程票查詢**：有些航空公司的里程票系統設計複雜（他舉 ANA 為例，常查不到又不說明原因，只能重試）。先登入好，再下條件明確的指令，例如「任何 5 天組合的曼谷—東京來回里程票、不要候補、要直飛、商務艙兩位」，它會把所有組合（該次共 86 組）逐一掃過確認。
- **其他**：購物網站比價、下載勞保單來簽名。

### 為什麼不用官方 API 或爬蟲

- 官方 API 價格高昂（Twitter 為例）或申請流程繁複（Meta 後台走進去像新宿車站一樣迷路，還常需提交正式文件）。
- 第三方 API／爬蟲服務要付費，但需求可能只是偶爾爬一次。
- 自架爬蟲更危險：這類社群網站需要登入，硬碰反爬機制最壞會導致帳號被封鎖。

速度並不是這套做法的賣點——它模擬人類操作、一個一個點，不一定快；價值在於同一段時間你可以去做別的事。

## 風險與界線（影片反覆強調）

- **服務條款**：許多社群平台明文禁止自動化機器人操作，這樣做有被封號的風險。
- **隱私與資料分界**：金融資料、隱私資料要不要交給 AI 處理，每個人尺度不同，得自己抓分寸。若處理的是客戶財務資料，要確認有無相關條款與倫理規範。
- **憑證外洩面**：讓 AI 進後台輪換憑證時，過程中後台其他機密資料或憑證也可能被模型讀到。
- Dustin 的立場是：他評估過後果、願意承擔風險才做，分享不代表觀眾也該照做；資訊安全與隱私要擺第一。判斷點包括資料願不願意讓模型商伺服器拿到、牽涉到的外部夥伴同不同意、平台有沒有禁止自動化。

## 安裝方式

1. 在 Codex 的外掛程式（plugin）清單找到 **Computer Use**；找不到就直接搜尋 `Computer Use`，同樣搜尋 `Chrome` 安裝對應項目。
2. 回到 Chrome，點工具列的拼圖圖示 → **Manage Extensions** → 進 **Chrome Web Store** 搜尋 ChatGPT 擴充功能並安裝。
3. 安裝後先開啟一次，依提示登入；連線完成後重開即可使用。連不上就兩邊一起重開，再不行就重開機。
4. 回 Manage Extensions 確認該擴充功能是啟用狀態。
5. 若要控制電腦（而非只有瀏覽器），Mac 需另外開啟系統的電腦控制權限，照系統提示操作。

## 模型選擇：最便宜的模型 + 最高推理強度

跑這類任務時，Dustin 建議用最便宜的 Luna 搭配最高推理強度：

- 該模型已被官方降到極低價，放著跑好幾個小時、跑一整晚都不太消耗額度。
- 它是三個等級中最不聰明的，拿去做高難度的程式建構或策略思考會出很多錯。
- 但雜活（找資料、下載表單、查里程票）本來就不依賴高智力，而它操控瀏覽器的能力已經夠好；把推理強度開到最高讓它不斷試錯，雖然跑得久，但不趕時間就丟到背景跑。

## 不必在模型商之間選邊站

AI 圈變化很快：Claude Code 在今年年初異軍突起（第一版是 2025 年 5 月推出，到現在剛過一歲），今年上半年論 agent 的自動化與任務分配能力，Claude 這一家綜合來說最強；到了 2026 年 7、8 月，Codex 的任務操作能力也追上來了。Dustin 的結論是：現在看到的領先者可能兩三個月後就風雲變色，該學的是善用每家模型的優勢、互相搭配。

## 延伸：部落格與電子報

Dustin 每週在 AgentCrew 網站的文章區分享自己的 AI use case（其中一篇就是用 GPT 做瀏覽器自動化）。另有新推出的電子報，連結放在影片說明欄。電子報的緣起是他每天看 Twitter、小紅書上的 AI 動態，但這些內容多半是二到六手轉載且加油添醋；於是他改為直接蒐集第一手來源、篩選出真正有用的資訊，內容包含不煽情的陳述、基於事實的摘要、原文連結，以及 AI 針對他個人狀況給的建議與點評。原本只寄給自己，分享給朋友後已有四十幾人在看，才決定常態化開放訂閱。
