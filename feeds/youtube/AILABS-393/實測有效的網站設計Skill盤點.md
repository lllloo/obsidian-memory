## 為什麼需要設計 skill

市面上讓 AI 設計網站的 skill 很多，但不是每個都有用——有些流程看起來很厚重，做出來的站仍跟其他站長得一樣。影片的論點是：模型再強，**每個模型設計時都有自己的固定 pattern，而且很好認出來**；需要外力把它從那個 pattern 拉開，網站才會突出。這些 skill 由有豐富設計經驗的人把自己驗證過的工作流重新封裝成可複用形式。

**與 Claude Design 的關係**：不需要另外把 skill 加進 Claude Design——在 Claude 設定裡加的 skill 就是 Claude Design 可以用的那些。影片雖以 Claude Design 演示，但這些 skill 用在 Claude Code、Codex 或任何 agent 上結果相同。

## Emil Kowalski 的 skill 組

一組九個 skill，各自改變設計的不同面向。其中 **Apple design** 收錄 Apple 在自家產品中使用的設計原則，讓其他網站也能套用；**animation vocabulary** 則把模糊的動畫描述轉成模型能理解的精確用詞。

作者自己最常用的兩個：

- **Emil design engineering**：包含如何打造好看的 UI 元件與替其加上動畫的指示，最適合當作**設計的起點**。
- **Animate**：針對**已建好**的網站補動畫，內含詳細的逐步流程；它會理解站怎麼運作，判斷哪裡該有動作、哪裡不該。

用法是在 Claude 加好 skill 後於 Claude Design 內以 `/` 加 skill 名稱叫起，並在 prompt 中說明要什麼站。實測時因為還沒有設計，先用 Emil design engineering：它會像 Claude Design 本身一樣先問一輪 app 相關問題，回答後才開始建。第一版偏極簡、單色調，但動畫不夠細緻、部分地方不同步；接著跑 Animate 修，動畫明顯改善，動作與捲動同步、整體更有意圖感。

**適用邊界**：在 landing page 上改善的多是細微動畫，效果不算突出（landing page 真正好看的是捲動驅動動畫）。它真正發揮的地方是**應用功能面的小元件**——作者做餐廳網站時用 Animate 加上表單送出的動畫、hover 時圖形彈出等細節，整體互動感與使用體驗提升明顯。

## Conard Lee 的 Garden skill

同樣是一組（五個），涵蓋影片簡報、圖像等，但最重要的是 **web design engineer**：內含如何像頂尖設計工程師那樣設計的指示，**專注視覺驚豔而非功能**。

運作方式是先把你的需求與你來回釐清，直到確定要什麼，然後**去找真實的設計來參照**。它的原則是「好設計從不是憑空長出來的」——每個設計都受先前的東西啟發，所以它用已被驗證有效的設計來錨定自己。skill 內另附一組 reference，涵蓋如何評判設計、設計常見的出錯方式，以及 Apple、Linear 等知名網站的風格配方，讓它能參考那些站的實際做法。

結果比 Claude Design 自己產出的更有意思、更完整，設計面也更好。若已有設計再跑這個 skill，它會逐項評分，可以反覆修改重跑直到達到滿分並符合你要的樣子。

## Elia Design 的 landing page skill

單一 skill、專做 landing page，所有內容都在一個檔案裡。它把你的想法轉成一套**視覺系統**，也就是頁面上所有元素都遵循的規則集，包含顏色、字體與間距。

背後的思路是**landing page 不是 homepage**：homepage 試圖同時服務很多不同的人，landing page 只有一個任務——讓人採取行動。模型傾向產出堪用的 homepage，但沒有針對 landing page 特化。這個 skill 因此把整頁圍繞「你希望訪客採取的那一個動作」來架構、把注意力導向它，並維持一致的視覺風格；它也涵蓋多數模型忽略的面向，例如讓網站容易被搜尋找到。

用法同樣是安裝後以 prompt 叫起，它會先問問題再開始設計。實測結果像個真正的品牌、符合預期調性，元素安排也更容易促成訪客實際下單。

## Meng To 的 skill 組

Meng To 是資深設計師，以沉浸式捲動敘事設計聞名，把自己累積的東西打包成一套設計 skill。整組涵蓋多個面向，共同重點是產出**會說故事**、而不只是看起來漂亮的高品質設計。其中 **video to super prompt** 能把螢幕錄影或網站導覽影片，透過本機工具轉成給 agent 的 prompt。

重點是 **Awwwards quality sites**：Awwwards 是舉辦設計競賽的網站，得獎作品被公認是網路上設計最好的一批。這個 skill 列出 Awwwards 級網站具備的原則與設計細節——**Claude 自己不會做到那個層級**——把這些原則放進流程中導引設計方向。它的特別之處在於除了原則之外，還收錄了讓網站看起來「昂貴」的實際技法與具體效果，而這正是模型自己產不出來的部分。實測產出的站在結構與設計上與得獎網站同路數，有細緻的動態背景，最突出的是採用了 Awwwards 那種捲動敘事手法。

## Jakub Krehel 的 skill 組

與其他把整站各面向包在一個 skill 的做法不同，這組**拆分成多個 skill**，排版、色彩、無障礙等各佔一個。可任選加入 Claude Design，作者用的是：

- **review skill**：全面審查設計的各面向並給分，可據此迭代。**連上 GitHub 會更好用**，因為它會比對改動前後的設計；若某項改動前可用、改動後壞掉，它會標出來並指出是哪次改動造成。審查涵蓋動畫、無障礙與各種螢幕尺寸下的表現，最後列出所有發現供修正。
- **better layout skill**：處理 Claude Design 真正吃力的地方——間距、定位與跨設計的對齊，做得很細。影片舉例：它抓到頁面上某個日期的空間不足，甚至指出還差幾個 pixel。修完不會讓網站看起來截然不同，但會讓它符合設計師實際遵循的原則。

## Tastemaker

主要目的是避開模型的通用預設樣式，特別之處在**做法**：它從真實參考的**實際像素**出發，不必先把外觀轉成文字而在轉換中流失資訊。一般給模型參考圖時，它會轉成文字摘要留待後用；這個 skill 改以腳本擷取確切的設計細節，存成 agent 之後可用的結構化格式，保住原本會在文字摘要中流失的細節。它也優先用腳本處理不需要 agent 親自動手的部分，例如往不同方向推、試各種變體。它做的決策會貫穿整個專案，而不是只停在單一畫面。實測結果視覺出色、沒有通用風格的味道，符合要求的外觀與感覺。

## designer-skills

最後一組的特點是**建立在真實研究與具名的設計法則上**，每條法則各有一個 skill。涵蓋的主題包括人為何在瀏覽到一半離開網站、以及行為如何在使用流程中顯現。不必全裝，挑符合自己工作方式的即可。作者裝了兩個：

- **screen critique**：拿一個畫面從多個角度審查，依正規的設計品質評判準則指出哪裡不對，列出如「什麼最先被看見」「字體與間距」等問題供修正。
- **perception laws**：內含人眼實際如何觀看與理解設計的指示；套用之後整體質感更精緻。
