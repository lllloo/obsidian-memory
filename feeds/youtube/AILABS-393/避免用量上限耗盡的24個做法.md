影片把 24 個做法分成三級：等級一是既有功能上的使用習慣，等級二是工具設定的改動，等級三是預設開啟、正在無聲耗用額度的功能。

## 基礎：context window 與 usage limit 是兩回事

**context window** 是模型在單一對話中同時能持有的量，以 token 計。模型本身不記得任何事——每次送出 prompt 時，整段對話連同新 prompt 一起送給模型，它才知道先前發生什麼。因此**同一則訊息在 session 開頭與深入 session 後的成本不同**：後期送出時附帶整段對話。

進 context 的不只使用者訊息：開 session 時系統指令、`CLAUDE.md`（Codex 對應 `AGENTS.md`）、以及每個已連接工具與 skill 的名稱與描述，都在你打字前就已載入，並整個 session 常駐。

容量隨模型而異：影片稱 Opus 為一百萬 token，Codex 內的 GPT 5.6 Soul 為 272,000。

**usage limit** 則是跨所有 session 可消耗的總量，隨方案而定：Claude 有 $20 的 Pro 與 $100／$200 的 Max；Codex 依 ChatGPT 方案（Free、Go、Plus、Pro）。兩者都是**每 5 小時重置**，計時從該窗口的第一則訊息開始，另有疊加其上的週上限。**用量上限跨所有模型共用**，用完後換模型也拿不回來。$20 方案者更需嚴格套用這些做法。

## 等級一：對話習慣

**`/clear`**（兩邊相同）：要開始一件與剛完成的任務無關的新工作時就跑，清空 context window、等同剛開工具，新 prompt 不會拖著一堆無關資訊送出。

**`/compact`**（兩邊相同）：讀完整段對話做摘要，再從摘要接續。問題有三：
- 多數細節在摘要中流失，模型後續拿到的資訊變少，答案品質下降。
- 壓縮本身不免費——agent 必須讀完整段對話才能寫摘要，這些讀取一樣計入用量上限；對話越長，壓縮花的 token 越多。壓縮後 session 的 context 是變少了，但已花掉的用量拿不回來。
- **時機也有影響**：工作期間 Claude 在伺服器保有一份對話的現成副本，免得每則訊息都重讀全文，讀這份副本大約是十分之一價格；但停太久這份副本就會被丟棄，之後得從頭以全價重讀。因此該在**休息前**壓縮，不要休息回來才壓。

結論：不要刻意反覆壓縮；真要壓時在 `/compact` 後面的指令中明講要保留什麼，讓重要細節活過摘要。

**rewind**：agent 做錯時，若把更正寫進下一則 prompt，錯誤與更正會一起留在 context 裡，之後每則訊息都扛著兩者。改用 rewind 把該訊息整個移出 context，再把更正放進下一則 prompt。Claude Code 可跑 rewind 指令或連按兩次 Esc；Codex 沒有對應指令，只能連按兩次 Esc。

**一次一則長 prompt**，不要排隊送多則短訊息拆開做。理由有二：一是送出去的不只你的訊息——agent 每讀一個檔案、每跑一個指令，整段對話都會跟著送上去，拆成多則等於多次送出大量 context；二是兩邊都擅長一次處理多項任務，收到一個大 prompt 時會整體規劃、合併推進，而非逐項各做各的。影片舉例：改一個網站的多項設計（去漸層、移除光暈、修對齊）合成一個 prompt 交出去，比逐項下 prompt 省下遠多的 token。

**關掉自動 recap**（僅 Claude Code，Codex 無此功能）：同時開多個 session 時容易忘記各自進度，Claude Code 會在你切回某 session 時給一行摘要。但寫這行摘要需要 Claude Code 自行送一次 prompt 給模型，一樣扣用量。作法：跑 `/config`，搜尋 session recap 關掉它，需要時自己跑 recap 指令。

## 等級二：工具設定

**選對模型**——這是影響用量最大的單一因素。Claude Code 有 Opus（最強、最耗，留給真正困難的工作）、Sonnet（日常足夠）、Haiku（小而快，處理簡答）。Codex 有 GPT 5.6 Soul（最強）到 GPT 5.4 Mini（小而便宜）等一系列，差別在回答前做多少推理，成本正是從這裡來。$20 方案日常用 Sonnet 或較小的 Codex 模型，遇到複雜、小模型開始吃力時才切上去；$100 方案則建議日常直接用 Opus，額度撐得住且表現明顯優於 Sonnet。切換用 `/model`（兩邊指令相同）。

**effort level**（思考深度）：等級越高，每次回答吃掉的額度越多。Codex 走 `/model` 選模型後可選 low／medium／high／extra high；Claude Code 跑 `/effort`，Opus 上可選的等級更多。建議預設 medium，只在單一任務真需要深度思考時才調高，不要整場開高。prompt 中加關鍵字 `ultra think` 也能拉高思考等級。

**用 sub-agent 分派模型**：sub-agent 預設跑在你當下的模型上，但可以指定不同模型——最簡單是直接在 prompt 裡連同任務指明模型，主 agent 就會用該模型開 sub-agent 並交付任務。若想自動化，規則得寫在某處；寫進 `CLAUDE.md` 有個問題：對話變長後 agent 最重視最近的訊息，session 最開頭的指令最先被漂移掉。影片作者因此改做成 skill，叫 model router，每個 prompt 都跑一次、看你要什麼再路由到合適模型。

**skill 檔 200 行上限**：預設只有 skill 的名稱與描述進 context；一旦被使用，整份 `SKILL.md` 就會載入。因此把主檔壓小，細節放進旁邊的獨立 reference 檔——那些可以任意長，因為 agent 只會在需要時抓其中一份。影片舉例：做專案管理網站時加入自家設計系統的 design skill，需要存取資料時加 Supabase skill，各自只在對應工作時載入，處理資料庫任務時不會把 design skill 拉進來。

**`CLAUDE.md` 也該短於 200 行**：專門的東西改放 skill。設計規則放 skill 只在做設計時才出現；留在 `CLAUDE.md` 則整個 session 都載著，即使你在做別的事。內容原則是**只寫 agent 還不知道的事**——叫 agent 自己寫這個檔，它會填一堆「怎麼跑這個 app」之類模型早就知道的內容，然後每個 session 白白載入。作者的做法是明確告訴 Claude 該往 `CLAUDE.md` 寫什麼，而不是放它自由發揮。大型多資料夾專案則**每個資料夾各給一份 `CLAUDE.md`**，只放該資料夾的指令，agent 開到裡面的檔案時才載入。

**追蹤用量**：跑 `/usage`，可看 5 小時窗口與週上限已用多少，並列出最耗 context 的來源——具體點名哪些 skill、MCP server 與習慣吃掉最多額度。

**CLI 優於 MCP**：許多工具（如 Supabase）同時提供 CLI 與 MCP，兩者運作方式其實相同，差別在載入 context 的量。**連上 MCP 後，它所有工具名稱與描述都進 context 並常駐**，不管你此刻是否在做資料相關的工作。CLI 不會被載入，agent 只是透過終端呼叫，只在真的要用時才跑指令，不需要時完全不佔 context。影片作者實作時因此選了 CLI。至於「agent 怎麼知道 CLI 存在」——MCP 靠資訊常駐 context，CLI 則靠 **skill** 告訴 agent 怎麼用它，Supabase skill 正是此用途。

## 等級三：預設開著、正在花你錢的功能

**記憶（memory）**：Claude Code 與 Codex 都會從過往 session 累積模式與細節以便日後協助你，但這些記憶會載入 context window——不管與當下工作有沒有關係，每則訊息都在為它付費。跑 memory 指令關掉，停止新增並卸下舊的；Codex 亦同。

**內建 bundled skills**：Claude Code 內附一組 skill（如 review 類），多數人不常用。在 settings 設 `disable bundled skills` 為 true，下次開 session 清單就短很多。可自己編輯該檔，或直接叫 agent 改。

**workflows**（Claude Code 有、Codex 無）：一個 workflow 會一次啟動大量 sub-agent 處理大工程，額度消耗極快。跑 `/config` 找到 workflows，不用就關掉；要用則可設定允許的規模上限，$20 方案設小一點。

**限制指令輸出進 context** 有兩種做法：
- 精準做法是 **hook**（在指令執行前跑、可改動指令的小腳本）。作者的例子是跑測試時，通過與失敗的輸出全被灌進 context，但 agent 只需要失敗的那些；於是請 Claude Code 寫一個 hook 過濾掉通過的測試、只留失敗的。完成後 hook 會註冊在 `.claude/settings.json`，腳本放在 hooks 資料夾。
- 粗略做法是不看內容、直接設上限：Claude Code 的 `bash max output length` 是回到對話裡的終端輸出字元數，建議從 30,000 降到 10,000，一樣加進 `.claude/settings.json`。Codex 的對應設定叫 `tool output token limit`，以 token 計且涵蓋所有工具、不限終端。

**advisor**（Claude Code 的實驗功能）：把主模型搭配一個更強的模型，在關鍵時刻（決定採用某方案前、或反覆撞同一個錯誤時）諮詢它。它確實有效，因為第二個模型能抓到第一個漏掉的東西，但成本很高——每次呼叫都把**整段對話**送給更強的模型，而那邊沒有可讀的快取副本，每次都得從頭處理；而且由 Claude 決定何時呼叫，不是你。建議關掉 advisor，自建一個 advisor agent、取相同名字取代內建版本，這樣仍保有強模型，但只在你要求時才跑。Codex 則在其 config 檔做同樣設定，指定用 GPT-5.6 並把 reasoning 開到最高。

**session 間互傳訊息**：Claude Code 近期支援讓開著的多個 session 彼此對話。做法是替 session 命名，再叫其中一個把**只有相關的那部分**傳給另一個，第二個 session 就只收到它需要的東西，而不是周邊全部。
