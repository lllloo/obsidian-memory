這六個 skill 不是要取代你既有的工作方式，而是替 coding agent 加上原本做不到的能力。影片的示範對象是一個健身房管理的 Next.js app（會員、教練、課表），資料庫用 Supabase。

## task-observer：讓 skill 從實際工作中自我改進

Skill 最大的問題不是寫，而是**維護**——agent 每次重犯同樣的錯，都得你自己注意到並回頭改 skill。你也不可能一次坐下來就預測 agent 會犯的所有錯。

task-observer 在你實際工作時持續觀察：發現某個解法值得成為新 skill 就記下來，發現既有 skill 缺一條規則也記下來。

- **安裝位置**：可裝在主要的 `.claude` 資料夾（跨全機所有 Claude Code session 生效），或裝在單一專案內。**影片建議 per-project**，讓各專案的教訓分開、比較好管理。
- 安裝後會建立 `log.md` 記錄所有觀察，檔案放在 Claude Code 主資料夾（專案之外）；per-project 安裝時各專案各有自己的 log。
- 旁邊還有第二個檔案，放**該套用到所有 skill 的通則**。例如「任何 skill 都不得把真實客戶名稱寫進檔案」——這條不專屬於當時在用的那個 skill，所以歸到這裡。
- 它要求你在 claude.md 加一條指示，讓 Claude 在工作過程中執行這個 skill。
- **關鍵設計：它不會直接改動真正的 skill。** log 裡每個 skill 有自己的段落，底下寫建議修改，供你日後 session 檢視後再決定要不要正式納入。這避免了單一次的壞結果變成 agent 從此永遠遵守的規則。

實例：影片作者做影片動畫的 skill 需要品牌 logo 的 SVG，模型自己畫不出來，原本都手動去 LogoHub 拿。該站也有給 agent 用的終端機工具，agent 就自作主張拿來抓 logo，但那個工具其實是為別的用途做的，於是失敗。task-observer 記錄了「動畫系統不該使用該工具」，並找出正確的取得來源記成新規則；兩條教訓經人工審核後納入 skill，之後動畫 agent 就知道去哪拿 logo。

## 行銷三件套：onboarding、paywall、churn

出自 Corey Haynes 的 48 個行銷 skill 合集。名稱聽起來像只管廣告與內容，實際涵蓋產品賺錢的各種面向，其中三個**直接內建在 app 裡**，而這三塊正是用 AI 寫程式的人最常整個略過的。

> 影片同時提到搭配 Supabase skill：Supabase 一直在更新，模型的訓練內容未必對得上你在用的版本，這正是 skill 的用途——補模型沒有的資訊。

- **Onboarding**（新使用者設定並開始使用產品的流程）。原本註冊要跨五個步驟回答五件事，門檻很高。改版後：姓名直接沿用建立帳號時已填的資料，唯一新問的只有健身房地點；接著直接帶到方案頁，且**預設已選好最熱門的方案**降低決策成本。進入 app 後，所有被移除的設定步驟改放到底部的進度條，通知會留著直到使用者稍後補完。影片強調這些不是隨便的選擇，而是基於多年跨產品的真實使用者行為。
- **Paywall**（使用者要用付費功能時出現的畫面）。這個 skill 的做法是讓人先免費註冊，然後**展示付費後會得到什麼**：部分內容開放、其餘鎖住，畫面直接把人導到定價頁解鎖。這個模式你在很多 app 看過，但**單純叫 agent「加一個 paywall」通常不會做出這些選擇**，因為它沒有內建這些原則。
- **Churn**（付費使用者停止付費）。示範的是取消頁：有人要取消會籍時，app 不立刻結束，先問離開原因，再依答案給出更好的方案。畫面上還有更細的設計選擇——**「暫停會籍」是頁面主按鈕，「繼續取消」則以純文字放在下方**。

影片註明這個實作仍偏通用因為是 demo；餵進真實使用者資料與你實際在賣的東西後，決策會更貼合你的產品。

## Karpathy 四條規則

多數 coding agent 的問題不出在程式碼，而出在 **agent 做了你沒要求它做的決定**。這個 skill 把 Andrej Karpathy 的建議轉成四條規則：

1. **不清楚就別猜**：請求含糊時，必須講明它的假設、列出各種選項、在做出可能把專案帶往另一個方向的決定前先問你。
2. **不做超過要求的事**：用可行的最簡解，不為你還沒遇到的問題加功能、加設定、加系統。
3. **不動任務範圍外的東西**：沿用既有做法，只清理自己造成的髒亂，發現其他問題要告訴你而不是自行修掉。
4. **改了東西不等於做完**：動手前先決定結果該是什麼、要如何驗證，然後持續做到每項檢查都通過。

**影片作者的用法不是裝成 skill**：他們把所有 coding 專案放在同一個 developer 資料夾（給了自訂圖示、拉進 Finder 側邊欄，讓每個專案都從同一處開始），並把這四條規則複製進**該資料夾根目錄的 claude.md**。因為 Claude Code 會讀專案內的 claude.md **以及所有上層資料夾的 claude.md**，所以資料夾內的每個專案都會自動載入這四條基礎規則，同時不會影響電腦上其他無關的 Claude Code session。

## Open CLI：把上百個網站變成指令

AI agent 目前仍不擅長操作網站——browser agent 得開每一頁、找對按鈕、慢慢摸索。Open CLI 把 **100 多個網站**（含你已登入的帳號）變成 agent 可直接執行的指令。

它有三個部分：主程式 Open CLI、一個 Chrome 擴充功能、一組教 agent 怎麼用的 skill。

- 每個指令只做一件明確的事。與其叫 agent「打開 X、找到我的書籤、把內容複製出來」，它跑一個指令就拿回一份乾淨的書籤清單。
- Chrome 擴充負責把 Open CLI 接上你**已登入**的網站，agent 因此能用你的帳號而不需要你再給一次密碼。
- 那組 skill 則教 agent 如何找到正確指令、需要時新建一個、以及在網站改版後修好它。

範例是 X：X 的官方 API 是要付費的，但只要你在 Chrome 已登入 X，Open CLI 就能讓 agent 透過你的帳號搜貼文、讀書籤、發文、回覆、追蹤別人。研究產品點子時，agent 可以去搜大家怎麼談論這個問題，也能把你收藏的貼文整理成可用於研究的清單。

**適用邊界**：這是為「你用自己帳號、透過網站完成的工作」設計的，不是用來取代你賣給別人的 app 裡該用的官方工具。

## variate：一次比較多個設計版本

AI 模型傾向重複產出同樣的設計，所以不該接受它給你的第一版，而要求多個版本再比較。問題是在真實專案裡追蹤頁面各部分的多個版本很快就一團亂。

variate 出自製作 hallmark 設計 skill 的同一位作者。它在 app 裡加一個小選單，讓你為頁面的**某一部分**產生並切換多個版本。影片主要推薦用在 landing page。

- 加在 landing page 上時，登入進入主 app 後選單就消失。
- 只做了 hero section 的變體時，切換版本會發現頁面其餘部分完全不變。
- 除了真實的 Next.js app，同樣的選單在**單純的 HTML landing page**上也能用（該頻道設計 app 時的慣例是先從簡單 HTML 頁開始）。
- 你選的版本會**直接送回給 agent**，接著可以請它為頁面的另一部分再產生變體。

好處是不必每次都重做整個 landing page：可以分別試一個按鈕、一個區塊、header 的不同版本，再組合出你喜歡的搭配。

## The Minimalist Entrepreneur：該不該做這個產品

前面的 skill 都在幫你把產品做好，但東西沒人要的話都是白費。這組 skill 出自 Gumroad 創辦人 Sahil Lavingia，依他的著作《The Minimalist Entrepreneur》拆成 10 個 skill，其中 9 個帶你走過創業各階段。

- **第一個 skill：找到要服務的人**，做法與多數人相反——不是先想點子再找可能想要的人，而是**先從人出發**：檢視你已經身在其中的社群，找出大家反覆抱怨的問題，其中之一可能就是你的產品點子。接著檢驗這群人值不值得投入：你能不能不靠付費廣告觸及他們？他們是否已經在花錢解決這類問題？
- **第二個 skill：驗證**，也就是在動手做之前確認有人會付錢。它**不接受「企業」這種含糊答案**：問「誰有這個問題」時，它要你講出 10 個叫得出名字的真實對象，而且其中至少 3 人說願意付錢給你。
- 其餘七個涵蓋：選出最小版本、先用人工把事做一遍、拿下第一批客戶、定價、行銷、不靠募資成長，以及在雇人之前先決定公司該怎麼運作。
