## Codex 環境設定

Codex 現在是 ChatGPT app 內的一個模式，需先下載 app 並登入。免費版額度非常有限，影片建議想實際建置就用月費 20 美元的 Plus 方案即可；要做更多可升級到 100 或 200 美元方案。

- 建立新專案可從零開始並自行命名，它會為你建一個資料夾；打第一個 prompt 就開始在該資料夾工作
- 同一資料夾內的對話 Codex 稱為 **thread**
- 模型選單中影片使用 GPT 5.6。**effort**（模型投入多少心力產出答案）建議固定在 light 到 high 之間，**不要往上超過**，因為那只吃額度、不帶來實際好處
- **speed** 建議維持 standard。Codex 模型相對其他模型（如 Claude）本來就快，切到 fast 只會多耗額度
- 額度可在選單查看（影片當下顯示週額度剩 81%），要養成留意的習慣
- Codex 專案就是你電腦上的實體資料夾，可在 app 內直接開檔案清單瀏覽；不需要離開 Codex app、不需要開終端機、也不需要開 VS Code 這類 IDE

## 階段一：用 agents.md 定調專案

Codex 設計任何東西之前，得先知道這個網站要做什麼。像「幫 AI 社群做一個 landing page」這種 prompt 只給了主題，沒說明**頁面給誰看、對方需要理解什麼、頁面該引導他們採取什麼行動**，Codex 只能自己猜，結果就算好看也可能解錯問題。

影片示範的 prompt 結構：

1. 說明要建 landing page，並指定使用 Next.js（Codex 拿來建站的系統，不熟就照抄這行）
2. 定義這個 landing page 的目的（範例是 podcast 分析平台 Beacon）
3. 說明平台會做什麼——它據此生成 landing page 的實際內容
4. **最重要的一行：landing page 的實際功能是什麼**。範例中是讓使用者點擊加入候補名單。已上線的產品通常放註冊按鈕，這裡則明確是候補，Codex 才知道要建什麼

Codex 能從單一 prompt 建出網站，但它只知道那段對話裡講過的事。開新 thread 或換到別的區塊時，它可能對同一專案做出不同決定——這就是 `agents.md` 的用途：Codex 動工前會讀的指示檔，讓每個新任務都從同一份資訊起跑，不必每個 prompt 重複同樣說明。

產生方式不必手寫：輸入 `/` 叫出內建指令清單，選 **init** 並按下 enter，Codex 就會建立 `agents.md` 並寫入初始 prompt 給過的所有 context——包含專案結構與資料夾組織等重點。

**額外必做的一件事**：告訴 Codex 在檔案最上方加一條指示——**只要 Codex 自己能做的動作就自己做**，包含啟動 app 與驗證是否正確建置。原因是這些 Codex 模型有一個缺點：雖然新版已改善很多，它們仍傾向要你代勞明明自己就能做的事。把這條放在 `agents.md` 頂端能讓 Codex 自主運作，你不必一直盯著。

## 階段二：GPT taste design skill

skill 是 Codex 在做某類工作時會讀的指示檔，把網頁設計規則存進 skill，Codex 設計前就會載入，不用每個 prompt 重講。

為什麼需要它：更強的模型不會自動給你獨特設計。就算沒有額外指示，模型也能從短 prompt 生出不錯的網站，但**產夠多次之後問題才會浮現——內容變了，設計語言卻一再重複**。因為成千上萬人用同一批模型生網站，那套設計語言就到處都是，這就是所謂 **AI slop**：單看還行，感覺卻和其他所有 AI 生成網站出自同一個模板。

- Anthropic 原本的 front-end design skill 是為了避開**舊版** AI 設計預設而生，但新模型早已避開那些選擇、並發展出該 skill 沒涵蓋的另一種視覺風格
- 影片改用 **GPT taste design skill**：它給 Codex 一套針對整個視覺系統的更新規則，把它推離新模型現在會重複的模式。該 skill 來自一組 13 個 skill 的集合，其中最適合 GPT 模型的就是 GPT taste；用其他模型可自行試其餘幾個
- 安裝：複製安裝指令，回到 Codex 叫它幫你裝。裝完**必須先退出 Codex 再回到同一個 chat**；因為是 thread，一切都會保留、不會掉進度
- 使用：打 `/` 指令並輸入該 skill 名稱，按 enter 後會插進你的 prompt，Codex 便會讀取 skill 內全部內容

**要明確叫它不要用 site skill**。site skill 是 OpenAI 對 Anthropic front-end design skill 的替代品，抄了很多相同概念，但影片實測認為產出不佳，建議避開，且**必須明講不要用**，否則 Codex 會預設拿它來用。也可以請它在 `agents.md` 寫下「設計時絕不使用此 skill」——限定「設計時」是因為這個 skill 另有一個用途（見部署一節）。

範例中它跑了 17 分鐘建完整站，給出一條 localhost 連結（只在你自己電腦上開得起來，分享給別人打不開）。預覽不必離開 Codex：打開側邊面板裡的瀏覽器，貼進連結即可。因為一開始就講清楚網站用途，它把使用者旅程排得很準：先產品展示，再小型圖像區塊，最後因為明講是候補頁而做出邀請早鳥註冊的 CTA。當下仍有幾個問題留待後面階段修：stock 圖片、部分動畫略卡。

## 階段三：瀏覽器驗證

網站程式跑得起來，不代表完成的設計看起來就對。瀏覽器驗證把**實際網站本身當成回饋**餵給 Codex，讓它抓到只有畫面呈現後才看得見的問題。

這也是 Codex 最強的領域之一。**computer use** 指模型理解並操作螢幕內容的能力，而 GPT 模型是 computer use 最強的模型；影片表示 Codex 的瀏覽器驗證在他們測試中比其他 coding agent 可靠得多。

因為 `agents.md` 已寫了要它自行驗證，不必手動要求。範例中它多次使用瀏覽器檢查網站、未發現錯誤，因此驗證期間沒改任何檔案（另外改的幾個檔屬程式碼層面）。

驗證也涵蓋 **responsiveness**（網站如何適應不同螢幕尺寸）：拉寬成桌機寬度看起來良好，縮窄成手機寬度 Codex 也已自動處理。過去必須特別交代模型做 responsive，現在模型會自動處理，但仍建議自己拖拉視窗快速確認。若有元素沒 responsive，截圖丟給模型即可。影片提到有個 annotate 工具，但實測很卡、不太可靠（尤其放大之後），因此他們仍採截圖法；這功能未來或許會改善。

## 階段四：用 design.md 建立品牌識別

即使用了 GPT taste skill，網站仍會退回 GPT 模型在各種設計中慣用的那批顏色。skill 改善的是模型的**通用**設計判斷，不會給這個特定品牌自己的視覺識別；大家用同一模型加同一 skill，結果還是會開始長得像。

**design.md** 補的就是這一塊。這個格式由 Google 透過其 AI 設計工具 Stitch 引入，一份 `design.md` 是承載**單一品牌完整視覺系統**的指示檔，給模型具體設計方向，而不是任由它挑自己的預設值。兩者分工是：**GPT taste skill 教 Codex 怎麼做出更好的通用設計決定，design.md 告訴它這個特定網站該長什麼樣。**

影片給的對照：有 design skill 與沒有 design skill 的 GPT 5.6 各產一版，後者也算好看，但明顯重複使用同一批元素，尤其配色——某個綠色與某個紫色反覆出現；用了 design skill 之後紫色用得少些，但仍在用。

design.md 檔案的來源：

- **getdesign.md**：收錄大量他人的設計，可取得 Claude、Cursor、Discord 等知名公司的設計系統
- **Aurabuild** 的 design.md 收藏（Aurabuild 本身是網站建置工具，但也提供這個免費 design.md library），往下捲點熱門項目就有很不錯的設計系統。影片選用的即出自此處，點下載鈕就存到 downloads 資料夾

注意它**不會改變網站的版面或風格**，而是套用間距、顏色等設計細節，讓網站呈現完全不同的樣貌。

套用方式：在 Codex 點附加鈕帶入下載的檔案，然後告訴 Codex 在專案內建一個 `design.md`、把該檔內容複製進去、再依此 design.md 改造網站，並**明確要求結構、版面與動畫不要改**——因為 GPT taste skill 在動畫上表現很好，整頁動畫幾乎不用你操心。完成後版面與結構維持原樣，配色整個換掉，網站觀感完全不同，也不再像 GPT 模型生出來的東西。

另一個團隊習慣：建 landing page 或完整 app 時一律使用 **Phosphor icons**，並寫進 `agents.md`，讓 Codex 之後建任何新東西都用這套 icon。理由是它極簡又好看，即使多半只用在箭頭之類的小地方，仍是他們心目中最好的 icon set。

## 階段五：用 GPT 圖像模型生成原生圖片

design.md 給了網站自己的視覺系統，但 stock 圖片仍不屬於這個系統——它們能填空間，卻很少貼合品牌，這是 AI 生成網站讓人覺得像「組裝」而非「設計」的另一個原因。

Codex 已透過 `agents.md` 理解產品、透過 `design.md` 理解視覺方向，可以用這些 context 以 GPT 圖像模型生成原創的品牌圖像並直接放進網站。

做法：

1. 下 prompt 要它建立 assets 資料夾，並在 `agents.md` 中登記該資料夾。之後 GPT 產出的資產、或你自己想加的圖都放這裡
2. 要求它替換 landing page 上所有 stock 圖片。**必須交代圖片要吻合設計與其所代表的內容**，否則它只會生出隨機視覺，而不是真正相關的視覺
3. 範例中要求生成插畫（此類任務出錯機率較高）。特別是 20 美元方案下圖像生成可能受限，**強烈建議先開 plan mode**——plan mode 讓 Codex 在動專案之前先想清楚要做什麼；不必寫進 prompt，點按鈕即可。開啟後它不碰程式碼、不改網站，先給出計畫，確認後再請它實作

結果：生成的圖像與網站設計高度吻合，也對應到卡片下方的文案描述。它同時把圖片放置規則寫進 `agents.md`；檔案位在 app 資料夾下 public 資料夾內的 assets 資料夾，之後要加圖就丟進去並告訴 Codex 怎麼用。最後三張圖不同，是因為那是為推薦區塊生成的頭像。

## 階段六：用視覺參考改善版面

此時網站已有自己的設計系統與原創圖片，但 Codex 仍是用它既有的版面模式決定東西該擺哪，所以顏色與圖像原創、結構卻仍像標準的 AI landing page，在 hero 區塊最明顯（那是使用者第一眼看到的地方）。

版面也難以只靠文字說明，給 Codex 一個視覺參考才能表達你要的構圖。**目標不是抄別人的網站，而是拿版面當靈感，同時保留自己的品牌與內容。**

靈感來源：

- **Pinterest**：影片搜尋「hero sections for SaaS apps」找到大量設計
- **Awwwards**：其 directory 裡有很多極出色的網站設計

範例中他們對 Pinterest 找到的 SaaS hero section 感想是彼此都很相似，且對現有版本已滿意，因此沒有更動。若不滿意，隨時可以把另一個設計的截圖給模型並請它重製。

## 階段七：升級個別元件與效能

整體設計就位後，一些較小的部件仍可能顯得普通。與其請 Codex 重做整站，不如**只把那些部位換成其他設計師做好的元件**，在不改動已建立的設計方向下拿回細節的控制權。（component 指頁面上一個可重複使用的部件，例如按鈕。）

元件來源：**21.dev**（有免費與付費）、**godly**、**fancy components**，各自提供 app 特定部位的元件，例如帶 liquid glass 的導覽切換器、hero 區塊背景、帶流體動畫的導覽展開器。

範例中他們只覺得 hero 區塊的背景可以更好，於是在 21.dev 找到名為 shaders 的背景，複製其 prompt（內含套用所需的全部資訊）給 Codex，請它套到 hero 區塊，並**特別要求不要使用 skills**（否則它會用到最佳化 skill）。套用後再請它微調顏色，成果相較之前有明顯提升。

**效能最佳化**：套完之後在 app 內移動會覺得很慢，原因是動畫太重。不需要移除動畫，而是要讓網站載入變快——**單純叫模型最佳化網站，就能解掉大部分問題**。影片另有自製的「重動畫 landing page 最佳化」skill，用 slash 指令啟動；跑了頗長時間，過程中可看到延遲下降多少的指標，網站明顯變快。此 skill 屬於他們自建自用、也用於客戶專案的 AI Labs design system。

## 用本機 commit 當還原點

若沒用過 git：它能建立 local commit，也就是專案的檢查點，在自己電腦上使用不需要註冊任何服務。做法就是請 Codex 做一次 local commit，它會建好並給該 commit 一個名字。

- 這些檢查點可在出事時回退
- 影片整個網站就是靠這些檢查點回去展示各階段成果，錄影當下停在網站完成的最後一個 commit
- 忘了 commit 名稱可以請 Codex 列出所有 commit，再回到任一個；Codex 弄壞東西時就靠這招復原

## 部署上線

完成的網站此時只跑在 localhost，只有你自己的電腦打得開。**deployment** 就是把它放上網路，讓任何人透過一般連結造訪。

過去部署要開 Vercel 帳號、再透過 GitHub 連接專案；流程可行但步驟分散。Codex 現在透過前面提過的 **site skill** 讓這件事簡單許多——設計時不用它，但可以用它把完成的專案直接從 Codex 發布。

- 點加號鈕加入 site skill，請它幫你部署，等它跑完即完成
- 側邊欄有獨立的 sites 區塊，列出所有透過 ChatGPT 發布的網站。影片順帶指出：用 site skill 設計出來的舊站設計非常陽春，這正是他們不建議拿它做設計的原因
- 分享權限預設是 just me，改成 anyone on the internet 後發布，即可複製連結給任何人
- 要用自訂網域就到 settings 加入，它會全程引導

整條流程走完，就能在 Codex app 內以幾個步驟為自己或客戶部署 landing page。
