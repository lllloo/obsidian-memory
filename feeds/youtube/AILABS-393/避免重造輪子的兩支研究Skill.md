## 要解決的問題：agent 永遠從零開始

AI agent 現在已經很強，建東西反而是最容易的部分。問題在於**每次你叫 agent 做事，它都得從頭開始**。

具體的失誤是這樣發生的：

- 有了新想法或想解決某個問題時，你開 plan mode 向 agent 說明構想，它規劃一陣子後告訴你打算怎麼建。
- 但你和 agent 都完全漏掉一個角度：**你想建的東西可能已經存在了**，不論是付費工具還是開源專案。agent 從不檢查這件事。
- 這不只發生在新專案。既有產品要加新功能時，agent 一樣只會開始探索這個問題可以怎麼解，**從不去看這問題是不是已經被解決並公開在網路上，也不看競爭對手怎麼解**。
- 結果是你把時間和 token 花在一個已經被解掉的問題上。

以下兩支 skill 各自處理這個問題的一半。skill 本質上就是寫著指示的檔案，讓 agent 照著一套 workflow 走；兩支都適用於 Claude Code 或 Codex。

## Skill 一：advise project approach

### 先定位，再提問，最後才搜尋

1. **判斷你在哪個階段**：告訴它一個全新想法，跟告訴它要在既有產品上加功能，是兩個完全不同的問題，它分開處理。全新想法就規劃整體怎麼建；已經建了東西就檢視你現有的部分，告訴你什麼該留、什麼該改。
2. **搜尋前先確認自己夠不夠了解**。想法還很模糊時它會回頭問你問題，例如：這是給誰用的、對那個人來說它必須做到什麼、預算限制是什麼（能不能用付費方案，還是只能用免費的）。
3. 若你一開始就給足了資訊，它直接跳過提問。
4. **沒被回答的部分它不會默默猜**——它會把自己的假設寫下來讓你看到，你可以指出哪裡不對。

### 搜尋什麼

到這一步它的搜尋是有明確目標的：找出已經在做這件事的**付費工具**，以及做同樣事情的**開源專案**。

若官方文件與 GitHub 不足以判斷，它會回頭問要不要進一步搜尋 X、Reddit、YouTube 取得額外資訊。作者的實測經驗是通常用不到這些來源，它很快就找到答案了。

### 陷阱：不要照抄最紅的專案

- agent 會直接衝向最熱門的選項，而 GitHub 上的「熱門」基本上就是星數最多——星數是只會往上加的書籤計數，它只說明「曾經有很多人喜歡過」，**不代表它適合你在做的事**。
- 更大的版本是專案架構本身：某個領域最大的專案之所以大，通常是因為背後有一整個團隊和大量使用者，所以他們的做法對他們是對的。**你的 agent 照抄的話，你會得到他們一整套複雜設定，卻沒有任何當初導致那些設定的理由。**
- 因此這支 skill 強制自己對找到的每個專案寫下兩件事：**哪些是真的適用於你的**、以及**哪些純粹是因為他們規模變大才存在的**。這正是「為你的處境量身規劃」與「照抄別人公司計畫」的差別。

### 成本角度：agent 通常會漏掉的部分

以「想在 app 裡加私訊功能」為例：這功能不必自己建，Stream、SendBird 之類的服務已經把整套做好了，接進去就能用。但要看清楚代價：

- SendBird 的免費方案約到 100 位使用者。
- Stream 起跳約每月 500 美元、對應一萬名使用者。
- 超過之後兩者都是**每多一個開啟聊天的人就多付一份錢**。

因此這支 skill 一定會在**三個不同時間點**檢查它對你的成本：

1. 你還在建、沒有人在用的時候。
2. 真實使用者實際出現的那一天。
3. 規模成長之後。

好處是你現在就知道，而不是六個月後才發現。

### 實際案例：skill 更新分發問題

**問題背景**：skill 的更新是單向的——作者改了東西，已經下載的人完全不知道，他們手上那份就停在舊版。他們需要一套自己的機制：發布一次，社群裡的所有人都能拿到更新版；更新先送自己團隊，再送整個社群。（這個問題其實是社群成員提出來的。）

**安裝**：把 GitHub repo 連結貼給你在用的 agent，叫它安裝 skill 即可。作者用 Claude Code，安裝完在 `.claude` 資料夾的 `skills` 底下就能看到 `advise project approach`。

**執行過程**：

- 需求是建一個 web app，可以把 skill 丟進去，任何把這些 skill 下載到自己筆電上的人都會自動拿到更新，不必擔心手上那份是不是最新。
- skill 先做了一點小研究，然後意識到需要問問題。
- 首先問這是給誰的，給了多個選項，並提出一個很好的建議：在對整個社群推出之前，可以**先為自己團隊建**，因為他們團隊自己也在用內部 skill。作者因此選定先為團隊建。
- 另一個讓事情變複雜的問題是：這個專案要支援哪些 agent。如果只支援 Claude Code，它查到**解法早就存在**——Claude Code 有 plugins，而 plugins 會自動更新。但因為作者與大量觀眾也用 Codex，所以必須納入其他 agent，事情因此複雜化。
- 它接著問這個東西是不是要拿來編輯 skill，作者澄清不是，它只負責儲存 skill 並把更新送給已經持有的人。
- 它再做了更多研究，然後確認更新是否要自動拉到裝置上。作者澄清：**推送到 app 是手動的**（作者覺得該更新時才推），但**持有 skill 的人應該自動收到**。
- 最後它建了一個 docs 資料夾，把該遵循的專案做法寫在裡面。

**產出的結論**：

- 第一支 skill 找到的答案是 **skills CLI**——在終端機執行、把 skill 安裝進 agent 的工具，它已經把作者想要的很多部分都想通了。
- 它還告訴作者**不需要為此做 web app**，有更好的做法。
- 它建議：現階段還在打磨、只給團隊用的時候，不需要另外建儲存空間，**skill 先放 GitHub 就好**；要對社群推出時再回頭處理儲存問題。

## Skill 二：Neuro Archive（讀 arXiv 論文）

### 何時需要它

第一支 skill 擅長的是「東西已經被別人建好、就躺在 GitHub 上」，去把它找出來。但當題目是**實驗性、還沒有人做出成品**時就卡住了。

不過那不代表沒人研究過——**概念可能已經存在**。作者的 app 就有一小塊踩到這個情況：他們實際在建的東西會**自動把指示推送到別人的筆電上**，第一支 skill 把這塊標為需要特別小心的部分，然後就停住了，因為外面沒有東西可以指給他們看。

### 它做什麼

這支 skill 透過搜尋 **arXiv** 來幫忙——研究者發表著作的平台。大學與實驗室裡的人整份工作就是花幾個月甚至幾年鑽研一個特定問題，然後精確寫下他們發現了什麼、以及什麼行不通；其他研究者再去讀它、把它拆開檢驗，而且全部免費公開。

你現在在用的東西幾乎全都始於這裡：讓 ChatGPT 成為可能的那項技術，其論文在產品出現的好幾年前就上去了。所以當你在建實驗性的東西時，概念就已經躺在那裡。

### 運作方式：一篇論文一個 sub-agent

1. 它接下你的問題，挑出真正吻合的研究領域。
2. 拉出論文。
3. **關鍵在讀法：它不是一口氣全部讀完**。每一篇論文分派給自己的 sub-agent——sub-agent 是主 agent 可以用全新 context window 啟動的另一個 agent，prompt 由主 agent 自己下，你什麼都不用做。
4. **一位讀者對一篇論文，彼此看不到對方在讀什麼。**
5. 全部讀完之後，它收斂成一個答案。

### 案例結果

作者的問題是：自動把檔案推送到別人筆電上，會造成什麼安全問題完全沒有概念。

這支 skill **拉了 12 篇論文**，來回比較哪一篇真正適用於他們的情況，最後落在**一篇關於套件系統（package systems）的論文**，並實作了該論文提出的技術、測試、確認可運作。

安裝方式同樣是給連結、由它裝進 skills 資料夾。載入 skill 後可以看到它 spawn 出 sub-agent，逐篇讀論文。

## 成品與整合

修正實作後，他們得到一個可運作的工具版本，是一個 **CLI 工具**（在終端機執行）。因為 coding agent 本身就跑在終端機裡，所以它們可以直接使用這個工具、自己把整件事做完。

運作方式：

- **發布端只有兩個指令**：指向一支你已經有的 skill，然後發布它。你也可以直接叫 Claude Code 幫你發布。
- **接收端**：其他人的 agent 在重新開啟時於背景把它拉下來。每個人只要在自己筆電上安裝一次，它會自動掛上 Claude Code 與 Codex，然後自己把事情做完。

### 兩支合併的問題與 Headstart

兩支目前是分開使用的，但分開跑有個問題：**第二支跑起來很貴，而你要建的東西大部分用不到它，所以你就不跑；然後真正需要它的那一次，你也剛好沒跑。**

因此作者另外做了一支叫 **Headstart** 的 skill 把兩者合併：**對所有東西都跑第一支，只有在碰到真正是新的東西時才拉進第二支**。實測效果很好。（這支放在作者的社群 AI Labs Pro。）
