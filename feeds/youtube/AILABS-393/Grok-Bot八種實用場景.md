## Grok Bot 是什麼

Grok Bot 讓你從單一介面管理一群 agent，每個 agent 稱為一個 bot，全部在線上持續執行，**不依賴你的電腦開機**。

關鍵特性是**共用**：

- 帳號底下所有 bot 共用**同一台線上電腦**——bot 建立的檔案、使用的瀏覽器、已登入的帳號全部共享。
- 瀏覽器只有一個，不是每個 bot 各一。你登入一次，之後所有 bot 都能看到畫面並用那些帳號做事，幾乎任何你在用的網站都不必逐一重設。
- Bot 之間可以互傳訊息、在群組聊天裡協作，也可以排程在指定時間執行特定任務。

與 Hermes 的差別：概念幾乎相同（agent 在你不在時繼續工作），**差在誰負責架設與維護那台電腦**。Hermes 要你自己設置與管理機器、工具連接、瀏覽器與登入；Grok Bot 由 Grok 全包，你只要登入自己的帳號。

### 取得與設定

- 需要付費方案：任何付費 Cursor 方案或任何 Super Grok 方案皆含。
- 有**獨立的每週用量額度**，bot 的行為不計入你既有的 Cursor 或 Grok 用量。
- 下載 app 執行安裝程式即可，之後想建幾個 bot 都行。用頂端按鈕新增 bot 會開啟對話問你要它做什麼，並依對話更新它的 profile；不想聊天也可直接編輯 profile、把指示寫進 description。

## 場景一：多角色權限測試

App 有 admin、customer 等不同身分時，平常你得逐一登入各帳號、確認每種人只能看到與做到該做的事。

作法：每個角色建一個 bot，另加一個管理測試的 lead bot，全部放進同一群組。把產品連結丟進群組，lead bot 分派各 bot 該測什麼，各 bot 在自己的畫面上跑，最後由 lead bot 匯整成一份報告。

**比 Claude Code 的瀏覽器測試強在哪**：bot 能用共用電腦上已登入的帳號。測試 bot 拿到錯誤結果時，lead bot 可以打開你接到 app 的工具（例如 Supabase）查後端實際發生什麼，找出問題來源。

另有一個工具讓 coding agent 直接操作 Grok Bot（建 bot、派任務等），從 repo 複製指令安裝後，Claude Code 或 Codex 就能在功能完成時直接發起測試，你完全不用打開 Grok Bot；跑完拿到一份通過／失敗總結。

## 場景二：客服

支援信件的工作不只是寫回覆，你得先確認客戶說的問題是否真的存在。多數問題不會只出現在 app 內——例如很常見的「無法登入」，得去 Supabase 與 Stripe 儀表板確認對方到底有沒有付款。Grok Bot 因為已登入這些帳號，你不必自己一個個開。

作法：建一個 support bot 接上 Gmail，指示寫在 bot 的 description。流程是讀未回覆的信 → 判斷問題類型 → 開瀏覽器重跑客戶走過的步驟 → 必要時開儀表板查證 → 把發現寫進回覆。

**瀏覽器實測這步是關鍵**：信件只告訴你客戶「看到什麼」，bot 得查出實際發生什麼，才能分辨是客戶操作問題還是 app 真的有 bug。若客訴成立，bot 可以自己修並開一個 pull request 等你審核後才上線。

接信箱有兩種方式：在共用電腦的瀏覽器登入 Gmail，或接 Gmail plugin。影片採用 plugin，設定較簡單且直接提供讀信與草擬回覆的工具。

## 場景三：找出 churn 的原因

Churn（客戶流失）的成因常小到你根本看不出來。你是建這個 app 的人，早就知道每個功能怎麼用，因此很難體會第一次使用者的處境。Stripe 或資料庫只告訴你**誰**離開，說不出**為什麼**。

作法：建一個 bot 專門找新使用者可能放棄的環節，給它 app 連結，要它走完全部流程並回報。它會開一個全新帳號、照新使用者的步驟走一遍；頁面沒載入、按鈕沒作用、指示令人困惑，它都記錄下來並截圖，最後給你一份可據以修正的報告。

## 場景四：競品監控

建一個 bot，說明你自己的產品是什麼，再給它要盯的競品清單。**瀏覽器在這裡是關鍵**——要真正檢視這些產品往往得登入，而 bot 保持登入狀態，可以持續追蹤並看出實際變化。

要它分析時，它會逐一走過各產品，回報各自做什麼、使用體驗與你的相比如何、你缺哪些功能。因為它看的是**實際產品**而非行銷頁，能講清楚那些功能實際怎麼運作。

## 場景五：AEO（在 AI 搜尋中被推薦）

以前要讓人找到產品主要靠 Google 排名，現在人也直接問 AI 該用什麼產品，模型會先搜網再回答。你的產品沒出現在那些答案裡，很多人就永遠不會知道它存在。

這比一般 Google 搜尋難查：**不能指名問**。你對 AI 問自己產品的名字，它當然會告訴你；但不認識你的人不會用名字搜。真正要知道的是「沒人提起你時，你會不會出現」。

作法：建一個 bot 去 ChatGPT、Claude、Perplexity，以真實使用者尋找這類產品時會問的方式提問（不提你的產品名），檢視回答後給出報告，並指出 app 哪些部分需要改才排得更前面。修正的知識由一個 skill 提供——**skill 可以直接上傳到 Grok Bot 的聊天裡請它加入**。使用前要先在 bot 的電腦上登入所有這些 AI 服務的帳號。

## 場景六：跨儀表板監控

付款資料、訪客活動、錯誤回報通常散在不同儀表板。作法是建一個 monitoring bot，統一去查 Stripe（付款）、分析工具（多少人來訪、停在哪裡）、Sentry（遇到什麼錯誤），以及任何其他你接上的儀表板；設成 routine 每天早上跑，開工就拿到 app 現況。

設定前要打開 bot 畫面登入所有它需要的帳號（Supabase、分析工具、GitHub 等）。**務必在指示裡要求它為每個發現附上連結或截圖**，這樣你拿到的不只是報告，還有資訊來源的實證。

## 場景七：角色分工的群組

產品本身只是工作的一部分，周邊的事也得運轉。作法是開一個群組聊天，每個 bot 負責一塊：影片中分成 product、marketing、support、growth 四個 bot，各有自己的指示說明職責與做法。

其中 **product bot 最關鍵**：它接收你的任務、判斷該由哪個 bot 處理、把工作派下去，確認成果符合要求後回報進度。實際上你只跟 product bot 對話，其餘由它調度——你把任務丟進群組，product bot 接手分派，各 bot 完成後回報。

## 注意事項

影片開頭即提醒：設定沒做好的話，Grok Bot 會變成浪費時間而不是提升生產力。共用電腦與共用登入狀態是它的威力來源，也意味著所有 bot 都碰得到你登入過的每個帳號。
