## [anthropics/claude-code#61609](https://github.com/anthropics/claude-code/issues/61609) — WSL2 貼圖：社群補上完整根因與可用 workaround

**VladimirCro（NONE，社群，2026-08-20）** 在 2.1.238 複現，並反轉了這個 issue 的框架：

- **PowerShell 分支其實已經存在，只是永遠走不到。** 反編譯 2.1.238 的 WSL 指令集：`saveImage` 依序試 `xclip image/png` → `wl-paste image/png` → `xclip image/bmp` → `wl-paste image/bmp` → PowerShell（`Clipboard::GetImage()` 存成 PNG）。WSLg 只把 Windows 剪貼簿影像橋接到 **Wayland 且只給 `image/bmp`**（X11 端連影像 target 都沒有），所以第 4 分支成功、`||` 短路，唯一能產出真 PNG 的 PowerShell 分支永遠不執行；後續 BI_BITFIELDS BMP→PNG 轉換拋錯被 catch 吃掉，UI 顯示 `No image found in clipboard`。
- **同機 A/B（唯一變因是 `wl-paste` 在不在 PATH）**：有 `wl-paste` → 走分支 4，3,342,402 B、magic `42 4d`，轉換拋錯；把 `wl-paste` 藏起來 → 走 PowerShell，81,204 B、magic `89 50`，`PNG 1088x768 RGBA`，貼上成功。
- **可立即用的 workaround**：`sudo apt remove wl-clipboard`。`wl-paste` 消失後 chain 落到 PowerShell，原生貼圖即恢復，不需 helper script；WSLg 下 `xclip` 仍能處理複製方向，代價只有 Pillow 的 `ImageGrab.grabclipboard()`。
- **建議修法**：WSL 下把 PowerShell 分支排到 `image/bmp` 分支之前，或在 `Wt()==="wsl"` 時直接跳過 BMP 分支——繞開 BI_BITFIELDS 解碼而非硬修它，且不引入新依賴。
- 另指出重複串已被關進死路：`#77102` 被自動判為 `#50552` 的重複、而後者已 `not_planned`/`stale` 關閉；`#36420` 被關向 `#32185`（VS Code 專屬的 `image-processor.node` bug，屬不同問題）。
- **官方仍無回應。** 此為社群留言（`author_association: NONE`），因該列標了 `[全留言]` 才進本輪訊號。
