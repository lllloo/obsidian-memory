1Context — 系統與外界

vault 是一份 markdown 的 git repo，本身不跑服務。所有動作由外部的人與程式對同一份檔案讀寫。

2Container — 分別開的程式與通訊邊界

「container」在這裡不是 Docker，而是各自獨立啟動的行程。vault 的六個目錄是被它們讀寫的檔案，不是行程。

3寫入邊界 — 誰能動哪一層

這個 repo 沒有路由檔，取而代之的「功能地圖」就是三個動作與六個 skill 對五個目錄層的權限矩陣。這是整份大綱裡最該記住的一張。

4入口一覽

入口觸發做什麼
Ingest使用者貼 URL／放檔先 Grep raw/ 的 source: 去重 → defuddle 抓取存 raw/fetched/ → 寫／更新 wiki 頁 → 更新 01.index（最近更新滾 5 筆）→ 補交叉引用 → 只檢當輪頁的輕量 lint。單次超過 15 頁先問。
Query直接提問讀 wiki/01.index.md → 讀相關頁 → 附引用作答。好答案回存成新 wiki 頁。
/vault-lint手動機械層掃死連結／孤立頁／frontmatter／tag 漂移／raw 消化缺口；語意層依日期輪替審近 7 天變動頁（上限 10 頁）的矛盾與事實錯誤。全部自主修補，skill 本身不碰 git。
/vault-watch手動gh 抓追蹤中的 issue/PR 現況、與快照比對，精選訊號有變才寫 digest 進 feeds/watch/。
/vault-youtube-sync手動頻道影片清單＋逐字稿 → feeds/youtube/，靠 last_sync_id 增量、draft: true 占位重試。
/vault-page手動把一組 wiki 頁改寫成人類好讀的自包含 HTML，落 docs/architecture/，動筆前先確認涵蓋範圍。
/ask-vault他 repo 呼叫依呼叫端環境變數分派 claude／codex／opencode headless，唯讀 Query 後即退。

5核心概念

名詞在這個 repo 裡的意思
三層治理分層：raw/ 可增不可改、wiki/ 全權、schema 依規則維護。feeds/、docs/architecture/、cards/topics 都在三層之外。
write-once約束的是修改，不是新增。抓到殘缺內容就不落地，改請使用者用 Web Clipper。
CWD 契約repo-local skill 一律要求 cwd 是 vault root，用 Read schema/vault-map.md 驗證——這個路徑只存在於本 vault，能同時擋「不在 root」與「跑錯 repo」。
操作記憶schema/MEMORY.md（40 行上限，跨 session 該延續的操作狀態）＋schema/BACKLOG.md（lint 的待決／已判／已婉拒三區）。checked-in 是為了跨工具可攜。
無守門agent 可自主改頁、刪頁、commit、push。只有兩個確認節奏：單次 ingest 超過 15 頁、以及動 skill。force push 仍需明確要求。

核對時發現的三處不一致

  • 文件 ≠ 實作CLAUDE.md 描述 ask-vault 的 symlink 是兩跳（repo → ~/.agents/skills/ask-vault → ~/.claude/skills/ask-vault），實況只有一跳：~/.agents/skills/ 底下沒有 ask-vault，~/.claude/skills/ask-vault 直接指向 repo 絕對路徑。功能不受影響，是描述過時。
  • 設定懸空schema/MEMORY.md:34 仍寫著 vault-lint 走雲端 routine trig_018QPWmi5K8hiV7ghMvKnTU9，該 routine 已不存在。讀到的 session 會以為排程還在跑而不主動 lint。
  • 索引不全schema/vault-map.md 的資料夾索引未列 root index.md（Quartz 首頁，指向 topics/，已 tracked）與 .clipper/、.github/。不影響運作。
