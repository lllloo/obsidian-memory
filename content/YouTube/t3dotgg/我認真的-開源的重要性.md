## 核心論點：閉源軟體無法被信任

Theo 認為 AI 時代放大了閉源軟體的危險性：**開發速度提升 100 倍，搞砸的速度也提升 100 倍**。每次 Cursor、Notion、macOS 等閉源工具更新，都可能讓你依賴的功能消失或降級，而你毫無辦法。

## patch-package 與 Yash 的啟示

Theo 的實習生 Yash 讓他重新思考「邊界」的意義：

- 一般開發者遇到第三方依賴的 bug，會選擇繞過
- Yash 不認為程式碼的存放位置有意義——他直接進去改，然後用 `patch-package` 固定
- Yash 在兩週內讓 patch-package 的數量增加四倍，並主動對各種依賴提交 PR
- 關鍵案例：AI SDK 不支援圖片生成時，Yash patch 了 AI SDK 加入 image gen，後來官方支援後刪除 patch

這個案例讓 Theo 意識到：**能夠直接修改依賴的能力是開發者的核心資產**，而閉源剝奪了這個能力。

## Cursor 和 Codex 的性能問題

- **Cursor**：用 VS Code 為基礎，疊加大量 AI 功能後性能崩潰；Glass（重寫版）比原版更慢
- Theo 在 Cursor 辦公室直接問：「性能到底怎麼了？」答覆是「我們優先讓它能用，再來考慮性能」
- Julius 嘗試使用 Cursor Glass，開兩個專案就一直崩潰
- **Codex app**：更新頻繁，但每次更新都是隨機變好或變差，某段時間性能幾乎無法使用
- Notion：AI 功能更新後，欄位拖曳只在本地版本生效，雲端沒有同步

根本問題：**閉源 + AI 加速開發 = 品質控管失效**

## T3 Code 為何開源

- Electron 框架（非原生 AppKit）提供最好的文字渲染和滾動性能
- 自建事件系統，易於追蹤狀態
- 開源帶來的好處：
  - 用戶可以 fork 並自行維護想要的方向
  - 30,000 用戶中有 1,100 個 fork（約 1/30）
  - YouTuber Quinn（Snazzy Labs）fork 後加入 final proof 流程、Notion 整合、短連結等功能
  - XLT Jake（非開發者）用 Claude 讓 Lawn（Theo 的影片審閱工具）支援自託管

## Claude Code 閉源的荒謬

Theo 的核心控訴：

- Claude Code 是終端機工具，設計目的就是讓人整合，卻是閉源
- 競品（Gemini CLI、Open Code、Codex CLI）全部開源
- Boris 當初幾乎不想發佈 Claude Code，認為是「秘密武器」
- 結果：Anthropic 意外把 source map 打包進 npm 包，觸發大規模 DMCA
- 閉源的唯一合理解釋：**開發團隊對自己的程式碼感到羞恥**

## 開源作為商業策略

Theo 認為開源不只是道德選擇，也是商業優勢，下一支影片會詳述這個論點。短期觀察：

- 能夠 fork 的成本因 AI 大幅降低（自動 merge、自動解衝突）
- 開源讓社群共同維護品質基準，閉源讓單一公司能快速搞砸品質

## 結論

閉源軟體在 AI 加速的世界裡風險更高、信任更低。Theo 表示會繼續尋找並推廣開源替代方案，並鼓勵用戶支援（包括金援）關鍵的開源專案。
