## 事件背景

Anthropic 宣布調整 Claude Code 訂閱方案的 5 小時 session 限制：**平日太平洋時間 5:00 AM–11:00 AM 期間，消耗限制會更快**（相當於變相降低該時段的可用量）。受影響用戶：約 7% 的用戶會遇到之前不會觸發的限制。

相比之下，三月中旬的「春假優惠」是在離峰時段提供 2x 使用量，該時段與限制窗口相同。

## 計算資源危機的根源

### GPU 分配衝突

Anthropic 內部有三個群體爭搶相同的 GPU 資源：

| 群體 | 特性 |
|------|------|
| 研究部門 | 訓練下一代模型（無直接收入，長期投資） |
| 訂閱用戶 | 固定月費，不論使用量多寡收入相同 |
| 企業/API 用戶 | 按量付費，用越多 Anthropic 賺越多 |

結論：給企業更多 GPU = 立即獲利；給訂閱用戶更多 = 留存但不增加收入；給研究更多 = 未來獲利。

### Anthropic 特有的問題

- Anthropic 是**研究公司文化優先**，研究人員掌握話語權
- 沒有及早購買足夠 GPU（競爭對手 OpenAI 採取「見到就買」策略）
- 與 Amazon 合作補充算力，但仍不足；Google 也在資助租給 Anthropic 的資料中心
- 2024 年收入 1 億美元 → 2025 年 10 億 → 2026 年預估 140 億；客戶增長 7x，GPU 卻沒跟上

### 過去嘗試的實驗

Anthropic 的「春假 2x 優惠」實際上是在測試：如果在離峰時段提供更多使用量，能否把流量分散開？結果顯示效果不足，因此進一步在峰值時段強制限制。

## Anthropic 的溝通問題

Theo 認為這個政策本身邏輯上說得通，但執行有嚴重問題：

- **事後才公告**：限制已經上線，下午才發推（窗口結束後才通知）
- **只在 Twitter 公告**：不在 dashboard、CLI、官網
- **沒有具體數字**：只說「會消耗更快」，不說快多少
- **實際影響遠超預期**：有用戶表示一個平常只用 10% 限制的工作流，突然用掉 100%

對比 OpenAI：Tibo 習慣性重置 Codex 用量限制，每次發布新功能、修 bug、推新模型都重置，甚至成為迷因文化（「St. Tibo，Token 的賜予者」）。

## Thoric（Anthropic 的 DevRel）

Theo 強調：Thoric 是整個事件中唯一主動對外溝通的 Anthropic 員工，他不是這個決定的制定者，對他的攻擊是「咬著為我們發聲的手」。他沒有團隊、不是主管，卻承擔了所有公關壓力，很可能有一半想說的話被法務擋下。

## 其他計算資源分配策略（API）

OpenAI 的定價作法（作為對比參考）：

- **Priority**：2x 標準價，確保全程有 GPU，不中斷
- **標準**：$2.50/M tokens in，$15/M tokens out（以 GPT-4.5 為例）
- **Flex**：高延遲，較低價
- **Batch**：離線排隊處理，$1.25/M in，$7.50/M out（約半價）

## 總結

- 限制本身有合理的業務邏輯（GPU 不夠，企業客戶優先）
- 執行方式（未提前通知、只在 Twitter、無具體數字）是典型的 Anthropic 溝通失誤
- 根本問題：Anthropic 是研究文化主導的公司，不擅長以開發者為中心地做產品溝通
- Theo 的立場：不歸咎個人（Thoric），批評的是公司的組織文化與決策優先順序
