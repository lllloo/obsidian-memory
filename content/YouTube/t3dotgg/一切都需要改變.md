## 核心論點：我們需要更大的 IDE

Theo 受 Karpathy 的貼文啟發，認為開發工具的演進方向不是「更小的 CLI」，而是「更大的整合環境」。

> 你需要一個更大的整合開發環境（Bigger IDE）。

## IDE 的演進歷史

從文字編輯器（Sublime Text）→ Atom → VS Code，每一代 IDE 都把更多工具整合進來：編譯器、型別檢查、測試執行器、Git 工作流。

Theo 自己從 Sublime Text 轉到 VS Code 的關鍵時刻：VS Code 在測試檔案旁邊顯示「執行按鈕」，讓他能直接在編輯器內跑單元測試並跳到錯誤行。這是「把工具整合進編輯器」的完美示範。

## 現在的問題：多個 agent 打破一對一關係

過去：一個開發者 → 一個專案 → 一個 IDE 視窗

現在：一個開發者 → 多個平行進行的專案 → 多個 agent 執行緒 → 多個視窗/終端/瀏覽器，根本管不清楚。

工作分散在：
- 多個終端視窗（dev server、git、各專案的 agent）
- 多個 IDE 視窗（各自針對不同專案配置）
- 多個瀏覽器分頁（localhost、GitHub、文件）

在各個 app 之間建立「這個終端對應哪個專案的哪個 GitHub 分頁」的心智模型，比開發本身還累。

## Theo 的理想：一個 app 管理一切

不是讓 IDE 適配單一 codebase，而是讓 IDE 同時管理多個 codebase：

- 管理不同專案的 work tree
- 內建各專案的 terminal 分區
- 內建瀏覽器（localhost 預覽 + GitHub）
- 可在不同專案之間快速切換

T3 Code 是這個方向的第一步（多執行緒、work tree、內建 terminal），但還遠遠不夠。

## 目前嘗試的解決方案

- **Zellij（Zedmux）**：基於 libghosty，支援側欄管理多個專案，每個專案可開多個 pane 和 tab
- 問題：仍然沒有真正整合瀏覽器

## Theo 的結論

沒有人知道最終形態會長什麼樣。T3 Code 不一定是答案，也可能被更好的東西取代。但現在的工具形狀和工作方式已明顯錯配，這個錯配只會隨著 agent 能力增強而越來越嚴重。

> 如果有人看了這支影片後做出了讓我不得不關閉 T3 Code 的工具，我會非常興奮。
