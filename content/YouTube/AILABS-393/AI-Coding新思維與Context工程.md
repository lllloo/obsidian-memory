## 軟體開發的中間層正在消失

我們正處於軟體開發的新紀元。開發者以前所未見的速度交付產品，但問題也隨之浮現：傳統工作流程無法因應 agent 的介入。這引發了一個關鍵問題：開發者的角色現在是什麼？

Linear（專為現代軟體開發設計的專案管理工具）CEO 的一篇文章讓我深受啟發。他親身經歷了從傳統工作流程到 AI 驅動系統的轉型。這篇文章讓我重新思考的不只是工具本身，而是整個產品建構方式。

## 開發工作流程的三段結構

過去，軟體開發分為三個階段：

- **前期**：需求收集與規劃，制定要建什麼的計畫
- **中期**：將計畫轉化為實際產品，也就是寫程式的階段，往往需要數週、數月甚至一年才能交付
- **後期**：各種形式的測試，以及對照原始需求進行審查

中期是摩擦最多的階段，因為意圖的傳遞容易在人與人之間的溝通中出現落差。但現在，這一切正在改變。

## AI 取代了中期工作

中期的實作與編碼工作正在被 AI 取代。Coding agents 已經強大到僅憑 context 和任務規劃就能產出程式碼。現在的重點是如何正確使用 agent 並監督其工作，而非自己寫程式。

IDE 從「撰寫工具」變成了「審閱工具」——現在只需到 VS Code 審查或新增註解，讓 AI agent 實作被標記的功能。只要 agent 能理解意圖，幾乎不需要親自修改任何程式碼。

## 開發者角色的轉變

我們的工作已從「寫程式」本質轉移到「監督程式」。這意味著：

- 以規劃為首要工作
- 清楚理解要解決的問題
- 確實了解用戶需求與使用方式

你不再依賴能夠詮釋模糊需求的人類，而是依賴會照字面執行指令的 AI agent。無論是行動或網頁 app，都必須知道確切想建什麼，缺乏清晰度就無法有效使用 agent 的規劃模式。

## 規劃的重要性

好的規劃帶來好的實作，無論使用哪個 agent 都一樣。花多少時間都值得，持續精煉計畫直到完全符合需求與期望。

建議的規劃方式：

- 確認計畫後開啟 bypass permission mode，讓 agent 一次性實作完規格
- 不要把所有文件塞進單一檔案，讓 agent 難以導覽
- 依類別建立不同文件，例如：風險評估、因應措施、技術規格
- 在獨立文件中列出限制與取捨，讓 agent 了解效能、成本、時間的可接受範圍

## Context 工程

寫程式已從「建構解決方案」轉變為「為好的解決方案創造條件」。核心技能不是特定的技術棧，而是 **context 管理**。

沒有妥善的 context 管理，agent 雖然會實作被要求的功能，但不會遵守任何限制或規則。讓 agent 獲得正確資訊、降低雜訊，它就能更清楚理解任務，產出更精確的實作。

管理 context 的工具組合：

- 可重用的指令（reusable commands）
- Skills
- Markdown 文件
- MCP 工具
- Sub-agents

沒有唯一正確的做法，應依專案需求組合出適合的工作流程。

## 結構化工具的重要性

結構對人類和 agent 的作用相同——明確定義期望與能力，消除不確定性。在沒有結構的情況下使用 AI agent，只是在發揮其潛力的一小部分。結構可採取多種形式：

- `claude.md`：整體專案指引
- Changelog：追蹤變更
- 可重用指令或專屬 skill.md 檔案（含腳本與參考資料）
- MCP 工具：擴充 agent 能力

每個專案都需要不同的設置，要依需求建立屬於自己的組合。

## 測試與程式碼審查

規劃與委派任務後，工作並未結束。使用 dangerously skip permission mode 讓 Claude Code 運作雖然省時，但壓力轉移到開發週期的末端：程式碼審查變得更加重要，未經審查的程式碼可能導致效能下降與高額成本。

測試策略包含：

**測試驅動開發（TDD）：**
1. 請 agent 先寫測試案例，不寫任何程式碼
2. 清除 context，開啟新視窗
3. 讓 Claude 執行測試（此時會失敗，因為還沒有實作）
4. 確認測試正常運作後，請 Claude 實作功能，並確保它不修改測試

**黑箱測試：**
- 建立使用者故事，描述用戶如何與系統互動以及可能觸發的錯誤
- 使用 Claude Chrome extension 逐段執行測試
- 著重功能性問題

**白箱測試：**
- 直接審視程式碼，追蹤實作方式並推論架構問題
- 使用含多個章節的 XML 文件作為 Claude 的測試指引
- 用自訂指令執行測試文件、記錄結果並產生最終報告

## 未來的優先事項

隨著中期工作消失，焦點轉移到前後兩端：

- **前期**：透過規劃與需求評估釐清正確意圖
- **後期**：透過完整測試與審查流程確保結果符合期望

掌握這些原則的開發者，將是引領未來的人。
