## 開發週期的壓縮

AI 正在永遠改變軟體的建構方式。從 AI 程式工具到自主 agent，整個開發生命週期正在大幅轉變——過去需要數週或數月的週期，現在因為 AI 的介入，幾個小時就能完成。

Anthropic 發表了一篇討論軟體開發趨勢的文章，其中的觀察與我們自身的工作流程高度契合：

- 傳統流程：數週的規劃設計 → 實作與測試 → 審查，然後週而復始
- 現在的流程：只需表達意圖，agent 就能產出實作

人類目前仍參與的部分，只剩審查與意圖表達，其餘都由 AI agent 處理。

## 工程的定義改變了

軟體開發不再意味著寫程式，而是：

- 協調負責寫程式的 agents
- 提供策略方向
- 確保系統按預期運作

甚至連新人入職的時間也從數週縮短到數小時——AI 可以立即探索 codebase 並協助新人上手。隨著焦點轉移到指揮 agents，每個人都開始成為全端工程師，而非單一領域的專家。工程師只需具備基礎的技術棧知識，AI 就能填補不足。

這與 Linear CEO 的預測完全一致：軟體工作流程的「中間層」已被 AI 取代。如果你仍把時間花在中間階段，你正在逆勢而行。現在最重要的技能是**清晰度**——精確描述你需要什麼，讓 agents 交付最好的產品。

## 從單一 Agent 到多 Agent 系統

Claude Code 已在產品內部實作多 agent 架構。過去單一 agent 使用單一 context window 管理所有任務，context 很快就會膨脹，導致失焦。現在改為：

- **Orchestrator agent**（類似專案經理）負責分配任務給各專業 agent
- 每個 agent 擁有獨立的 context window，整合後產出最終結果

Sub-agents 的能力也提升了，可以在背景執行，同時處理應用程式的不同面向，大幅加速整體流程。

## 長期執行的 Agent

Agent 從逐功能建構，進化到能夠自主建構完整系統。自 Opus 4.5 等模型發布後，2026 年的 agent 能夠以最少的人工干預連續工作數天。

長期任務的工作流程：

- 在 `claude.md` 中加入指示，引導 Claude 每次實作後進行測試
- 使用 agent 進行內部測試，視覺測試使用 Claude Chrome extension
- 測試通過後，以具描述性的訊息 commit 到 Git（agent 容易修改不該動的程式碼，Git 讓回滾變得容易）
- 請 Claude 記錄決策過程，保持 commit 整潔

## 人工監督的演進

隨著 agent 能力提升，它們審查輸出的速度比人類更快。我們開始依賴 agent 執行各種審查：

- 安全漏洞檢查
- 架構一致性
- 品質問題

監督的重點從「審查所有東西」轉移到「只審查例外情況」。Agent 也越來越懂得在需要人工輸入時主動提問，而非盲目嘗試。

判斷 AI 的建議是否正確，需要真正的軟體工程經驗——知道哪種方法適合哪種情境的人，才能有效地引導 AI。

## Agentic 程式設計的擴展

2025 年初期，AI 程式設計主要對熱門框架有效，對 legacy 語言或不常見框架力有未逮。2026 年，agentic 程式設計將擴展到傳統開發工具無法觸及的領域：

- 支援 COBOL、Fortran 等 legacy 語言
- 讓維護舊系統更容易，無需再翻閱過時的文件

AI 也讓開發對非開發者敞開了大門，資安、維運、資料科學等領域的人才都能開始使用。一個不熟悉 Golang 的團隊成員，透過 plan mode 就能建構一整個聊天應用的後端，省去了學習新語言的時間。

## 非技術使用場景的增加

銷售、行銷、法務、營運等團隊，現在無需工程團隊支援，就能用 AI 程式設計自動化工作流程、建構工具。有領域專業知識的人，對自身面臨的問題理解最深，他們可以直接指揮 agent 找出解決方案，不需等待開發團隊。

## 安全性的雙重面向

AI 對安全是把雙面刃。同樣能協助 onboarding 的 AI，也可能被用來利用系統漏洞。

- 安全知識不再是安全工程師的專屬領域，任何工程師都能扮演安全審查的角色
- AI agent 在網路防禦系統中的角色將持續擴大
- 進攻型的使用案例也在增加，使攻擊變得更智慧化、危害更大
- 建立 app 時，應使用專門的 agent 負責程式碼審查、測試與伺服器端安全
- 可搭配 Code Rabbit 等外部工具，它們專為早期捕捉已知漏洞模式而設計
