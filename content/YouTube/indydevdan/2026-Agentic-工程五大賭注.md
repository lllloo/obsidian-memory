## 核心框架

每個計畫都是對未來的一次賭注。每個賭注都有風險和回報。關鍵不在執行，而在選擇正確的賭注。以下是 Dan 為 2026 年押注的五大方向。

## 賭注 1：Custom Agents

**賭注**：專注建構 custom agents（不只是使用現有工具）

為什麼：
- 使用 Claude Code 等工具的工程師已超越大多數人
- 在生產系統中部署 custom agent → 直接進入工程師前 1%
- Custom agents 讓你以 compute 的方式解決 domain-specific 問題，且可重複執行

**風險**：學習曲線陡峭，需要時間；過度依賴 AI 是必然的取捨
**回報**：2026 年定義性的競爭優勢

## 賭注 2：廢棄舊技能

**賭注**：主動讓老的工程方式退場，為新方式騰出空間

核心觀念（鉛筆比喻）：
- 一端創造，一端刪除
- 成長不只是寫下一行，也需要知道何時擦掉重來

現實：
- 技能萎縮（skill atrophy）是必然的，不是風險，是保證
- 計算機讓你失去心算能力，Google Maps 讓你失去路感——這是技術進步的本質
- 如果你知道 agent 可以做這件事，卻還是用舊方法做，就是在浪費時間

**行動**：辨識出哪些工作「你知道可以讓 agent 做，但你還是自己做」，一件一件廢棄

## 賭注 3：突破 Agentic 編碼的兩大限制

**限制**：Planning（規劃）和 Reviewing（審查）

這是 agentic coding 的真正瓶頸，不是模型、不是工具、不是 agent——是工程師自己。

**解決方向**：
- 用 custom agents + ADW（AI Developer Workflows）打破這兩個限制
- ADW = 舊世界的程式碼 + 新世界的 agent 組合在 pipeline 中
- 提升 planning 和 reviewing 的速度 → 1-2 個數量級的提升

**風險**：實作複雜，需要深度理解自己的程式碼庫；不了解就無法教 agent

## 賭注 4：Multi-Agent UI 與互動介面

**賭注**：聊天介面是最懶惰的 agent 介面，2026 要超越它

**目標**：提高工程師與 agent 之間的資訊傳遞速率

具體方向：
- Voice-based agent coding（語音控制 agent fleet）
- Use case specific multi-agent UI（不是另一個 Claude Code wrapper，是針對你的產品的 UI）
- 讓多個 agent 同時在同一個產品 UI 上工作

**重要釐清**：不要再做廣而淺的系統，要聚焦在真正的工程問題上，用這個技術深入解決。

## 賭注 5：Compute Maxing（極大化算力使用）

**賭注**：你用的算力不夠多，要更多

現狀診斷：
- 如果你沒有 24/7 全天候運行的 agent 為你解決問題，你就沒有充分利用算力
- 你知道有多少開發者工作流程、產品、工具完全沒有被 agent 接觸過？那都是機會

**2026 計畫**：建構第一個永遠在線的 custom agent，全程在頻道上分享過程

**風險**：昂貴、架構複雜、前期會浪費大量算力
**回報**：Living software that works for you while you sleep（讓軟體在你睡覺時為你工作）

**預測**：2026 年出現第一次「算力緊縮」——算力供應有限，而使用需求飛速增長

## 總結

```
Custom Agents
+ 廢棄舊技能
+ 突破規劃/審查限制
+ Multi-Agent UI
+ Compute Maxing
= 工程輸出量指數級提升
```

核心等式：**Scale your compute = Scale your impact**

Agent 不是你的工具，是你需要教會的員工。重點不再是你能做什麼，而是你能教 agent 做什麼。
