## 什麼是 AI 工程師

AI 工程師 = 使用預訓練模型與 API 建構 production-ready 系統的軟體工程師，工作在 API 層右側（應用側），不同於訓練模型的 ML 工程師或資料科學家。

## 六大核心學習支柱

### 1. AI 工程基礎

- Python 語法、函式、類別、錯誤處理
- 開發環境：虛擬環境、Git/GitHub、專案結構、測試、logging、環境變數
- OpenAI API：認證、送出請求、處理回應、結構化輸出
- 多模態：文字、圖片、影片、音訊
- Prompt Engineering 基本技巧

**目標**：能在本地跑出有乾淨結構的小型 Python 專案

### 2. AI 系統設計原則

- 了解 LLM 可建構哪些系統：文件處理、個人助理、內容生成、後端自動化、多代理工作流
- 最有效的 AI 產品往往盡量少用 AI——結合確定性邏輯與 LLM
- LLM 系統核心元件：inputs、prompts、context window、output、feedback loop
- 軟體設計模式：責任鏈（Chain of Responsibility）、外觀（Facade）、策略（Strategy）
- Agent 框架：LangChain、LangGraph、Pydantic AI（推薦從 Pydantic AI 入門）
- 重要：理解框架後，要自己重新實作簡化版本，才能真正掌握底層邏輯
- Cognitive architecture：用方塊圖畫出資料流與 LLM 放置位置

**目標**：能端到端設計 AI 系統並清楚說明每個步驟

### 3. AI 架構與容器化

- FastAPI + Pydantic 建立後端 API
- 非同步程式設計、背景工作者（Celery）
- Docker 容器化
- 資料庫：PostgreSQL
- 資料庫 migration：Alembic
- Event-driven architecture、job queue
- MCP Server 擴充 AI 應用

**目標**：能在本地或 Docker 運行連接資料庫並暴露 API 的後端服務

### 4. RAG（檢索增強生成）

- 文件分塊與 embedding 建立
- 向量資料庫：Chroma、LanceDB、Weaviate、pgvector
- 建立 ingestion pipeline
- 相似度搜尋與混合搜尋
- 進階技術：Contextual Retrieval、Query Expansion、Self-Query、Reranking
- 評估 retrieval 效能並找出失敗案例

**目標**：能讓 AI 系統連接自訂資料來源，在 runtime 取得相關 context

### 5. LLM 監控與 Evals

- Langfuse：追蹤所有 LLM 呼叫的 inputs、outputs、延遲、token 成本；可雲端或自架
- Eval 層級：單元測試 → 人工標注資料集 → LLM as Judge
- 回歸測試資料集管理
- Guardrails：防 prompt injection、內容過濾、輸出驗證
- 應用錯誤追蹤：Sentry

**目標**：能量化效能、提早抓到回歸問題、持續改善 AI 應用

### 6. 部署

- 雲端平台選擇：AWS、Azure、GCP、Hetzner（作者目前用 Hetzner，成本低）、DigitalOcean
- 從裸機 VM 或 container service 部署，先學 Docker 直接部署再考慮 managed service
- HTTPS 設定（Let's Encrypt/Caddy）
- 日誌監控、環境變數與 Secrets 管理
- Health check 與告警
- CI/CD：GitHub Actions

**目標**：能部署、監控、維護 production 環境的 AI 應用

## 整體建議

- 核心架構兩年來幾乎沒變，模型進步只是換 endpoint 和調 prompt，軟體工程底層邏輯穩定
- 少看資訊、多動手建：交出 3 個能展示端到端能力的完整 GitHub 專案
- 善用 AI 生成個人化學習課程填補知識空缺
- 路線圖文件含 10 小時以上免費影片連結（存於 GitHub repository）
