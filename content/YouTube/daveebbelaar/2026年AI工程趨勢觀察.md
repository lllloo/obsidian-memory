## LLM 的限制與未來走向

現況：LLM 仍然幻覺（hallucinate）、Copilot 仍然差強人意、大多數公司仍不知道如何讓 AI 產生實際收益。

對 LLM 架構的觀察：
- 模型效能持續提升（coding、工具使用），但「萃取價值的方式」沒有根本改變
- 與兩年前的 GPT-4 相比，圍繞模型建構應用程式的方法依然大致相同
- 真正的研究專家（如 Yann LeCun）認為 LLM 架構正在碰壁，需要全新的智慧工程範式
- 值得關注的新方向：Recursive Language Models（遞迴式 LLM 鏈接，可克服 context window 限制）

實務結論：LLM 是目前最佳工具，但同時要關注新範式研究，並積極學習最大化現有 LLM 效能的技術。

## Google 的崛起

Google 近半年的佈局值得高度關注：

- **模型**：Gemini 系列在 Arc AGI 等 benchmark 上已達頂尖水準，涵蓋語言、圖像、影片多模態
- **硬體**：唯一擁有自製 TPU 的 AI 實驗室，不依賴 Nvidia 芯片
- **資料**：擁有全球最龐大的資料集
- **A2A Protocol**：Agent-to-Agent 通訊協定，是 MCP 的上一層
  - MCP：讓工具對 LLM 可用
  - A2A：讓 Agent 之間互相溝通、委派子任務、處理複雜工作流程與跨系統互通

Google 可能是 2026 年最大贏家。

## Workflows vs. Agents（DAG vs. 純 Agent）

持續爭論中，但核心結論：**沒有絕對答案，取決於使用場景**。

DAG（有向無環圖）的優勢：
- 可測試、可控制、行為確定
- 適合高風險流程（如銀行系統）、需要近 100% 正確率的場景

純 Agent（LLM + 工具呼叫）的優勢：
- 有人在回路（human-in-the-loop）的聊天場景容錯率高
- 使用者可即時糾錯

判斷原則：
- 問「這個錯誤或幻覺的代價是什麼？」
- 代價高 → 傾向 DAG；代價低且有人監督 → 傾向 Agent
- Anthropic 建議：永遠先找最簡單的解決方案，再逐步增加複雜度

## Agentic Coding 的未來

被視為 2026 年最大進步空間的領域：

- LLM 在 coding 上表現特別好，fine-tuning 潛力大
- 工具（Cursor、Claude Code）、Prompt、模型三者同步進步，相互增強
- **Spec-Driven Development**：目前最佳的 AI 輔助開發工作流程
  - 先撰寫規格文件再讓 AI agent 執行，避免純粹的 vibe coding
  - 參考：Claude Code Best Practices（Anthropic 官方文件）

建議：同時精進基本編程能力與 agentic coding 工具使用技巧，兩者缺一不可。

## Context Engineering

定義：「在正確的時間，將正確的 context，放到正確的模型面前」所使用的所有工具、技術與策略。

無論使用 DAG 或 Agent，context engineering 都是最重要的單一技能。這是持續改善 LLM 應用的核心能力。

## 語音介面的未來

長期趨勢（十年維度）：語音將成為人類與科技互動的主要介面。

- 語音比鍵盤快 4-5 倍
- OpenAI 等公司正重押語音技術
- 建議：現在就開始用語音下指令給 AI 工具，培養習慣

## 現在仍是 AI 早期

即使是 AI 領域的從業者，也只是在頭部少數人之列。大多數企業仍處於「完全不知道從哪裡開始」的狀態。

對開發者的建議：
- 不需要全都弄懂，選定一個方向深入（AI 工程、no-code、AI 諮詢等）
- 兩年前的程式碼今天仍在生產環境跑，只是換了模型、調整了 prompt
- 保持學習基礎，不要被快速變化淹沒
