## 上下文管理的核心觀念

上下文視窗對模型來說是稀缺資源：

- **塞太多**：模型能力會在幾輪對話後迅速下降，選擇性遺忘
- **塞太少**：模型完全不知工作背景

一句話總結：**在對的時機給模型對的資訊**。Claude Code 提供五種「按需載入」機制達成這件事。

## 1. Rules 路徑載入（按檔案類型注入）

在 Rules 規則的開頭加一個路徑欄位，**只有模型動到對應檔案時才載入**。

- Python 規則 → 動到 Python 檔才載入
- TypeScript 規則 → 動到 TypeScript 腳本才載入
- 動前端資料夾、動測試資料夾的規則同理

跟這條規則無關的檔案載入時，規則不會被餵給模型。

## 2. Hooks 按事件注入

Hook 是按照事件觸發、強制塞入提示詞的機制。

- 偵測到模型要寫跟時間相關的信 → 強制注入提示，要求用指令檢查今天的日期、星期幾
- 工具跑完後 → 強制注入提示，要求模型檢查結果有無洩漏密碼

事件沒出現時，hook 對應的上下文完全不會注入。

## 3. Skill / Subagent / MCP 描述載入

Skill、Subagent、MCP 的描述頂部欄位（front matter）只放短短一段功能說明。

- **模型一開始只讀描述**，自行判斷任務是否需要這個工具
- 真的需要才會進一步讀工具的全文
- 像書架上的書名、桌上的工具標籤——掃一眼就知道要不要拿下來用

也可以**主動觸發**：

- Skill：打 `/<skill 名稱>`
- Subagent / MCP：用自然語言（「請你用 XXX subagent」、「請你用 XXX MCP」）

## 4. Memory 主副檔索引

Claude Code 的記憶資料夾設計成按需載入：

- 主檔 `MEMORY.md` 放索引，連向各 topic 子檔
- 模型先讀主檔索引 → 判斷需要哪些細節 → 再依索引讀對應 topic 檔
- 同樣的機制也用在 Skill 設計（`SKILL.md` 主檔 + 副檔）

## 5. `@` 手動指定檔案

任意專案資料夾內的檔案（合約 PDF、特定文檔）：

- 用 `@<檔名>` 直接抓——**最精準**
- 用文字描述讓模型去找會比較沒效率，模型可能要讀好幾個檔案才判斷對的那一個，失去按需載入的意義

## 綜合應用：財務文件管理範例

工作場景串連五種機制：

- 動財務文件 → Rules 路徑載入「財務相關規則」（其他規則不載入）
- 修改日期 → Hook 偵測到事件 → 注入提示「檢查日曆與星期幾」
- 需要財務 SOP → Skill 自動或手動觸發 → 先讀 `SKILL.md` 主檔 → 依索引讀對應章節副檔
- 需要過去記憶 → 讀 `MEMORY.md` 主檔索引 → 讀財務相關 topic 檔
- 需要拉外部資料 / 審核 → 自動觸發 MCP / Subagent

## 結論

額度爆掉、模型回答變蠢、配合不順，根本原因是**沒給模型適合的環境讓它剛好讀到對的上下文**。文檔管理與索引設計是按需載入的關鍵。
