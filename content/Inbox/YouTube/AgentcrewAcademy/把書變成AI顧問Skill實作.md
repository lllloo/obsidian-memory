## 為什麼要把書做成 Skill

把一本書（必須是自己有版權購買）轉成 Claude Code Skill，可讓書的作者變成隨時可調用的專業顧問，幫忙解決工作問題，而不是放在書架上生灰塵。

**直接整本貼給 Claude 行不行？** 不行——一本書 200~300 頁，每次都把整本貼進對話會塞爆上下文。Skill 解決的就是這個問題。

## Skill 的本質

Skill 是一本「專業說明書」：

- 平常收起來，Claude 不一定會用
- 使用者主動 `/skill_name` 叫出來，或 Claude 判斷情境用得上才會被翻開
- 可塞專家知識（書中的框架、方法論）或自己習慣的工作流

## 主副檔架構

書本 Skill 的拆法：

- **主檔（`SKILL.md`）**：放書的精華概要 + 對使用者互動方式的說明 + 內部連結指向各副檔
- **副檔**：放各章節細節
- 主檔內標註「什麼情境讀第一章、什麼情境讀第二章……」讓模型按需載入

每次叫用時，Claude 先讀主檔 → 判斷現在需要哪幾個章節 → 才去讀對應副檔 → 給出最詳盡建議。

## 官方實踐建議

- **每個檔案不要太大**，讓模型能精準讀到剛好需要的資訊
- 做書本 Skill 前可先請 Claude 上網找官方實踐 / 別人的書本 Skill 範例參考

## 實戰示範：一人公司決策建議

範例書：作者用《一人公司如何不迷失方向、用最小資源穩穩前進》這本書做 Skill。

- 終端機打 `/skill` 列出所有 skill
- 同時做了多本書的 skill（例：《Made to Stick》、《Minimalist Entrepreneur》）
- 工作場景：手上有多項事業（學院服務、網站流量、機構合作、研究計劃、系統遷移）需要決定優先順序
- 打書的 skill 名稱 → 模型讀這本書的精華 → 給出建議：

  1. 先服務付費學員
  2. 再轉換潛在客戶
  3. 做 SEO 追蹤
  4. 做外部機構合作
  5. 進行遷移計劃

每條建議都附上書中對應章節、原則、理由，相當實用——等同隨時邀請書的作者進來給專家建議。

## 重點

把學以致用變成實際行動，而不只是空想：挑幾本自己有版權的書做成 Skill 自用。
