## 三個關卡與對應解法

### 關卡一：看不懂輸出

Claude Code 輸出一堆程式碼或術語，看不懂怎麼辦？

**解法 A**：直接說「用白話文重新解釋，我看不懂」

**解法 B**：執行 `/config`，找到 `Output style` 設定，選擇 `Explanatory` 模式。之後回應會更詳細說明，而非直接給程式碼。

### 關卡二：做不對 / 記不住

每次都要重新教 Claude 同樣的規則或習慣，很累。

**解法**：請 Claude 把學到的教訓、你的習慣、不希望再犯的錯誤寫進 `CLAUDE.md`。

`CLAUDE.md` 是 Claude Code 對話的最高指導原則：

- **User level**（`~/.claude/CLAUDE.md`）：這台電腦任何專案都要遵守的規則，例如：使用語言、時區、每次發訊息前要先確認
- **Project level**（專案資料夾內的 `CLAUDE.md`）：只有這個專案才需要知道的規則與背景

快速初始化：用 `/init` 指令讓 Claude 先讀資料夾內所有檔案，自動產生一份初版 `CLAUDE.md`。

注意：`CLAUDE.md` 不要寫太長，越精簡越好，太長會讓模型注意力分散。

### 關卡三：不放心 / 資訊過時

Claude 一直用錯誤或舊方法？

**原因**：模型知識截止在訓練完成的那刻，時效性資訊可能過時。

**解法**：告訴 Claude「請上網查官方文件，找最新的設定方式」，讓它主動搜尋最新資訊。

## 其他常見問題的解法

### 長對話後表現下滑

原因：上下文窗口滿了，注意力開始分散。

- `/compact`：壓縮對話，釋放上下文空間
- `/clear`：清空對話，完全重置

### 不要從零造輪子

有新需求時，先讓 Claude 搜尋現成的套件或工具，不要預設從零開始寫。現成工具通常更穩定，也有社群維護。

### 安全意識：安裝外部套件前

請 Claude 幫你確認：
- GitHub 星數（星數多 = 使用者多）
- 是否有活躍的 commit 記錄（代表開發者持續維護）
- 近期 Issues 有無嚴重 Bug 或安全問題被回報
- 可行的話，掃一遍原始碼，確認無惡意設計
