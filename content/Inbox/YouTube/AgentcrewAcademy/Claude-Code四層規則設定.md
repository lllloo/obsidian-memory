## 四個層面總覽

Claude Code 用一套完整的方式記住「你是誰、你怎麼工作、你的規則與邊界」，分為四層：

| 層級       | 性質             | 使用時機                                       |
| ---------- | ---------------- | ---------------------------------------------- |
| `CLAUDE.md` | 永遠載入的默契檔 | 通用、不常變、每次都該被讀到                  |
| Rules      | 條件載入的規則   | 只跟特定檔案 / 路徑相關                       |
| Memory     | 模型自動寫入的記憶 | 動態知識、臨時狀態                             |
| Hooks      | 程式碼強制執行   | 不可忘記、不可繞過、風險大                    |

## 1. CLAUDE.md（默契檔）

文字檔，啟動時**自動強制注入**模型上下文。適合寫：

- 身分、工作內容
- 跟模型對話的語氣偏好
- 需要遵守的規則
- 專案特殊背景、重要文檔位置

### 重要原則：精簡

每次都會被注入，寫太長 → 上下文被佔滿、重要資訊被稀釋、模型注意力缺失：

- **官方建議不超過 400 行**
- 作者習慣維持在 200 行以下

### 兩個常用範圍

- **User level（全局）**：放電腦最上層目錄，所有專案都讀到。適合身分、語氣偏好、做事習慣等通用規則
- **Project level（專案）**：放專案資料夾，只對該專案有效。適合專案背景、注意事項

兩個會同時載入。判斷規則該放哪個位置的簡單原則：**換一個專案、換一個資料夾還適用嗎？適用就放 user level，不適用就放 project level。**

還有兩個進階位置（公司統一版、本機私有版）較少用。

### 建立方式

- 終端機 `/init` → Claude 掃描資料夾自動產出基礎 `CLAUDE.md`
- 或請 Claude 上網搜尋別人的 `CLAUDE.md` 範例 + 對話問你問題 → 幫你寫一份
- 對話過程中希望它記得不再犯的事 → 隨口請它「寫進 CLAUDE.md」，並判斷該放全局或專案

## 2. Rules（條件載入規則）

放在 `rules/` 資料夾，每個檔案管一個主題。**與 `CLAUDE.md` 最大差別：可條件載入。**

- 規則上加「路徑設定」：只有跑到對應檔案才讀取
- 例：Python 規則只有跑 Python 腳本才載入

### 何時把 CLAUDE.md 規則移到 Rules

- `CLAUDE.md` 超過 200 行 → 開始稀釋重要規則
- 某些規則明確只跟某類檔案相關

通常不需自己動手 → 直接請 Claude 「幫我判斷哪些 `CLAUDE.md` 規則只在某些路徑用到，幫我移到 rules」。

## 3. Memory（自動記憶）

跟 `CLAUDE.md`、Rules 一樣會被注入上下文，但**核心區別是 memory 是 Claude 自己寫給自己的**。

### 觸發時機

模型判斷某件事值得記住或暫時記得時自動寫：

- 你糾正它的某個做法
- 你提到的偏好
- 處理專案的規律
- 還沒做完明天要繼續的事項

### 結構（同樣按需載入）

- 主索引 `MEMORY.md`：每次啟動載入，連向各細部記憶
- 細部記憶（topic 子檔）：模型發現需要再去讀

也可主動：「請你記下來，我明天要對賬」、`/memory` 查看 / 編輯目前 memory（作者通常不手動編，因為 Pro 自己有定期重整功能會排除過時記憶）。

### 與 CLAUDE.md / Rules 的區別

- `CLAUDE.md` / Rules = **持久規定**
- Memory = **動態知識、臨時狀態**（這個專案進行中學到的東西、需暫時記得的狀態）

## 4. Hooks（程式碼強制執行）

`CLAUDE.md`、Rules、Memory 本質上都是自然語言文檔，模型「通常」會遵守，但：

- 規則太多太雜時模型注意力會缺失
- 模型自主判斷情境不需要時可能略過
- 自然語言指令本質上無法 100% 強制

**Hook = 一段程式碼**，走嚴格邏輯判斷，事件觸發 → 一定執行、不會被繞過。

### 運作範例

- 偵測模型要用 Gmail 寄信工具 → 觸發前直接跳出強制用戶確認彈窗
- 偵測模型要刪除危險檔案 → 立刻擋下
- 偵測模型要把密碼或 API key 送出去 → 擋下

### Hook 類型

- **工具使用前攔截**：檢查或直接擋掉
- **工具使用後檢查**：結果出來後做後續驗證

### 何時改用 Hook

某條規則寫進 `CLAUDE.md`、Rules 但 Claude 還是偶爾不執行，且不執行的代價很大時 → 改寫成 hook，把建議變成強制。

不需自己寫程式：「請你判斷哪些規則可以改寫成 hook」、`/hook` 查看目前設定。

### 作者實際使用的 hook

- 對話開場：注入今天日期 + 時區，防模型腦算錯
- Slack / Outlook / Gmail 寄信前：強制使用者確認
- 偵測要刪除危險檔案：直接擋下
- 偵測要把密碼 / API key 送出：直接擋下

風險大、不容妥協的事 = 寫 hook。

## 作者親身上手經驗（四步走）

1. **`/init` 起點**：Claude 自動掃資料夾產基礎 `CLAUDE.md` → 再請它上網搜尋他人範例 + 對話討論修改 → 完全沒親手打過字
2. **慢慢累積規則**：對話過程中希望它記得的，請它寫進 `CLAUDE.md`
3. **太長時拆 Rules**：`CLAUDE.md` 變長 → 模型開始忘事 → 請 Claude 判斷哪些可改成路徑載入的 Rules
4. **必須 100% 的事改 Hook**：仍會被忽略的關鍵規則 → 請 Claude 改寫為 hook，效果不變還能繼續節省上下文

Memory 由 Pro 自動記，臨時狀態可手動「請你記到 memory」。所有設定從頭到尾沒親手打字，全靠對話指定 Claude 幫忙設定。

## 一句話總結

懂得幫一個強大模型配置符合它的強大環境 = 從 Claude Code 初學者升級成境界者。
