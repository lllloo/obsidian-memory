## 使用 AI 的核心心法

不要好高騖遠，先腳踏實地想清楚要完成的任務：**如果沒有 AI，每個步驟你會怎麼做？**

以會議記錄為例，人類完整流程是：

1. 拿到會議錄音 → 轉成逐字稿
2. 從逐字稿寫摘要
3. 因為要發給不同對象，做不同調整：
   - 給主管／老闆 → 大方向會議決議
   - 給與會團隊成員 → 個人分工事項與專案進程
   - 給自己 → 待辦事項
4. 寄出三份不同版本
5. 自己歸檔的版本檔名要清晰，未來才好回溯

想清楚人類怎麼做才漂亮，再來看怎麼跟 Claude Code 協作。

## 跟 Claude Code 協作走通流程

### Step 1：語音轉文字

把錄音拉進 Claude Code，請他先做第一步轉逐字稿。Claude 本身不支援直接語音轉文字，需借助外部 AI（如 Groq、Gemini API）。過程中會遇到技術錯誤（如速率限制），Claude 會自主排查、改方法、分段處理——這就是 Agentic AI 的特色：**自主執行任務，不受干擾**。

### Step 2：清理與整理

請 Claude 清理逐字稿（移除雜字、切分段落）。教學情境會替換掉敏感資訊，實際使用時這步通常不需要。

### Step 3：擬不同版本摘要

明確告訴 Claude 三份版本各自的目標讀者與重點：

- **客戶版**（如 AI 教學的 Demo session）：今天客戶學到什麼、下一步行動
- **自己版**：客戶背景、客戶反應、未來合作方向、追蹤計畫
- **夥伴版**：對話前半段夥伴沒進來，需主動補上脈絡，加上共同討論的商業策略、共識、推廣方向

### Step 4：產出 PDF

請 Claude 呼叫 PDF 產出 skill，套用預先設計好的公司品牌模板，產出三份 PDF。

### Step 5：寄送 Email

跟 Claude 講「寄給客戶／夥伴」，他會擬信、套 HTML 模板、附 PDF 附件、送進 Gmail 草稿。Claude 還會主動檢查 email 是否寫反並提醒。

> Email 寄送依賴 Google Workspace OAuth 與 Gmail MCP，見 [[Claude-Code串接Google-OAuth教學]]。

### Step 6：歸檔

跟 Claude 講「歸到這個資料夾，檔名用『日期-對方-會議記錄』」，自動完成。

## 把工作流包成 Skill

跑通一次後，下一句直接告訴 Claude：

> 「請把我們今天這個對話的整個流程包成一個 skill，名字叫 debrief-demo」

Claude 自動產出 skill.md，包含：

- 工具前置檢查（哪些 AI 服務、哪些工具要先裝）
- Step 1 轉錄
- Step 2 清理（移除雜字、切分段落）
- Step 3 辨認參與者
- Step 4 擬三份不同版本摘要
- Step 5 產 PDF
- Step 6 詢問 Email、發信
- 最後附上「過程中遇到的技術問題與解決方式」，未來重跑出錯機率大幅降低

Skill 是給模型讀的手冊，不是給人讀的，所以模型偵測到符合敘述會自動觸發，也可以手動 `/<skill-name>` 觸發。

## Skill 重跑的效果

新對話視窗 `/debrief-demo` + 丟新錄音：

- 自動壓縮音訊 → 轉錄
- 自動清理 → 整理逐字稿
- 自動辨認參與者，跟你確認後繼續
- 自動產 PDF（出錯自己修）
- 自動詢問 Email、寫草稿、寄送

整個過程使用者只負責確認，不再一步一步指揮。

## 工作效率倍增的關鍵

> 「真正達成的，只有 10% 甚至以下的時間你在做確定，90% 以上的時間都是他來幫你完成。」

實務上不是只開一個分頁，而是同時開 3-4 個分割視窗：

- 在 A 下完任務 → 跳到 B
- B 下完 → 跳到 C
- 任一視窗完成階段任務跟你確認 → 你給下一個指令

把日常工作流 skill 化 + 多工處理習慣 = 工作效率倍增。
