## AI 授權的兩個極端

讓 AI 跑任務後常見兩種失敗模式：

- **過度盯梢**：戰戰兢兢不離座位，眼睛緊盯 AI 每一步、手動確認每個操作。安全但效率歸零，跟自己做沒兩樣。
- **完全放手**：放任 AI 跑完不檢查。最後品質常不如預期，反而要花更多時間救爛攤子。

兩個極端都不好，關鍵在於先分辨任務性質。

## 區分可逆與不可逆操作

決定授權程度前，先判斷任務是「可逆」還是「不可逆」。

**可逆操作**（傾向放手讓 AI 跑）：

- 已用 Git 追蹤，誤刪檔案可回到上一個快照
- 電腦本地有備份，或已推到雲端倉庫
- 只暫時影響自己，不影響他人
- 不影響賺錢的生產環境

**不可逆操作**（必須謹慎介入）：

- 把正式上線網站搞宕機，別人付錢失敗、付進來的帳對不到、資料遺失
- 寄信寄錯（數字寫錯、誤用 BCC 把不該互看的客戶名單暴露）— 信寄出去就收不回來
- 任何破壞生產環境的行為

對可逆操作做好快照、備份、版本記錄就能放手；對不可逆操作則要走 Git 開分支、逐步稽核，讓 AI 一步一步經過人工審核。學會這個風險點分解，才能用對 Claude Code 內建的權限模式。

## 系統內建的四種權限模式

Claude Code 提供四種權限模式，對應不同風險邊界：

- **Plan 模式**：只能讀、分析、調查，不會移動／刪除／寫入檔案。安全性最高，AI 寫出計畫後人工仔細審核完再放手執行。
- **預設模式**：每次新操作都先問過。三種回應選項：
  1. 允許這一次
  2. 允許之後類似操作（例如此會話往後的刪除都自動同意）
  3. 拒絕
- **Accept Edits 模式（影片中口誤稱 Step edit）**：改檔案自動同意，但對外的非檔案操作仍會詢問。適合大方向已確定、只想省去每次改檔確認的場景。
- **Bypass Permissions 模式**：完全跳過所有詢問，AI 想做什麼直接做。極致快、極致方便、極致自動化，但風險最高。

## 極致自動化的風險管控

作者自己也常用 Bypass Permissions 模式，但前提是已備好以下保護：

- 系統快照做好
- 養成 `git commit` 的習慣
- 開發環境、測試環境、生產環境隔離
- 設好 `CLAUDE.md` 的安全規則
- 進階使用 hooks（之後會講到）— 在 AI 高風險操作或「發瘋」（機率雖低）時擋下，或強制送入稽核

具備這些準備後才適合開 Bypass。否則該模式的風險不可忽視。

## 建立人機協作的工作邊界

授權與監督的分界不是一次畫定，而是逐步學習：

- 在與 AI 協作的過程中，慢慢摸索哪些任務可以放心交付、哪些需在旁稍微盯著
- 跟人類同事的合作一樣，建立清楚的工作邊界後，AI 才能幫你做到更多
