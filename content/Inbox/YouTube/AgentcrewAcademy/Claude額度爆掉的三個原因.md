## 三個額度爆掉的原因

買了 Claude 月費 100~200 美金方案，跑不到 20 分鐘就爆額度的常見原因：

### 1. 一直用最耗額度的模型

Claude 有 Opus / Sonnet / Haiku 三個模型：

- Opus 最強、最貴、最耗額度
- 大部分日常任務用 Sonnet 就夠
- Opus 留給真的需要深度推理、解複雜 bug 時再用

### 2. 撞到尖峰時段

Anthropic 最近調整：**美東尖峰（台灣晚上 8 點到凌晨 2 點）會縮減 5 小時可用額度視窗**。撞到這時段，5 小時視窗的額度比其他時段少。

→ 把工作移到晚上 8 點之前完成。

### 3. 快取機制失效

Claude 處理對話時有暫存機制，讀過的檔案、對話內容會留在記憶體，下次繼續對話不需重新讀。

- **Claude Max**：暫存保留 1 小時
- **Pro**：暫存只保留 5 分鐘

超過時間後重啟對話，整包對話重新計費，吃額度非常可觀。

## 避免快取失效的三個習慣

1. **不要讓對話閒置**：Pro 不超過 5 分鐘、Max 不超過 1 小時
2. **對話中途不要切換模型 / 切換思考強度** — 會讓暫存失效
3. **不要在對話中間貼圖片** — 貼圖會破壞快取暫存

## 兩個必養成的指令習慣

### `/compact` 壓縮上下文

- `/context` 隨時檢查上下文視窗占用情況
- `/statusline` 設定狀態列顯示佔用比例
- 約 6 成時可主動 `/compact`，不用等自動壓縮
- 完成一個小階段、但任務還沒做完、需要保留歷史脈絡時用
- 後面接空格寫說明可指定壓縮重點

### `/clear` 清空上下文

- 換完全不相關的新任務時直接 `/clear`，把前一個任務歷史全部清掉
- 額度耗費會降很多

## 進階：精簡環境文件

`CLAUDE.md`、Rules、MCP 工具設定都會被 Claude Code 主動注入上下文，每次對話的起始成本就是這些東西的總和。精簡方法：

- **`CLAUDE.md` 只放全域性都適用的規則**
- 特定檔案才用到的規則 → 放 Rules，用路徑載入
- 特定工具或工作流規則 → 放 Skill，呼叫時才載入
- 用不到的 MCP 工具 → 進 `/mcp` 把它 disable 或移除

做完起始成本就會降低很多，同樣的額度可以做更多事。

## 總結

額度快速耗盡 = 三個原因：

- 模型用太高階
- 撞尖峰時段視窗
- 快取容易失效

解法：

- 日常用中間模型
- 對話不要閒置 / 別中途換模型 / 別貼圖
- 小階段完成 `/compact`、大階段完成 `/clear`
- 精簡 `CLAUDE.md`、Rules、MCP，降低起始成本
