## 預設誤解：Claude Code 不只給工程師用

- 講者 Dustin 是 GMAT 教學與課程管理的教育工作者，幾乎不寫程式
- 文字密集型工作（報名表、問卷、教案、逐字稿、課後信）都能讓 Claude Code 處理
- 重點不是「程式能力」，是把它當成可呼叫工具的文字處理 agent

## 示範一：課前報名表分析

- 指令範例：「請幫我檢視 L1 這堂課的課前報名表，分析這些人對 AI 的認識與準備狀況，給我統計與畫像，並建議課程設計方向」
- 報名表為 Google Sheet，欄位混雜（背景型別、AI 不滿意點、工作型別等）
- 過往做法：用 Excel 排序，欄位分類不規範時很難整理；做雙因子組合分析更困難
- Claude Code 直接產出：程式經驗分佈、工作背景分佈、AI 使用痛點聚類

## 示範二：依痛點分群草擬個人化通知信

- 後續指令：根據 4 種痛點分別寫不同課前通知信，讓學員對課程有正確預期，寫完放進 Gmail 草稿夾
- Claude Code 會先讀既有信件模板，再依四群痛點各寫一封
- 四群分類：品質焦慮群、保姆疲勞群、記憶崩潰群、完全新手群
- 結果直接出現在 Gmail 草稿夾，無需手動複製貼上

## 示範三：課後三方比對

- 三份輸入：上課前的教案、上課中的逐字稿（實錄）、課後問卷
- 指令範例：「比對 L2 工作流課程的逐字稿與課前教案，找出符合與落差；整理問卷回饋並對下一期 L2 提出改善建議」
- 不需指定路徑，因為文件已預先用清楚的資料夾結構與命名規範整理好
- Claude Code 自動派出兩個 subagent 平行執行：
  - Agent A：比對教案與逐字稿，輸出固定格式
  - Agent B：抓問卷並做跨班交叉比對，再讀教案理解設計意圖，最後給改善建議

## Subagent 平行執行的好處

- 兩個任務無相依關係 → 可同時跑，不互相阻塞
- 等待時可分割視窗開另一個 Claude Code 做別的事
- 主 agent 會在子 agent 結果回來時主動通知

## 比對結果：教案 vs 實際執行

- 開場順序被打散：原本三個主軸 → 實際變成火力展示、簡單任務、一對一客製、進階觀念補充
- 時間分配比對：列出「有規劃但沒做到」與「沒規劃但有做」的項目
- 問卷分析：8 條對下一期的具體改善建議
- 重點：所有結論都基於指定來源（教案、逐字稿、問卷），不是 AI 幻想

## 加上 Made to Stick Skill 強化說服力

- 安裝過 `Made to Stick` skill，能用 SUCCESs 框架（Simple／Unexpected／Concrete／Credible／Emotional／Stories）診斷
- 指令：「幫我分析如何提升這個課程」
- 診斷結果：本體可，打破預期與真實展示可，但缺個人故事、學員無法帶走自己的證據、核心訊息模糊、內容過載
- 對 SUCCESs 每一項給出具體改進建議

## 連續任務追加：不打斷工作流

- 在 Claude Code 處理過程中可隨時插入新任務（例：「能不能透過寄送課後信彌補這些缺失？」）
- 判斷邏輯：
  - 與當前任務相關 → 即時納入處理
  - 與當前任務無關 → 先做完當下任務再回來處理
- 任務排程有條不紊，使用者不需手動暫停

## 課後信草稿產出

- 講者請 Claude Code 直接擬草稿放進草稿夾
- 建議內容：Simple（核心訊息）、Stories（個人故事）、Emotional（情緒連結）、今晚就能做的具體行動、課後資源連結
- Agent 還會主動問「當天寄還是隔天寄？」以調整策略與措辭
- 因為是教學示範，提前要求不露出收件者資訊（避免隱私外洩）

## 總結：辦公室文字工作流全覽

- Google Sheet 報名表分析 → 設計適合班上的教案
- 教案 + 逐字稿 + 問卷三方比對 → 找改進點
- 自動產出個人化課前／課後信並放入 Gmail 草稿夾
- 預先規劃好的資料夾結構與命名規範，是讓 Claude Code 自動找到資料的關鍵
