Dave 用一張白板把企業導入 AI 的成熟度切成三階段（AI-enabled、AI-first、AI-native），並指出開發者下一階段最有價值的位置：能帶企業沿著這條軸線往右移，整段端到端做掉的人。

## 三種企業 AI 成熟度

由淺到深，反映 AI 在組織內的角色：

- **AI-enabled**：員工為主，AI 工具（ChatGPT 或更進階工具）只是個別員工的生產力加成。流程沒變，只是員工變快了。多數公司目前在這層。
- **AI-first**：流程被「以 AI 為核心」重新工程化。AI agent 成為主層，員工透過 agent 管理日常工作。可能是員工用 Claude Code、整合度更高的工具，或公司自建的 AI 平台/作業系統。對股東吸引力來自「人更少、產出相同甚至更多」，等於更高營收與成長。
- **AI-native**：公司從零以「agent 優先」設計每一個流程——資料來源、系統介接、輸入輸出皆為 agent 服務。Headcount 進一步下降，未來甚至會出現完全由 agent 跑、創辦人決策即可的公司（目前在規模化公司仍難實現）。

Dave 的判斷：這趨勢幾乎是必然。股東看到 AI-first / AI-native 公司用更少人做出同樣產出，老牌大公司若不跟上會被新創吃掉市佔；軸線會持續往右移。

## 開發者該卡的位置

順著這條軸線玩，**學會把整個工作流（甚至整個職位）端到端用 AI agent 自動化**——把企業從 AI-enabled 帶到 AI-first，再帶到 AI-native。

這需要兩種能力疊加：

- **Full-stack 工程能力**：端到端自動化會橫跨 database、後端、部署、前端、dashboard（給 human-in-the-loop 監看）。只懂單一垂直容易變成系統瓶頸，被自動化掉。
- **流程診斷能力（新加的）**：能進到企業裡「畫出流程、找出可被 agent 接管的工作流」，而不只是接到規格才開工。這是傳統工程師很少做、但 AI 時代被高度需要的角色。

## 從 headcount 思維轉成 workflow 思維

老式做法：出問題 → 開職缺 → 招人。AI 時代要把粒度拆細：

- 不要看「員工 + 一堆任務」，要看「workflow 本身」
- 一個員工通常綁多條 workflow，常含大量隱性知識與 edge case，靠「人天生會處理混亂」撐著（多半源自管理沒做透）
- 你要做的是把這些 workflow 從人身上抽出、定義清楚、再決定哪些交給 agent

## Type 1 vs Type 2 浪費

進入企業做流程審計時，找的是 type 2 浪費：

- **Type 1**：流程必要的步驟，砍不掉
- **Type 2**：純粹浪費——重複步驟、把資料從 A 系統手動搬到 B 系統、人工拼湊報表等

這些就是切入點：「我可以用 30 分鐘寫個 script 把這段自動化」，把這個能力包成 skill 提供給企業。

## 為什麼開發者能做這件事

非工程背景的人對 AI 仍是黑盒——只認得 ChatGPT、聽過 Claude，不知道能力邊界。工程師清楚自動化的可行性與成本，能直接看著流程說「這段我能做掉」。但前提是要拿到看流程的權限——一般 dev 角色被隔開，看不到業務全貌。

## 兩條切入路徑

- **大企業**：難拿到流程觀察權限，但每家公司都會多少變成軟體公司（為了活下去得導入 AI）
- **小企業 / 在地公司**：老闆多半完全不知道 AI 該怎麼用，正在追進度。以 freelancer / consultant 進場示範怎麼蓋 AI agent，是高槓桿的位置

不論正職、freelancer、外部顧問，重點都一樣：能進去看流程、能蓋出端到端的 agent 系統、能排出實作優先順序。
