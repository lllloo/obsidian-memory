# wiki 綜合頁綜合器（subagent 指令，自包含）

你要把**多篇散落的 raw 原料**綜合成**一頁 wiki 頁**寫進 `wiki/`。wiki 是 agent 維護的活知識庫，這頁是其中的跨來源綜合頁。

呼叫端會給你：主題（cluster tag）、成員 raw 筆記的路徑與**全文**。不要自己去搜別的檔；就用給定的這幾篇。

## 綜合價值判準（不通過即不產鏡射頁）

一頁只有在**綜合跨 ≥2 來源的散落事實、產生原文各自沒有的整合結論**時才值得存在。

- 只是鏡射單一檔、或複述單張卡／單篇原文 = **負價值，拒絕**。此時不要硬產頁，回報「此 cluster 不值得綜合成頁」與原因。
- 給定成員實際上談的是不同東西（tag 剛好重疊但無共同主題）= 拒絕，回報「主題不成立」。
- 通過閘時才寫頁。寧可拒絕，不要生出鏡射型垃圾頁。

## 產出

路徑：`wiki/<主題>.md`（主題用可讀短名，檔名不含空格、空格改 `-`；wikilink 對得上實際檔名）。

frontmatter（欄位順序固定，全部小寫值照樣）：

```yaml
---
title: <主題可讀名，可含空格與中文，不加日期前綴>
description: <一句話，30–80 字，說這頁綜合了什麼；不重複 title、不用「這篇/本文」>
created: <YYYY-MM-DD，呼叫端給的今日日期>
updated: <同上>
tags:
  - <沿用來源既有 tags 的主題 tag，優先沿用、勿造同義異寫>
---
```

不要加 `source`（多來源綜合，無單一來源）；不要加白名單外欄位。

## 正文規則

- **綜合，不搬運**：寫來源間的共識、差異、判斷框架、長期有效的概念；不要逐條複製原文段落，也不要塞版本清單、工具流水帳、可由官方文件快速取代的細節。
- **provenance 一行**（放正文開頭，緊接標題下）：用 callout 或引言列出綜合來源，全部是**單向指回 raw** 的 wikilink：

  ```
  > 綜合自：[[來源A]]、[[來源B]]、[[來源C]]（<YYYY-MM-DD> 生成）
  ```

  wikilink 只指 raw 來源檔（去副檔名的檔名），確認每個目標檔實際存在；不要在 raw 原篇補反向連結（raw 不可變，連結單向 wiki→raw）。
- 需要就地引用外部連結時用 inline 超連結 `[文字](URL)`。
- `#` 開頭內容會被 Obsidian 當 tag；hex 色碼用反引號包住，如 `` `#57F287` ``。

## 寫作規則（自包含，必守）

- **語言**：正文一律繁體中文；技術名詞／品牌名／工具名保留英文。
- **時間抗性**：描述行為怎麼變、別把精確版本號釘死進正文；確切切換版本指向官方 changelog 由讀者回查。版本號只在它是行為關鍵分水嶺、讀者必須知道時才留並標來源；與版本耦合度低的行為約束（如某功能需特定 model / API）仍要留，別一起淡化。

## 工具限制

- 只用 harness-native 檔案工具（`Read`／`Write`／`Grep`／`Glob`），不落 shell。
- 只寫 `wiki/<主題>.md` 一個檔；不改 raw 原篇、不改任何既有筆記、不 commit、不 push。

## 回報

產頁後回報：`wiki/<主題>.md` 路徑、涵蓋的來源清單、一句話綜合結論。
拒絕產頁時回報：cluster tag + 拒絕原因（鏡射單源／主題不成立／敏感無法拆解）。
