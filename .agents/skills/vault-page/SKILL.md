# Vault Page

把 wiki 的一組主題頁，改寫成**自包含的長文 HTML**——內容少就一頁，多就拆成一組數頁。

分工前提：wiki 維持給 agent 讀的高密度，**不為人類可讀性妥協**；人讀 artifact。所以成功標準是「讀完不必回 wiki」，不是「摘要得夠短」。

## 產出

- `docs/architecture/<主題-kebab>.html`——單頁時的檔名，用英文 kebab-case。
- 拆成多頁時用共同前綴加序號與短標：`docs/architecture/<主題>-1-<短標>.html`、`-2-`、`-3-`……前綴讓同組頁在檔案清單裡自然聚在一起。
- `docs/architecture/01.index.html`——所有讀本的入口，每次產頁後就地更新。
- 兩者皆屬呈現層，不參與 Ingest／Query／Lint，不是 `raw/`／`wiki/` 的來源。

## 主流程

1. 用 harness-native `Read schema/vault-map.md` 確認 cwd 是 vault root；讀不到就停止，請使用者 cd 到 vault root（`~/code/obsidian-memory`；三平台一致，cmd.exe 不認 `~` 改用 `%USERPROFILE%\code\obsidian-memory`）。
2. 讀 `wiki/01.index.md`，依使用者給的主題找出**彼此交叉引用密集的一組頁**——邊界是「一條脈絡」而非一個檔案，通常 2–5 頁。
3. **先提範圍與分頁給使用者確認**：列出打算涵蓋哪幾個 wiki 頁、分幾頁產出、每頁的標題與涵蓋節次，點頭才動筆。自包含讀本一頁數千字，範圍或切法錯了等於整頁白寫，這是最便宜的檢查點。
4. 讀那組 wiki 頁**全文**（不是只讀 index 摘要），依下方改寫規則寫成 HTML。
5. 更新 `docs/architecture/01.index.html`；若來源 wiki 頁尚未指向產出頁，在頁內補一行指向（多頁時各自指向對應的那一頁）。
6. 回覆附可點的 `file://` 連結。

產出頁面的機制面（落點、可點連結、完整 HTML 的寫法、設計品質校準、inline SVG 畫法）依 `map` skill 的「產出成頁面」一節，本檔不重述。

## 什麼時候拆成多頁

**預估超過約六節或四千字就考慮拆。** 這是提醒 agent 該想這件事的門檻，不是硬規則——實際分頁在上面第 3 步跟範圍一起提給使用者確認。

**拆點必須落在敘事的自然分界：一頁回答一個完整的問題**，不是切字數、也不是機械對應來源 wiki 頁（wiki 的切分是按 agent 維護方便來的，不一定符合人讀的分界）。判準是：拆完之後每一頁單獨拿出來看，標題是否仍成立、內容是否仍完整。做不到就是切錯位置。

多頁時每頁各自帶完整的頁尾三件套（沒講什麼／證據標註規則／快照），勿引用清單也拆回各頁——**每一頁都要能單獨被讀**。

## 改寫規則

wiki → 讀本的轉換就是這個 skill 的實質內容，四條：

**自包含。** 主體內容完整寫進頁面，不寫「詳見 wiki 某頁」把讀者踢回去。可以連回 wiki 當出處，但那是註記、不是內容的續集。拆成多頁時，「自包含」的單位是**整組**：組內互相指路是正常的，指回 wiki 要讀者自己拼湊則不行。

**證據分層。** wiki 逐條標註強度，全搬過來正是難讀的來源之一，全刪又會讓已經查證到否決的數字重新流回視野。所以：

- 強證據（一手、原始碼、同儕審查）**直接當事實寫，不加註**——讀者看到沒標註就可以直接信。
- 只有**弱的才就地標**：單一作者經驗值、未同儕審查的 preprint、廠商自評、單次實測。
- 被查證**否決**的主張集中到頁尾一節（如「這些數字別引」），列明主張與為何不可用；不無聲丟棄。

**配圖要自己掙位置。** 長文為主。只有真正存在**空間關係或流程關係**的節才畫圖，一頁約 1–3 張；概念性內容（取捨、證據、反例）畫不成圖，用表格、小標與重點框攤開。不為了風格統一而湊圖——把清單畫成方框是零資訊增量。

**快照，不追同步。** 頁尾記來源 wiki 頁清單與產生日期（「依據 wiki 於 YYYY-MM-DD 的內容」）。來源頁之後被 ingest 改了**不回頭修補**，要更新就整組重跑重生。artifact 是週期性產物，不是活維護層。

## 導覽

**跨主題**：每頁頂部導覽列指回 `docs/architecture/01.index.html`，不列出其他主題的頁——否則每新增一頁都要回頭改完所有舊頁，而舊頁是快照、不該為了導覽被動到。

**組內**：同一主題拆出的數頁**彼此互連**——頂部導覽列在指回索引之後列出同組全部頁、標出目前在哪一頁（像書的章節）。同組頁是一起產生、一起重跑的，所以互連不會造成「新增一頁要改舊頁」的問題。

`01.index.html` 的登錄以**一個主題一列**為單位：主題名、一句摘要、底下列出各子頁與各自一句話，最後是快照日期與來源頁。單頁主題就是只有一個子頁的退化情形，直接讓標題本身當連結即可。
